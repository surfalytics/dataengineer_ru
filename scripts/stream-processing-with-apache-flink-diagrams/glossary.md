# Глоссарий книги «Потоковая обработка данных с Apache Flink»

Названия классов и параметров конфигурации приводим в написании Flink 1.7. В заголовках глав сохраняем формулировки русского издания.

| English | Как пишем | Не писать | Пояснение |
| --- | --- | --- | --- |
| stream processing | потоковая обработка | стрим-процессинг | Программа обрабатывает записи по мере их поступления. |
| stateful stream processing | потоковая обработка с учётом состояния | — | Результат для очередного события зависит от сведений, которые программа сохранила при обработке предыдущих событий. |
| data pipeline | `pipeline` | пайплайн | Последовательность шагов, по которой данные проходят от источника до места назначения. |
| dataflow graph | граф потока данных | — | Вершины задают операции над данными, рёбра задают направление передачи записей. |
| data parallelism | параллелизм данных | — | Несколько экземпляров одной операции одновременно обрабатывают разные части потока. |
| task parallelism | параллелизм задач | — | Разные операции графа могут выполняться одновременно. |
| parallelism | степень параллелизма | — | Число параллельных экземпляров оператора. |
| operator | оператор | — | Шаг вычисления, например фильтрация событий или подсчёт по ключу. |
| job | задание | джоб | Единица исполнения, которую клиент отправляет в кластер Flink. |
| task | задача | — | Часть задания, которую Flink планирует для исполнения. Задача может объединять несколько операторов. |
| subtask | подзадача | субтаск | Один параллельный экземпляр задачи. |
| operator chaining | объединение операторов в цепочку | чейнинг | Совместимые соседние операторы исполняются в одном потоке выполнения. |
| source | `source` | сорс | Начальный оператор графа. Он читает входные данные или сам создаёт записи. |
| sink | `sink` | синк | Конечный оператор графа. Он, например, записывает результат в Kafka или в базу данных. |
| latency | задержка | латентность | Время от поступления события до получения результата. |
| throughput | `throughput` | — | Сколько записей или байтов система обрабатывает за единицу времени. |
| backpressure | `backpressure` | противодавление | Когда получатель не успевает за отправителем, ограничение скорости передаётся по графу в сторону источника. |
| JobManager | JobManager | — | Координирует выполнение задания. Планирует задачи, отслеживает их состояние и инициирует восстановление. |
| TaskManager | TaskManager | — | Рабочий процесс кластера, в котором выполняются подзадачи. |
| task slot | слот | — | Единица ресурсов TaskManager, на которую Flink назначает подзадачи. |
| slot sharing | совместное использование слота | — | Подзадачи разных задач одного задания могут занимать один слот. |
| shuffle | `shuffle` | шаффл | Передача записей между параллельными экземплярами, например при перераспределении по ключу. |
| DataStream API | DataStream API | — | Интерфейс для построения потоковых приложений из операторов. Названия методов, в том числе `keyBy`, сохраняем в кодовом написании. |
| keyed stream | поток с разбиением по ключу | — | После `keyBy` все записи с одинаковым ключом поступают одному параллельному экземпляру следующего оператора. |
| event time | `event time` | — | Время события по его временной метке. Оно сохраняется при повторном чтении записи с той же меткой. |
| processing time | `processing time` | — | Время по локальным часам машины, на которой оператор обрабатывает запись. |
| ingestion time | `ingestion time` | — | В режиме Flink 1.7 источник назначает записи время по своим часам при входе в приложение. |
| watermark | `watermark` | водяной знак, вотермарк | Сигнал о продвижении `event time`. Записи с метками не позднее указанного времени больше не ожидаются, но могут прийти. |
| timer | таймер | — | Зарегистрированный вызов функции при достижении заданного времени. Для таймера по времени события продвижение определяет `watermark`. |
| window | окно | — | Группа событий, для которой оператор вычисляет общий результат. |
| tumbling window | `tumbling window` | шагающее окно, кувыркающееся окно | Последовательные окна одинакового размера без перекрытий. |
| sliding window | `sliding window` | — | Окна фиксированной длины с заданным шагом. При шаге меньше длины одна запись может попасть в несколько окон. |
| session window | `session window` | — | Объединяет события, между которыми нет паузы длиной в заданный интервал бездействия. |
| window assigner | `window assigner` | — | Определяет, к каким окнам относится входная запись. |
| trigger | `trigger` | — | Правило, которое определяет, когда вычислить результат окна и когда очистить его содержимое. |
| evictor | `evictor` | — | Необязательная функция, которая удаляет выбранные записи из содержимого окна до или после вычисления результата. |
| late data | поздние данные | — | Записи, которые поступили после продвижения `watermark` до их временной метки или дальше. Возможность обновить результат зависит от окна и его настроек. |
| allowed lateness | допустимое опоздание | — | Дополнительный интервал по времени события, в течение которого оператор хранит состояние окна для поздних записей. |
| side output | `side output` | — | Дополнительный выход оператора. Через него, например, можно отдельно отправлять поздние записи. |
| state | состояние | стейт | Данные, которые оператор сохраняет между вызовами функции обработки. |
| managed state | управляемое состояние | — | Приложение работает с ним через интерфейсы Flink. Система отвечает за сохранение и перераспределение при изменении параллелизма. |
| keyed state | состояние по ключу | — | Каждому ключу соответствует своё состояние. Функция обращается к нему в контексте ключа текущей записи или таймера. |
| operator state | состояние оператора | — | В этой модели состояние закреплено за параллельным экземпляром оператора. При изменении параллелизма Flink применяет правила перераспределения. |
| list state | состояние в виде списка | — | При перераспределении обычного состояния оператора элементы списка распределяются между новыми подзадачами. |
| union list state | `union list state` | каталожное состояние | При восстановлении каждая подзадача получает объединённый список элементов, которые сохранили все прежние экземпляры оператора. |
| key group | группа ключей | — | Минимальная единица перераспределения состояния по ключу между подзадачами. |
| broadcast state | широковещательное состояние | — | Все экземпляры оператора получают одни и те же обновления, например новые правила обработки. |
| queryable state | `queryable state` | — | Механизм Flink 1.7, через который внешний клиент может прочитать опубликованное состояние по ключу. |
| state backend | `state backend` | бэкенд состояния | Компонент Flink 1.7, который управляет рабочим состоянием и записью его снимков. |
| checkpoint | `checkpoint` | чекпоинт, контрольная точка | Согласованный снимок состояния задания и позиций воспроизводимых источников. Flink использует его для восстановления. |
| checkpoint barrier | барьер | — | Служебная запись, которая отделяет данные, относящиеся к текущему снимку, от последующих. |
| barrier alignment | выравнивание барьеров | — | После барьера оператор приостанавливает обработку соответствующего входного канала до получения барьеров того же снимка по остальным каналам. |
| savepoint | `savepoint` | сейвпоинт, точка сохранения | Согласованный снимок, который пользователь создаёт и хранит для планового переноса, обновления или перезапуска задания. |
| at-most-once | `at-most-once` | — | При сбое некоторые записи могут потеряться, но повторный учёт одной записи исключён. |
| at-least-once | `at-least-once` | — | После сбоя обработка может повториться. Каждая запись должна быть учтена хотя бы один раз. |
| exactly-once | `exactly-once` | ровно-один-раз | Каждая запись влияет на восстановленное состояние один раз, даже если код обработал её повторно. |
| end-to-end exactly-once | сквозная гарантия `exactly-once` | — | Гарантия однократного эффекта распространяется и на результат во внешней системе. Для этого источник и способ записи должны поддерживать восстановление. |
| idempotent write | идемпотентная запись | — | Повтор одной и той же записи даёт такой же конечный результат, как однократное выполнение. |
| write-ahead log | журнал упреждающей записи | — | В описанном приёмнике записи накапливаются в состоянии Flink до подтверждения снимка. |
| two-phase commit | двухфазная фиксация транзакции | — | Приёмник подготавливает транзакцию и фиксирует её во внешней системе после подтверждения снимка. Сокращение в книге — 2PC. |
| rescaling | изменение степени параллелизма | — | Задание возобновляет работу с другим числом параллельных экземпляров. Flink распределяет сохранённое состояние между ними. |
| high availability | высокая доступность | — | Резервный процесс может взять на себя координацию после отказа ведущего процесса. |
| complex event processing | `CEP` | — | Поиск заданных комбинаций или последовательностей событий в потоке. |
