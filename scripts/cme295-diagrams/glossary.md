# Глоссарий: Stanford CME295 «Transformers and Large Language Models»

<!-- ru-proofread: two-languages -->

Единые слова для всех лекций курса. Правило: навык `lecture-summary`, раздел «Terms in two languages».

- «Как пишем» — форма первого упоминания на странице: ведущее слово, а в скобках тот же термин на другом языке. Дальше на странице пишем только ведущее слово.
- Ведёт русское слово, если оно принято в русских текстах по ML: «токенизация (`tokenization`)».
- Ведёт английский термин, если русского слова нет, оно громоздкое или это транслитерация, а также для сокращений: «`embedding` (векторное представление)», «`LLM` (большая языковая модель)».
- «Не писать» — формы, которые `check.py --glossary` считает ошибкой.

|---|---|---|---|
| LLM (large language model) | `LLM` (большая языковая модель) | БЯМ | Модель-трансформер, которая предсказывает следующий токен. На лекциях LLM — это `decoder-only` модель большого размера |

| subword tokenization | токенизация по подсловам (`subword tokenization`) | — | Компромисс между размером словаря и длиной последовательности |
| vocabulary | словарь (`vocabulary`) | вокабуляр | Набор всех токенов модели |
| sequence length | длина последовательности (`sequence length`) | — | Число токенов в тексте |
| out-of-vocabulary | слово вне словаря (`out-of-vocabulary`) | — | Слово или кусок, которого нет в словаре |
| special tokens | служебные токены (`special tokens`) | — | `BOS`, `EOS`, `UNK`, `PAD`: начало, конец, неизвестный кусок, заполнение |

| embedding | `embedding` (векторное представление) | эмбеддинг, эмбединг | Числовой вектор, который передаёт смысл токена. Русское слово длинное, поэтому ведёт английский |
| one-hot encoding | `one-hot` (вектор с одной единицей) | ванхот | Вектор из нулей с одной единицей на месте токена |
| Word2vec | Word2vec | — | Метод 2013 года: `embedding` из прокси-задачи (CBOW, skip-gram). Название |
| proxy task | прокси-задача (`proxy task`) | — | Задача, которую решают ради побочного результата |
| loss function | функция потерь (`loss`) | лосс | Число, которое показывает, насколько модель ошиблась |
| cross-entropy loss | кросс-энтропия (`cross-entropy loss`) | — | Функция потерь: насколько модель ошиблась с вероятностью верного токена |
| backpropagation | обратное распространение ошибки (`backpropagation`) | — | Как градиент идёт от выхода сети к её весам |
| RNN | `RNN` (рекуррентная нейросеть) | — | Сеть, которая читает текст по одному токену и несёт скрытое состояние |
| LSTM | `LSTM` (долгая краткосрочная память) | — | Вид RNN со вторым вектором, который хранит информацию дольше |
| hidden state | скрытое состояние (`hidden state`) | — | Вектор в RNN, где сжат смысл прочитанного |
| cell state | состояние ячейки (`cell state`) | — | Второй вектор LSTM для долгой памяти |
| long-range dependency | дальняя зависимость (`long-range dependency`) | — | Связь между далёкими токенами, которую RNN теряет |
| vanishing gradient | затухающий градиент (`vanishing gradient`) | исчезающий градиент | Градиент становится почти нулевым при обратном распространении ошибки |
| attention | внимание (`attention`) | аттеншн | Механизм: для каждого токена модель решает, на какие другие токены смотреть. Когда слово стоит одно (в начале фразы, в подписи), пишем «механизм внимания»: одно «Внимание.» читается как предупреждение |
| self-attention | самовнимание (`self-attention`) | — | Внимание, где токены смотрят на токены того же текста |
| query | `query` (запрос) | — | Что ищет токен. Буква Q в формуле |
| key | `key` (ключ) | — | Чем помечен токен. Буква K в формуле |
| value | `value` (значение) | — | Что токен отдаёт, когда его выбрали. Буква V в формуле |
| softmax | `softmax` (превращает числа в вероятности) | софтмакс | Функция, которая превращает числа в веса с суммой, равной единице |
| multi-head attention | многоголовое внимание (`multi-head attention`) | — | Внимание из нескольких «голов», которые считают параллельно |
| cross-attention | перекрёстное внимание (`cross-attention`) | — | Внимание, где `query` из декодера, а `key` и `value` из энкодера |
| masked self-attention | маскированное самовнимание (`masked self-attention`) | — | Токен видит только себя и предыдущие токены |
| causal mask | каузальная маска (`causal mask`) | причинная маска | Маска, которая не даёт токену смотреть на следующие токены |
| encoder | энкодер (`encoder`) | кодировщик | Часть трансформера, которая читает вход |
| decoder | декодер (`decoder`) | дешифратор | Часть трансформера, которая пишет выход |
| encoder-only | `encoder-only` (только энкодер) | — | Модель только из энкодера, например BERT |
| decoder-only | `decoder-only` (только декодер) | — | Модель только из декодера, например GPT |
| positional embedding | `positional embedding` (вектор позиции) | позиционный эмбеддинг | Вектор, который сообщает модели позицию токена |
| RoPE (rotary position embedding) | `RoPE` (позиция через поворот векторов) | ротационные эмбеддинги | Позиция кодируется поворотом векторов `query` и `key` |
| feedforward network | полносвязная сеть (`feedforward`) | — | Слой, в котором лежит большая часть параметров |
| linear layer | линейный слой (`linear layer`) | — | Умножение на матрицу весов |
| activation function | функция активации (`activation function`) | — | Нелинейная функция после линейного слоя |
| residual connection | остаточная связь (`residual connection`) | скип-соединение | Вход блока прибавляется к его выходу |
| layer normalization | нормализация слоя (`LayerNorm`) | — | Нормировка значений внутри слоя. `RMSNorm` проще и быстрее |
| dropout | `dropout` (случайное отключение значений) | дропаут | При обучении часть значений случайно обнуляют |
| label smoothing | сглаживание меток (`label smoothing`) | — | Верному токену дают не 100%, а меньше, остаток делят между остальными |
| autoregressive | авторегрессионный (`autoregressive`) | — | Каждый новый токен подаётся на вход для следующего |
| sliding window attention | внимание со скользящим окном (`sliding window attention`) | — | Токен смотрит только на окно из ближайших токенов |
| grouped-query attention (GQA) | `GQA` (grouped-query attention: головы делят ключи и значения) | групповое внимание | Несколько голов `query` делят одни `key` и `value`. Экономит память |
| mixture of experts (MoE) | `MoE` (смесь экспертов) | — | Модель из групп параметров («экспертов»). На токен работают только несколько |
| scaling law | закон масштабирования (`scaling law`) | — | Как качество зависит от размера модели, данных и вычислений |
| prompt | `prompt` (запрос к модели) | промпт | Текст, который мы отправляем модели |
| context window | контекстное окно (`context window`) | — | Сколько токенов модель видит за раз |
| context rot | `context rot` (качество падает на длинном контексте) | гниение контекста | Модель хуже работает, когда контекст длинный |
| chain of thought (CoT) | цепочка рассуждений (`chain of thought`) | — | Модель рассуждает по шагам перед ответом |
| sampling | `sampling` (выбор следующего токена по вероятностям) | сэмплирование, семплинг | Как модель выбирает токен из распределения |
| temperature | температура (`temperature`) | — | Параметр случайности при выборе токена |
| inference | `inference` (работа обученной модели) | инференс | Расчёт ответа уже обученной моделью |

| post-training | `post-training` (обучение после предобучения) | постобучение | `SFT`, `preference tuning`, RL |

| preference tuning | `preference tuning` (обучение на предпочтениях) | — | Обучение по данным о том, какой ответ лучше |
