# Глоссарий: Escaping the Build Trap (Melissa Perri)

Единые слова для всех глав. Правила: навык `book-summary`, раздел «Translation guide».
Колонка «Как пишем»: термин в обратных кавычках = оставляем английским; обычное слово = пишем по-русски (английский в скобках при первом упоминании).
Колонка «Не писать»: варианты, которые `check.py --glossary` считает ошибкой.

| English | Как пишем | Не писать | Пояснение |
|---|---|---|---|
| build trap | `build trap` | ловушка разработки, ловушка сборки | Главный термин книги: компания меряет успех числом выпущенных фич, а не пользой для клиента |
| product management | управление продуктом (`product management`) | продуктовый менеджмент | Роль и практики, которые превращают проблемы клиента в ценность для бизнеса |
| product manager | продакт-менеджер (`product manager` при первом упоминании) | продуктовый менеджер | Отвечает за то, какой продукт строить и зачем. Не руководитель команды |
| product owner | `product owner` | владелец продукта | Роль в Scrum: ведёт backlog и работает с командой разработки. Автор отделяет её от `product manager` |
| product team | продуктовая команда | команда продукта | Разработчики, дизайнеры и `product manager` вокруг одного продукта |
| product operations | `product operations` | продуктовые операции | Команда, которая даёт `product manager` данные, процессы и инструменты |
| CPO | `CPO` | директор по продукту | Chief Product Officer. Отвечает за стратегию и людей продуктовой организации |
| VP of product | `VP of product` | вице-президент по продукту | Руководитель продуктового направления ниже `CPO` |
| group product manager | `group product manager` | групповой менеджер | Ведёт `product manager` одного направления. Растит их и coach'ит |
| feature | фича | — | Часть продукта, которую выпускает команда |
| feature factory | `feature factory` | фабрика фич | Команда, которая только выпускает фичи и не проверяет их пользу |
| output | результат работы (`output`) | — | Что команда выпустила: фичи, релизы. Противопоставлен `outcome` |
| outcome | `outcome` | — | Изменение поведения клиента, которое приносит пользу бизнесу |
| business outcome | бизнес-результат (`business outcome`) | бизнес-исход | Чего хочет компания: рост выручки, меньше оттока |
| customer outcome | результат для клиента (`customer outcome`) | исход клиента | Чего клиент достиг с помощью продукта |
| value | ценность | стоимость | Польза для клиента и для бизнеса |
| value exchange | обмен ценностью (`value exchange`) | — | Клиент платит деньгами или вниманием, компания даёт пользу |
| customer-centric | ориентация на клиента | клиентоцентричность | Решения компании исходят из проблем клиента |
| strategy | стратегия | — | План, как компания выиграет на рынке. Автор: это не список инициатив |
| strategic intent | `strategic intent` | стратегическое намерение | Цель компании на 1-3 года, к которой ведут все инициативы |
| strategic gap | стратегический разрыв (`strategic gap`) | — | Разрыв между тем, где компания сейчас и где хочет быть |
| strategy deployment | `strategy deployment` | развёртывание стратегии | Способ довести стратегию до команд: цели идут сверху вниз, идеи снизу вверх |
| vision | видение (`vision`) | — | Картина будущего, ради которой компания работает |
| product vision | видение продукта (`product vision`) | — | Куда ведёт продукт и как он решает проблему клиента |
| mission | миссия | — | Зачем компания существует |
| product strategy | стратегия продукта (`product strategy`) | — | Как продукт достигнет цели компании |
| product portfolio | портфель продуктов (`product portfolio`) | — | Все продукты компании, которыми управляют как набором |
| product initiative | `product initiative` | — | Крупная работа, которая двигает продукт к цели |
| roadmap | `roadmap` | дорожная карта | План. Автор спорит с планом по датам и фичам: нужен план по целям |
| backlog | бэклог | — | Очередь работ команды |
| Product Kata | `Product Kata` | ката продукта | Авторский цикл из текущего состояния, целевого состояния, препятствий и экспериментов. Основан на Toyota Kata |
| target condition | целевое состояние (`target condition`) | целевое условие | Что должно стать лучше, измеримо |
| current condition | текущее состояние (`current condition`) | — | Где команда сейчас по измеримым фактам |
| obstacle | препятствие | — | Что мешает перейти к целевому состоянию |
| hypothesis | гипотеза | — | Проверяемое предположение о том, что решит проблему |
| experiment | эксперимент | — | Дешёвая проверка гипотезы до большой разработки |
| problem exploration | исследование проблемы (`problem exploration`) | — | Этап: понять, есть ли проблема и у кого |
| solution exploration | исследование решения (`solution exploration`) | — | Этап: проверить, что решение работает, до полной сборки |
| MVP | `MVP` | минимально жизнеспособный продукт | Самая маленькая версия, которая проверяет гипотезу |
| prototype | прототип | — | Модель продукта для проверки идеи на людях |
| success metric | метрика успеха (`success metric`) | — | Число, по которому видно, что цель достигнута |
| KPI | `KPI` | ключевой показатель эффективности | Главные метрики результата |
| OKR | `OKR` | — | Цели и ключевые результаты. Автор советует ставить их на `outcome`, не на `output` |
| north star | `north star` | — | Главная метрика продукта |
| A/B test | A/B-тест | А/Б-тест | Две версии показывают разным группам и сравнивают |
| user research | исследование пользователей (`user research`) | юзер-рисерч | Разговоры и наблюдения за клиентами |
| user story | `user story` | пользовательская история | Короткое описание задачи с точки зрения пользователя |
| agile | `Agile` | аджайл, гибкая методология | Семейство подходов с короткими итерациями |
| Scrum | `Scrum` | скрам | Одна из практик `Agile` с ролями и спринтами |
| sprint | спринт | — | Короткий цикл работы команды |
| waterfall | `waterfall` | водопад | Последовательная разработка по этапам |
| Lean Startup | `Lean Startup` | — | Подход Эрика Риса: build, measure, learn |
| cost of delay | `cost of delay` | цена задержки | Сколько бизнес теряет за время ожидания фичи |
| technical debt | технический долг | техдолг | Плохие решения в коде, за которые потом платят временем |
| stakeholder | стейкхолдер | заинтересованное лицо | Человек вне команды, чьё мнение влияет на продукт |
| product-led | `product-led` | — | Компания, где продукт ведёт рост, а не продажи или маркетинг |
| sales-led | `sales-led` | — | Компания, где продажи диктуют, что строить |
| project | проект | — | Работа с датой конца. Автор противопоставляет её продукту, который живёт, пока нужен |
| career path | карьерный путь продакта (`career path`) | — | Ступени роста `product manager`: от `associate` до `CPO` |
| coaching | коучинг | — | Руководитель учит `product manager`, а не раздаёт задачи |
| story map | `story map` | карта историй | Картина пути пользователя по шагам. Из неё команда выбирает, что строить первым |
| vanity metric | `vanity metric` | метрика тщеславия, тщеславная метрика | Число, которое приятно видеть, но оно не меняет решений |
| leading indicator | `leading indicator` | опережающий индикатор | Число, которое меняется раньше результата и даёт сигнал заранее |

| business case | `business case` | бизнес-кейс | Расчёт: сколько стоит идея и что она даст компании |
