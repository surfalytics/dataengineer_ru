# Единый глоссарий

Формы для перевода и конспекта. Английский термин при первом появлении сопровождается коротким пояснением. Написание в коде, командах и названиях API сохраняется.

| English | Как пишем | Не писать | Пояснение |
|---|---|---|---|
| data lakehouse | `lakehouse` | озерохранилище | Архитектура с общим хранилищем, табличным слоем и поддержкой аналитических и ML-нагрузок. |
| data lake | `data lake` | озеро данных | Хранит разнородные данные в исходном или обработанном виде. |
| data warehouse | хранилище данных (`data warehouse`) | склад данных | Центральная система для аналитики |
| object storage | объектное хранилище (`object storage`) | — | Хранение объектов по ключу (S3) |
| data catalog | каталог данных (`data catalog`) | — | Описание наборов данных: владелец, схема, смысл |
| metadata | метаданные | — | Данные о данных: схема, владелец, время обновления |
| data governance | `data governance` | — | Правила, ответственность и контроль качества, доступа и использования данных. |
| data lineage | `lineage` | линидж | Источники, перемещения и преобразования, через которые прошли данные. |
| data observability | `data observability` | — | Видно, что с данными происходит |
| data sharing | `data sharing` | шеринг данных | Предоставление другим потребителям доступа к данным. Способ передачи зависит от реализации. |
| data product | `data product` | — | Набор данных, которым управляют как продуктом |
| data mesh | `data mesh` | — | Подход: данными владеют доменные команды |
| ingestion | `ingestion` | — | Стадия, где данные забирают из источника |
| data pipeline | `pipeline` | пайплайн | Цепочка шагов, которая двигает и меняет данные |
| change data capture | `CDC` (`change data capture`) | захват изменений | Передача изменений базы во внешние системы |
| ETL / ELT | `ETL` / `ELT` | — | Порядок: transform до load или после |
| OLTP / OLAP | `OLTP` / `OLAP` | — | Транзакции против аналитических запросов |
| vendor lock-in | `vendor lock-in` | — | Зависимость от одного поставщика |
| data mart | `data mart` | витрина данных | Небольшой набор данных под одну тему или команду |
| columnar storage | колоночное хранение (`columnar`) | столбцовое хранение | Значения колонки лежат рядом |
| copy on write | `copy on write` (`COW`) | — | При изменении записей переписываются затронутые файлы данных. |
| feature store | `feature store` | — | Хранилище признаков для ML |
| partition | `partition` | — | Для таблиц это часть набора данных, выделенная по правилу разбиения. |
| data fabric | `data fabric` | — | Единый слой доступа к разрозненным данным через metadata и автоматизацию |
| serverless | `serverless` | бессерверный | Сервис без управления серверами: платите за вызовы |
| total cost of ownership | `total cost of ownership` (`TCO`) | общая стоимость владения без пояснения | Все прямые и косвенные расходы на систему |
| table format | табличный формат (`table format`) | — | Iceberg, Delta: какие файлы составляют таблицу |
| time travel | `time travel` | путешествие во времени | Чтение старой версии данных |
| compaction | `compaction` | уплотнение | Объединение небольших файлов данных или изменений. Слово «сжатие» закреплено за compression и не используется для compaction. Конкретная операция зависит от табличного формата. |
| snapshot | snapshot | снапшот | Зафиксированное состояние таблицы на определённый момент. |
| data contract | `data contract` | контракт данных | Соглашение поставщика данных с потребителями о составе данных и условиях поставки. |
| failover | `failover` | фейловер | Переход на другую реплику, когда лидер упал |
| durability | долговечность | устойчивость | Записанное не пропадает после сбоя |
| latency | задержка (`latency`) | латентность | Время от запроса до ответа |
| throughput | `throughput` | пропускная способность | Сколько записей или байт система обрабатывает за секунду |
| batch processing | пакетная обработка | батч-обработка | Обработка ограниченного набора записей за один запуск. |
| stream processing | потоковая обработка | стриминговая обработка | Обработка поступающих событий по мере их появления. |
| HTAP | `HTAP` | — | OLTP и аналитика в одной системе |
| metastore | `metastore` | метахранилище | Сервис хранения и выдачи технических метаданных, например схем и расположения таблиц. |
| schema on read | `schema on read` | — | Схема применяется при чтении, а не при записи |
| schema enforcement / evolution | `schema enforcement` / `schema evolution` | принудительная схема, эволюция схемы | Первое проверяет соответствие записываемых данных схеме. Второе допускает изменение схемы по правилам формата. |
| transaction log | `transaction log` | журнал транзакций, delta log | История зафиксированных изменений таблицы. В книге термин встречается при описании Delta Lake. |
| partitioning | `partitioning` | партицирование | Организация данных таблицы по ключу или преобразованию ключа. |
| clustering | `clustering` | кластеризация | Организация близких по ключу значений для сокращения объёма чтения. |
| file format | формат файла | — | Описывает кодирование данных внутри файла, например Parquet. Выражение «табличный формат» закреплено за table format. |
| compute engine | вычислительный движок | кластер как синоним | Исполняет вычисления. Кластер предоставляет для них ресурсы. |
| storage tier | уровень хранения | слой очистки данных | Группа хранилищ с определённой стоимостью и характеристиками доступа. Учитывать смысл в контексте. |
| merge on read | `merge on read` (`MOR`) | слияние таблиц | Изменения хранятся отдельно и совмещаются с основными данными при чтении. |
| RPO | целевая точка восстановления (RPO) | время простоя | Допустимый объём потери данных, выраженный интервалом времени. |
| RTO | целевое время восстановления (RTO) | допустимая потеря данных | За какой срок нужно восстановить работу после сбоя. |
| data management | управление данными | data governance как полный синоним | Практические процессы работы с данными на протяжении жизненного цикла. |
