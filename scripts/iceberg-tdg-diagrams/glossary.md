# Глоссарий Apache Iceberg

В прозе при первом употреблении даём короткое пояснение. Регистр и написание в коде, SQL, именах свойств, API и ссылках сохраняем.

| English | Как пишем | Не писать | Пояснение |
|---|---|---|---|
| data lake | data lake | дейталейк | Хранилище данных в файлах. |
| data lakehouse | lakehouse | озерохранилище | Архитектура, которая добавляет возможности аналитического хранилища к данным в файловом или объектном хранилище. |
| data warehouse | хранилище данных (DWH) | варехаус | Система для аналитической работы с данными. |
| open table format | открытый формат таблиц | открытый файловый формат | Описывает устройство и правила изменения таблицы, которая может состоять из множества файлов. |
| file format | формат файла | формат таблицы | Внутреннее устройство файла, например Parquet. |
| compute engine | вычислительный движок | движок хранения | Выполняет вычисления над данными. |
| query engine | движок запросов | запросный двигатель | Планирует и выполняет запросы. |
| object storage | объектное хранилище | объектная база | Хранит объекты по ключу. |
| catalog | каталог Iceberg | каталог файлов | Связывает имя таблицы с её текущими метаданными. |
| namespace | пространство имён | папка | Группирует имена таблиц в каталоге. |
| snapshot | snapshot | снапшот | Состояние данных таблицы на момент фиксации. |
| time travel | time travel | путешествие во времени | Чтение состояния таблицы на указанное время или по идентификатору snapshot. |
| rollback | откат | откат чтения | Возврат таблицы к предыдущему состоянию. |
| commit | фиксация изменения | сохранение файла | Шаг, после которого новая версия метаданных становится текущей. |
| atomic swap | атомарная замена | синхронная замена | Замена ссылки на метаданные как одна неделимая операция. |
| optimistic concurrency control | оптимистическое управление конкурентным доступом | оптимистическая блокировка таблицы | Перед фиксацией проверяется, можно ли применить изменение при текущем состоянии таблицы. |
| metadata file | файл метаданных таблицы | — | Описывает таблицу, в том числе её схемы и snapshot. В этом значении следует отличать от термина «манифест». |
| manifest file | файл манифеста | файл со списком манифестов | Содержит записи о файлах данных или файлах удалений и статистику. |
| manifest list | список манифестов | — | Файл, который перечисляет манифесты одного snapshot. В этом значении следует отличать от термина «манифест». |
| data file | файл данных | файл таблицы без уточнения | Содержит строки таблицы. |
| delete file | файл удалений | — | Описывает строки, которые следует исключить при чтении. В этом значении следует отличать от термина «удалённый файл». |
| positional delete | удаление по позиции | удаление по номеру ключа | Строку задают путь к файлу данных и позиция внутри файла. |
| equality delete | удаление по значениям полей | удаление одинаковых строк | Удаление применяется к строкам, значения указанных полей которых совпадают с заданными. |
| sequence number | порядковый номер | идентификатор snapshot | Передаёт порядок изменений. |
| copy-on-write (COW) | copy-on-write (COW) | копирование таблицы целиком | При изменении строк переписываются затронутые файлы данных. |
| merge-on-read (MOR) | merge-on-read (MOR) | перезапись при чтении | Читатель применяет сведения об удалениях к файлам данных. |
| partition | раздел таблицы | шард | Группа данных с одинаковыми значениями полей разбиения. |
| partition spec | спецификация разбиения | — | Задаёт поля разбиения и преобразования исходных столбцов. В этом значении следует отличать от термина «схема таблицы». |
| partition transform | преобразование разбиения | преобразование раздела | По исходному значению вычисляет значение поля разбиения. |
| hidden partitioning | скрытое разбиение | скрытый раздел | Iceberg выводит ограничения на разделы из условий по исходным полям. |
| partition evolution | изменение схемы разбиения | переразбиение всех файлов | Позволяет сменить спецификацию для новых записей и читать файлы со старыми и новыми спецификациями. |
| schema evolution | schema evolution | миграция всех данных | Изменение структуры таблицы с сохранением связей полей по идентификаторам. |
| field ID | идентификатор поля | номер столбца по порядку | Стабильный идентификатор поля в схеме. |
| pruning | отсечение | обрезка данных | Исключение объектов из плана чтения по метаданным и условиям запроса. |
| predicate pushdown | передача предиката на уровень чтения | проталкивание данных | Позволяет использовать фильтр ближе к источнику. |
| compaction | compaction | сжатие данных | Перезапись файлов для улучшения их размера или расположения данных. |
| orphan file | файл без ссылок | устаревший snapshot | В контексте очистки это файл, который больше не связан с таблицей через её метаданные. |
| expire snapshots | удалять устаревшие snapshot | откатывать таблицу | Операция обслуживания с учётом настроек хранения и действующих ссылок. |
| branch | ветка | копия таблицы | Именованная ссылка на snapshot, которая может продвигаться при новых фиксациях. |
| tag | метка | — | Именованная ссылка, закрепляющая определённый snapshot. В этом значении следует отличать от термина «ветка». |
| write-audit-publish | write-audit-publish (WAP) | публикация до проверки | Сначала записывают данные, затем проверяют их и публикуют. |
| change data capture | отслеживание изменений данных (CDC) | полный снимок таблицы | Передача сведений о вставках, обновлениях и удалениях. |
| data pipeline | pipeline | пайплайн | Последовательность шагов обработки данных. |
