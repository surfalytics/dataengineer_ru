# Глоссарий: The Data Warehouse Toolkit, 3rd Edition (Ralph Kimball, Margy Ross)

Единые слова для всех глав. Правила: навык `book-summary`, раздел «Translation guide».
Колонка «Как пишем»: термин в обратных кавычках = оставляем английским; обычное слово = пишем по-русски.

| English | Как пишем | Не писать | Пояснение |
|---|---|---|---|
| data warehouse | хранилище данных (`data warehouse`) | склад данных | Хранилище для аналитики и отчётов |
| data mart | витрина данных (`data mart`) | — | Набор таблиц для одного бизнес-процесса |
| dimensional modeling | `dimensional modeling` | размерное моделирование, многомерное моделирование | Метод Kimball: факты и измерения |
| star schema | `star schema` | звёздная схема | Таблица фактов в центре, измерения вокруг, на реляционной СУБД |
| snowflake schema | `snowflake schema` | снежинка | Звезда с нормализованными измерениями. Kimball обычно не советует |
| OLAP cube | `OLAP cube` | кубик | Многомерная база. Книга считает куб одним из видов хранения для звезды |
| OLTP | `OLTP` | — | Операционная система для транзакций |
| fact table | таблица фактов (`fact table`) | факт-таблица | Измерения процесса: продажи, остатки, проводки |
| dimension | измерение (`dimension`) | размерность | Контекст фактов: кто, что, где, когда, почему, как |
| dimension table | таблица измерений (`dimension table`) | — | Таблица с атрибутами одного измерения |
| fact | факт | — | Числовое значение, которое измеряет процесс |
| grain | `grain` | зернистость | Что значит одна строка таблицы фактов. Объявляем до выбора измерений и фактов |
| business process | бизнес-процесс | — | Операция бизнеса, которую описывает таблица фактов |
| four-step design process | четыре шага проектирования | — | Бизнес-процесс, `grain`, измерения, факты |
| surrogate key | `surrogate key` | суррогатный ключ | Целое число без смысла, которое хранилище выдаёт строке измерения |
| natural key | `natural key` | естественный ключ, натуральный ключ | Ключ строки в исходной системе |
| durable key | `durable key` | устойчивый ключ, долговечный ключ | Ключ, который не меняется, даже если у объекта меняется `natural key` |
| primary key | первичный ключ | — | Однозначно определяет строку |
| foreign key | внешний ключ | — | Ссылка на ключ другой таблицы |
| referential integrity | ссылочная целостность | — | Каждый внешний ключ указывает на существующую строку |
| additive fact | `additive fact` | аддитивный факт | Факт, который можно суммировать по всем измерениям |
| semi-additive fact | `semi-additive fact` | полуаддитивный факт | Суммируется не по всем измерениям, например остаток не суммируют по времени |
| non-additive fact | `non-additive fact` | неаддитивный факт | Не суммируется: цены, коэффициенты. Считаем из слагаемых |
| transaction fact table | `transaction fact table` | — | Одна строка на событие в момент времени |
| periodic snapshot | `periodic snapshot` | периодический снимок | Одна строка на объект за период, например остаток на конец дня |
| accumulating snapshot | `accumulating snapshot` | накопительный снимок | Одна строка на весь жизненный цикл, строку обновляют по мере этапов |
| factless fact table | `factless fact table` | безфактовая таблица, таблица без фактов | Фиксирует событие или покрытие, числовых фактов нет |
| consolidated fact table | `consolidated fact table` | консолидированная таблица фактов | Факты из нескольких процессов в одной таблице на общем `grain` |
| degenerate dimension | `degenerate dimension` | вырожденное измерение | Номер документа в таблице фактов без своей таблицы измерений |
| role-playing dimension | `role-playing dimension` | ролевое измерение, измерение-роль | Одно измерение, на которое ссылаются несколько раз: дата заказа, дата отгрузки |
| junk dimension | `junk dimension` | мусорное измерение | Одна таблица для набора флагов и индикаторов с малым числом значений |
| conformed dimension | `conformed dimension` | согласованное измерение | Измерение с одинаковым смыслом и ключами во всех витринах |
| conformed fact | `conformed fact` | согласованный факт | Факт с одним определением и единицами во всех таблицах |
| outrigger dimension | `outrigger dimension` | — | Измерение, на которое ссылается другое измерение. Допустимо в малой доле |
| mini-dimension | `mini-dimension` | миниизмерение | Выносит часто меняющиеся атрибуты большого измерения в отдельную таблицу |
| bridge table | `bridge table` | мостовая таблица | Связывает таблицу фактов с измерением, когда у факта несколько значений атрибута |
| multivalued dimension | `multivalued dimension` | многозначное измерение | У одной строки факта несколько значений измерения |
| ragged hierarchy | `ragged hierarchy` | рваная иерархия | Иерархия с переменным числом уровней |
| fixed depth hierarchy | иерархия фиксированной глубины | — | Все уровни есть в самой таблице измерений |
| slowly changing dimension | `SCD` (`slowly changing dimension`) | медленно меняющееся измерение | Приёмы для атрибутов, которые меняются редко |
| SCD type 1 | `SCD1` | — | Перезаписать значение, историю не хранить |
| SCD type 2 | `SCD2` | — | Добавить новую строку с новым `surrogate key` и периодом действия |
| SCD type 3 | `SCD3` | — | Добавить колонку для прошлого значения |
| late arriving fact / dimension | `late arriving fact` / `late arriving dimension` | запоздавший факт | Строка пришла позже события, к которому относится |
| audit dimension | `audit dimension` | — | Метаданные о том, как строка факта попала в хранилище |
| enterprise data warehouse bus architecture | `bus architecture` | шина данных | Витрины строятся по общим `conformed dimension` |
| enterprise data warehouse bus matrix | `bus matrix` | шинная матрица, матрица шины | Строки: бизнес-процессы. Столбцы: измерения |
| drill across | `drill across` | — | Запрос по нескольким таблицам фактов через общие измерения |
| drill down | `drill down` | — | Переход от итогов к деталям |
| aggregate | агрегат (`aggregate`) | — | Предсчитанная таблица для скорости. Выбор между агрегатом и сырой таблицей прозрачен для пользователя |
| ETL | `ETL` | — | Extract, Transform, Load. В книге: 34 подсистемы ETL |
| ETL subsystem | подсистема `ETL` | — | Одна из 34 типовых частей ETL |
| staging area | `staging area` | зона подготовки | Область, где данные лежат до загрузки в витрины |
| data profiling | `data profiling` | — | Проверка источника: типы, диапазоны, пропуски |
| data lineage | `lineage` | линидж | Откуда пришли данные и какие шаги их изменили |
| master data management | `MDM` (`master data management`) | — | Единый справочник ключевых сущностей: клиент, товар |
| data governance | `data governance` | — | Правила владения, доступа и качества данных |
| data steward | `data steward` | — | Отвечает за смысл и качество своих данных |
| metadata | метаданные | — | Данные о данных: определения, происхождение, расписания |
| Kimball lifecycle | жизненный цикл Kimball (`Kimball lifecycle`) | — | Путь проекта: планирование, требования, три ветки, развёртывание |
| independent data marts | независимые витрины | — | Витрины без общих измерений. Anti-pattern по Kimball |
| hub-and-spoke (CIF) | `hub-and-spoke` (`CIF`) | — | Подход Inmon: нормализованное хранилище и витрины вокруг |
| big data | `big data` | большие данные | Данные большого объёма и разных форматов. Книга показывает, как они дополняют хранилище |
