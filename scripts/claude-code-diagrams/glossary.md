# Глоссарий: Claude Code: Up and Running (Ken Kousen)

Единые слова для всех глав. Правила — в навыке `book-summary`, раздел «Translation guide».
Колонка «Как пишем»: термин в обратных кавычках = оставляем английским; обычное слово = пишем по-русски (английский в скобках при первом упоминании).
Колонка «Не писать»: варианты, которые `check.py --glossary` считает ошибкой.
Формы взяты из глоссариев `redefining-de-ai-diagrams` и `ai-engineering-diagrams`.

## Общие

| English | Как пишем | Не писать | Пояснение |
|---|---|---|---|
| Agent-Driven Development (AgDD) | `Agent-Driven Development` (`AgDD`) | агентная разработка, разработка на агентах | Термин книги: агент делает production-работу, а человек задаёт направление, условия успеха и проверку |
| agent | агент | `agent`, эйджент | Система на LLM, которая сама планирует шаги и вызывает инструменты |
| agentic coding | `agentic coding` | агентное программирование, агентный кодинг | Кодинг, где агент сам читает код, правит файлы и запускает команды |
| agentic harness | `harness` | обвязка, каркас, упряжь | Всё вокруг модели в Claude Code: инструменты, права, контекст, цикл запросов. Модель — это «движок» |
| prompt | `prompt` | промпт | Текст-запрос к модели |
| context window | `context window` | контекстное окно, окно контекста | Сколько токенов модель видит за раз |
| compaction | сжатие контекста (`compact`) | компактизация, компакт | Claude Code сжимает историю разговора, часть деталей теряется. Команда `/compact` |
| sandbox | `sandbox` | песочница | Изолированная среда: ограничивает, что может сделать агент |
| non-deterministic | недетерминированный | — | Один и тот же запрос может дать разные ответы |

## Глава 1: подъём Agent-Driven Development

| English | Как пишем | Не писать | Пояснение |
|---|---|---|---|
| vibe coding | `vibe coding` | вайб-кодинг | Описываем результат, агент пишет код, мы проверяем только, что работает |
| doghouse | `doghouse` | будка, собачья будка | Термин книги: маленький личный проект на выходные, код никто не проверяет |
| cabin | `cabin` | хижина, домик | Термин книги: скромный, но надёжный проект. Есть границы, тесты, явные договорённости |
| skyscraper | `skyscraper` | небоскрёб | Термин книги: большая система с командой, процессами и долгой жизнью |
| three scales (project scales) | три масштаба проекта | — | `doghouse`, `cabin`, `skyscraper`: чем больше масштаб, тем строже дисциплина |
| request loop | цикл запроса (`request loop`) | петля запроса | Claude Code читает контекст, планирует, использует инструменты, проверяет, отвечает |
| permission gate | запрос разрешения (`permission gate`) | ворота разрешений, шлюз | Запись файлов и shell-команды идут только после согласия человека |
| hooks | `hooks` | хуки, крючки | Скрипты, которые срабатывают на события жизненного цикла Claude Code |
| skill | `skill` | навык, скилл | Пакет инструкций, который расширяет возможности агента. Может запускаться как команда |
| subagent | `subagent` | субагент, подагент | Отдельный агент со своим контекстом. Основной агент отдаёт ему часть работы |
| agent teams | `agent teams` | команды агентов | Несколько сессий работают вместе. Пока экспериментальная функция |
| trust contract | явная договорённость (`trust contract`) | контракт доверия | Термин книги: что код обещает и что проверено. Нужна в `cabin` |
| testable core | тестируемое ядро | — | Логика отдельно от интерфейса и ввода-вывода, чтобы её легко тестировать |
| software maintenance | сопровождение (maintenance) | поддержка кода, мейнтенанс | По NIST 60–70% стоимости ПО, по Глассу 40–80% |
| production work | production-работа | производственная работа | То, что делает агент: пишет и меняет код |
| direction, verification, judgment | направление, проверка, оценка | — | То, что остаётся человеку в AgDD |
| embedded tutor / pull-mode learning | встроенный наставник, обучение по запросу | — | Спрашиваем агента о коде в тот момент, когда знание нужно |
| autocomplete | автодополнение | автокомплит | Copilot, JetBrains AI Assistant: дописывают код строку за строкой |
| MCP | `MCP` | — | Model Context Protocol: общий протокол, через который агент подключается к внешним сервисам |

## Глава 3: разговор с Claude Code

| English | Как пишем | Не писать | Пояснение |
|---|---|---|---|
| clarification pass | уточняющий проход (`clarification pass`) | проход уточнения | Просим агента задать вопросы до работы, чтобы он не угадывал |
| slash command | `slash`-команда | слеш-команда, косая команда | Команда вида `/clear`, `/compact`, `/help` |
| custom command | своя команда | кастомная команда | Старый способ: сохранённый prompt в `.claude/commands/`. Сейчас её заменяют `skill` |
| plugin | `plugin` | плагин | Пакет из `skill`, команд, `MCP server` и `hooks` |
| effort level | уровень усилий (`effort`) | уровень эффорта | Сколько модель «думает» над задачей. Подбираем под задачу |
| headless mode | `headless mode` | безголовый режим, режим без интерфейса | Запуск без диалога, одной командой, для скриптов и CI |
| plan mode | `plan mode` | режим планирования | Агент только читает и составляет план, ничего не меняет, пока мы не одобрим |
| output style | `output style` | стиль вывода, стиль ответа | Настройка манеры ответа: например, «скептичный старший инженер» |
| @ file reference | `@`-ссылка на файл | собака-ссылка | `@src/app.js` в prompt подтягивает файл в разговор, агенту не нужно его искать |
| success condition | условие успеха | условие сукцесса | Что значит «готово»: маршрут возвращает 400, тест проходит |
| over-specification | лишняя детализация | овер-спецификация | Диктуем, как писать код, вместо того, что должно получиться |
| tool use | вызов инструмента (`tool use`) | использование тула | Любое действие вне генерации текста: чтение файла, shell-команда, MCP |
| steer | `steer` (указание посреди работы) | рулить | Новое указание во время долгой задачи, агент берёт его перед следующим вызовом инструмента |
| session | сессия | сеанс | Сохранённый разговор, привязанный к папке проекта |
| checkpoint / rewind | `checkpoint` | контрольная точка | Двойной Esc открывает выбор точки, к которой можно откатиться |
| stateless | без состояния (`stateless`) | безгосударственный | Запрос к API не помнит предыдущих запросов |
| RAG | `RAG` | — | Retrieval-Augmented Generation: в контекст кладут только нужные куски документов |
| expand-contract | `expand-contract` | расширить-сжать | Миграция колонки по шагам: новая колонка, backfill, двойная запись, переключение чтения, удаление старой |
| shadow table | теневая таблица (`shadow table`) | — | Создать новую таблицу, скопировать, переименовать |
| blast radius | что сломается (`blast radius`) | радиус взрыва | Сколько всего заденет неверное изменение |
| ultracode | `ultracode` | — | Уровень `effort`: xhigh плюс автоматическая оркестрация workflows |

## Глава 4: когда vibe coding не хватает

| English | Как пишем | Не писать | Пояснение |
|---|---|---|---|
| refactoring | рефакторинг | переработка кода | Меняем устройство кода, не меняя поведение |
| DOM glue | тонкий слой для DOM (`DOM glue`) | клей DOM | Код интерфейса должен быть «скучным»: вся логика уходит в тестируемое ядро |
| project memory | память проекта (`project memory`) | проектная память | Знания о проекте, которые агент получает в каждой сессии |
| CLAUDE.md | `CLAUDE.md` | — | Файл с инструкциями, который вы пишете сами. Claude Code читает его в начале каждой сессии |
| auto memory | `auto memory` | авто-память, автопамять | Заметки, которые Claude пишет себе сам по вашим поправкам. Лежат в `~/.claude/projects/` |
| import (@) | `@`-импорт | — | Строка `@file.md` в `CLAUDE.md` подключает другой файл |
| AGENTS.md | `AGENTS.md` | — | Общий формат инструкций для агентов. Claude Code читает его только через `@AGENTS.md` |
| context is a budget | контекст — это бюджет | — | Мысль книги: контекст ограничен, держим `CLAUDE.md` коротким |
| context rot | падение качества из-за длинного контекста | — | Ответы хуже, когда контекст заполнен, даже если место есть (после 300–400K токенов) |
| enforcement | жёсткое ограничение (`enforcement`) | принуждение | Права, `hooks` и `sandbox` блокируют действие. `CLAUDE.md` и память лишь советуют |
| unit test | `unit test` (в составных словах: unit-тест) | модульный тест, юнит-тест | Тест одной функции или модуля без остальной системы |
| end-to-end test | end-to-end тест | сквозной тест | Тест всей системы через интерфейс: медленный и хрупкий |
| edge case | граничный случай | краевой случай, эдж-кейс | Значение на краю допустимого: последняя строка, испорченный индекс |
| fake / test double | заглушка | фейк, мок | Простой объект с тем же интерфейсом, что и настоящая зависимость |
| Single Responsibility Principle | принцип единственной ответственности (Single Responsibility Principle) | — | Принцип SOLID: у модуля одна задача |
| code coverage | покрытие кода тестами (code coverage) | кавередж | Доля строк кода, которые выполняют тесты |
| MCP server | `MCP server` | MCP-сервер | Сервер, через который агент получает внешние данные и инструменты |
