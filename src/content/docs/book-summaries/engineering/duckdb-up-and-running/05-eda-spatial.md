**Главная мысль:** разведочный анализ (`EDA`) можно сделать почти целиком на SQL в DuckDB. Python нужен только для карт и графиков. В главе всё идёт на одном датасете: рейсы США за 2015 год. Главный урок: сравнивайте группы по доле, а не по числу строк.

## О чём глава

Глава 4 была про Polars. Здесь DuckDB решает живую задачу: исследовать данные от первого взгляда до выводов. Темы: загрузка трёх CSV, геоанализ (карта, `spatial`, ближайшие аэропорты) и описательная аналитика (штаты, маршруты, отмены, дни недели, слоты времени, задержки).

## Что такое EDA

`EDA` (exploratory data analysis) — подход, когда данные суммируют и рисуют, чтобы понять их главные свойства: закономерности, тренды, связи. Три приёма:

- **Summarization.** Описательная статистика: среднее, медиана, стандартное отклонение.
- **Visualization.** Графики через Matplotlib и Seaborn.
- **Trends.** Поиск закономерностей и аномалий и догадки о причинах.

## Датасет и загрузка

Набор из главы 2: 2015 Flight Delays and Cancellations. Три CSV: `airlines`, `airports` и `flights` (больше 5 млн рейсов за 2015 год). Каждый файл читается запросом `CREATE TABLE ... AS SELECT * FROM read_csv_auto(...)`.

## Геоанализ

Геоанализ (`GIS`-анализ) изучает пространственные данные: где что лежит и как это связано. Пример: транспортный отдел города оптимизирует автобусные маршруты по остановкам и плотности населения. У нас координаты хранит таблица `airports`.

### Карта и маркеры

Для карт автор берёт `folium`: обёртку Python над `leaflet.js`. Она работает в Jupyter и не входит в DuckDB.

- `folium.Map` принимает центр (для США широта 47,1, долгота -101,3), размер, `zoom_start` (больше число, ближе вид) и плитки `tiles`. Плитки — это фрагменты, из которых собрана карта: `openstreetmap`, `cartodbpositron`, `cartodbdark_matter`.
- Несколько наборов плиток добавляют через `TileLayer`, переключатель даёт `LayerControl`.
- Аэропорты берут запросом (широта, долгота, название) и в цикле ставят `CircleMarker` с подсказкой. Можно взять `Marker` со значком из Font Awesome.

### Расширение spatial

Расширение `spatial` считает расстояние между точками и проверяет, лежат ли они не дальше заданного расстояния. Ставится так: `INSTALL spatial; LOAD spatial;`. Нужен столбец типа `Point`. Автор показывает два способа:

1. **Shapely в pandas.** Точка строится в Python и пишется в `WKT` (well-known text, текстовое описание геометрии), например `POINT (-75.4404 40.65236)`. Система координат `EPSG:4326`, она же `WGS 84`: обычные широта и долгота. Результат идёт в таблицу `airports_2`.
2. **Расширение spatial.** `ST_Point(longitude, latitude)` прямо в SQL, при желании с `ST_AsText`. Это проще: Python не нужен.

> **Пояснение:** `ST_Point` принимает сначала долготу, потом широту. Это обратно привычному порядку. Ошибка не даёт сбоя, точка просто окажется в другом месте.

Чтобы показать точки на карте, автор делает из DataFrame `GeoDataFrame` (таблицу GeoPandas с геометрией) через `leafmap.df_to_gdf()`. Метод `explore()` сам строит интерактивную карту.

### Поиск ближайших аэропортов

Возьмём точку в Майами. Две функции решают задачу:

- `ST_DWithin(a, b, d)`: лежат ли точки не дальше `d`. В радиусе 3 градуса автор нашёл 8 аэропортов, в радиусе 2 градуса 5.
- `ST_Distance(a, b)`: расстояние. С `ORDER BY distance LIMIT 3` получаем три ближайших. Это удобно для «топ N».

Расстояние считается в градусах, не в километрах. Для грубого поиска хватает. Для километров нужны сферические функции. Результат можно снова отдать в `GeoDataFrame`, `explore()` рисует карту, а `folium.Marker` отмечает Майами.

![Из широты и долготы получаем точку, ST_DWithin фильтрует по радиусу, а ST_Distance с LIMIT даёт ближайших](/assets/duckdb-up-and-running/ch05-nearest-airports.png)

Схема читается слева направо: точка из координат, затем верхняя ветка (радиус) или нижняя (топ N).

Короткая версия на наших данных ([полный код](https://github.com/surfalytics/dataengineer.ru/tree/main/scripts/duckdb-code/ch05_spatial.py)). Мы взяли 10 аэропортов, поэтому числа отличаются от книги:

```python
miami = "ST_Point(-80.2706578, 25.7824017)"  # точка в Майами, как в книге
for iata, city, d in duckdb.sql(f"""
    SELECT iata, city, round(ST_Distance(geom, {miami}), 3) AS dist_deg
    FROM airports ORDER BY dist_deg LIMIT 3
""").fetchall():
    print(f"  {iata}  {city:<16} {d} градуса")
```

```text

Радиус 3 градуса вокруг Майами, аэропортов: 5
Три ближайших:
  MIA  Miami            0.021 градуса
  FLL  Fort Lauderdale  0.312 градуса

```

## Описательная аналитика

Это пересказ прошлых данных, чтобы увидеть закономерности. Автор ставит шесть вопросов: сколько аэропортов в штате, сколько рейсов между аэропортами, в какие дни рейсов меньше, когда лучше лететь, у кого больше отмен и задержек.

### Аэропорты по штатам и городам

Сначала `ORDER BY STATE, CITY`. В pandas `set_index(['STATE','CITY'])` делает составной индекс, а `loc` достаёт штат или город. Затем `GROUP BY STATE` с `count(*)` даёт число аэропортов по штатам. Круговая диаграмма по всем штатам нечитаема. Автор оставляет `LIMIT 10`, потом пишет функцию `fmt()`, чтобы на секторах стояло число аэропортов, а не проценты. В конце он показывает столбчатую диаграмму: многие считают круговые вредными.

### Рейсы по маршрутам

`GROUP BY ORIGIN_AIRPORT` даёт рейсы из каждого аэропорта: из ATL вылетело 346 846, из ORD 285 884. `GROUP BY ORIGIN_AIRPORT, DESTINATION_AIRPORT` даёт пары. Самый частый маршрут — SFO и LAX. Фильтр `WHERE AIRLINE = 'DL'` оставляет Delta, у неё чаще всего LGA в ATL. Код компании в фильтре меняется на любой другой.

### Отмены

Отменённый рейс имеет `CANCELLED = 1`. Число отмен менее полезно, чем процент: `SUM(CANCELLED) * 100.0 / COUNT(*)`. У Delta высокий процент на маршрутах BOS и LGA, в целом отменено 0,44% рейсов. Но одна цифра без сравнения ничего не значит: без фильтра по компании Delta третья с конца по отменам. Чтобы вместо кодов были названия, автор делает `JOIN` с `airlines` и рисует bar и pie chart.

### Дни недели

Для каждой пары аэропортов считаем рейсы по дням недели, отмены исключаем (`WHERE CANCELLED = 0`). Для SFO и LAX в субботу и воскресенье рейсов меньше. Лучше считать долю дня в общем числе рейсов пары: два `CTE` (рейсы за день и рейсы пары за всё время), потом `JOIN` и деление.

> **Проверка данных.** У первых строк коды аэропортов числовые, а не буквенные. Так выглядит весь октябрь 2015. Автор находит их запросом с `NOT SIMILAR TO '[A-Za-z]+'` и для простоты считает отдельными кодами. Урок: перед анализом проверьте формат ключей.

### Слоты времени

Сутки делятся на четыре окна по шесть часов. `CASE WHEN` по плановому вылету ставит окно, `AVG(ARRIVAL_DELAY)` считает среднюю задержку только по задержанным рейсам. Для графика автор делает `pivot()`: день недели в индексе, слоты в столбцах. Выводы:

- вечерний слот (18:00-24:00) самый плохой;
- утренний слот в большинство дней самый короткий, кроме четверга, пятницы и воскресенья;
- меньше всего задержек: четверг или пятница очень рано утром.

### Авиакомпании: число и доля

Считать задержанные рейсы по компаниям нечестно. Если у компании два рейса в день и один задержан, доля 50%. Правильно делить задержанные на все: `CTE` с `sum(CASE WHEN ARRIVAL_DELAY > 0 ...) / count(*)` и `JOIN` с названиями. Лидер по задержкам Spirit Air Lines: 48,46% рейсов. Если заменить `>` на `<=`, получим вовремя прилетевших. Лидер Delta: 70,72%.

![Одни и те же задержки: по числу лидирует большая компания A, по доле маленькая компания C](/assets/duckdb-up-and-running/ch05-count-vs-share.png)

Мы повторили это на придуманных рейсах: 6000 штук, три компании, фиксированный `hash`. Код: `scripts/duckdb-code/ch05_flights_eda.py`. Вывод настоящий. Блок 1 показывает ловушку: по числу задержек первая Alfa Air, по доле последняя.

```python
duckdb.sql("""
    SELECT a.airline, count(*) AS flights,
           sum(CASE WHEN f.arrival_delay > 0 THEN 1 ELSE 0 END) AS delayed,
           round(100.0 * sum(CASE WHEN f.arrival_delay > 0 THEN 1 ELSE 0 END) / count(*), 1) AS delayed_pct
    FROM flights f JOIN airlines a ON f.airline = a.iata_code
    WHERE f.cancelled = 0
    GROUP BY a.airline ORDER BY delayed DESC
""")
```

## Что делает Python

SQL считает, Python показывает: `folium` для карт, `matplotlib` и `seaborn` для графиков, `.df()` и `pivot()` для pandas. Для pie chart оставляйте топ-10, для сравнения долей берите bar chart.

## Итоги главы

- `EDA` — первый взгляд на данные: суммирование, графики, поиск закономерностей.
- Три CSV грузятся в таблицы запросом `read_csv_auto()`.
- Расширение `spatial` даёт `ST_Point`, `ST_Distance`, `ST_DWithin`. `ST_Point` ждёт сначала долготу.
- `ST_DWithin` отвечает «кто в радиусе», `ST_Distance` с `LIMIT` отвечает «кто ближайший».
- Описательная аналитика — это `GROUP BY`, доли, `CASE WHEN` и `CTE`.
- Сравнивайте группы по доле: число задержек зависит от размера компании.
- Отмены исключайте явно, формат ключей проверяйте до анализа.
- Python нужен для карт и графиков. Логика остаётся в SQL.

## Ключевые термины

| Термин | Значение |
|---|---|
| `EDA` | Первый разведочный анализ данных |
| `spatial` | Расширение DuckDB для геоданных |
| `WKT` | Текстовый формат геометрии: `POINT (-80.29 25.79)` |
| `EPSG:4326` | Система координат: широта и долгота (`WGS 84`) |
| `GeoDataFrame` | Таблица GeoPandas с геометрией |
| `ST_Distance` / `ST_DWithin` | Расстояние / проверка «в пределах расстояния» |
| `CTE` | `WITH`-запрос, временная таблица внутри запроса |
| Pivot | Разворот строк в столбцы |

## Что это значит на практике

- Начинайте новый источник с `count`, `min`, `max`, числа `NULL` и проверки формата ключей.
- Сравнивайте группы по доле, а не по числу строк.
- Для «топ N ближайших» берите расстояние и `ORDER BY ... LIMIT N`. Не нужен сложный GIS.
- Исключайте отменённые и тестовые записи явно, в `WHERE`. Пишите это в комментарии.
- Тяжёлые агрегаты по большому CSV или Parquet работают локально и быстро. Хранилище для первого взгляда не нужно.
- Порядок координат проверяйте на одной известной точке. Ошибка не даёт сбоя.

## Практика в DuckDB

Запустите `duckdb` в терминале или откройте [shell.duckdb.org](https://shell.duckdb.org). Блоки идут по порядку. Данные придуманы, файлы скачивать не нужно.

### Шаг 1. Создаём аэропорты и рейсы

```sql
CREATE TABLE airports AS
SELECT * FROM (VALUES
    ('MIA', 'Майами',     'FL', 25.79, -80.29),
    ('FLL', 'Форт-Лодердейл', 'FL', 26.07, -80.15),
    ('PBI', 'Палм-Бич',   'FL', 26.68, -80.10),
    ('ORL', 'Орландо',    'FL', 28.43, -81.31),
    ('JFK', 'Нью-Йорк',   'NY', 40.64, -73.78),
    ('LAX', 'Лос-Анджелес', 'CA', 33.94, -118.41)
) t(iata, city, state, lat, lng);

CREATE TABLE airlines AS
SELECT * FROM (VALUES
    ('AA', 'Альфа Эйр'),
    ('BB', 'Бета Лайнс'),
    ('CC', 'Гамма Джет')
) t(iata, airline);

-- 600 рейсов, фиксированный шаблон без случайных чисел
CREATE TABLE flights AS
SELECT
    i AS flight_id,
    CASE i % 3 WHEN 0 THEN 'AA' WHEN 1 THEN 'BB' ELSE 'CC' END AS airline,
    ['FLL', 'JFK', 'LAX', 'MIA', 'ORL', 'PBI'][1 + i % 6] AS origin,
    ['FLL', 'JFK', 'LAX', 'MIA', 'ORL', 'PBI'][1 + (i % 6 + 1 + (i // 6) % 5) % 6] AS destination,
    1 + (i % 7) AS day_of_week,
    (i * 37) % 24 AS dep_hour,
    CASE WHEN i % 25 = 0 THEN 1 ELSE 0 END AS cancelled,
    (i * 13) % 60 - 15 AS arrival_delay
FROM range(0, 600) t(i);
```

### Шаг 3. Расстояния и ближайшие аэропорты

```sql
INSTALL spatial;
LOAD spatial;

CREATE TABLE airports_geo AS
SELECT *, ST_Point(lng, lat) AS geom FROM airports;

-- три ближайших к точке в центре Майами
SELECT iata, city,
       round(ST_Distance(geom, ST_Point(-80.19, 25.77)), 3) AS dist_deg
FROM airports_geo
ORDER BY dist_deg
LIMIT 3;
```

### Задания

**1.** Посчитайте долю отмен по каждой авиакомпании с названием, от большей к меньшей.

<details>
<summary>Решение</summary>

```sql
SELECT a.airline,
       round(sum(f.cancelled) * 100.0 / count(*), 2) AS cancelled_pct
FROM flights f
JOIN airlines a ON f.airline = a.iata
GROUP BY a.airline
ORDER BY cancelled_pct DESC;
```

Каждый 25-й рейс отменён, поэтому у всех трёх компаний доля 4%. `JOIN` нужен только для названия.
</details>

**2.** Найдите аэропорты, которые лежат не дальше 1 градуса от Майами (`-80.29, 25.79`).

<details>
<summary>Решение</summary>

```sql
SELECT iata, city
FROM airports_geo
WHERE ST_DWithin(geom, ST_Point(-80.29, 25.79), 1)
ORDER BY iata;
```

В радиус попадают MIA, FLL и PBI. Орландо дальше.
</details>

**3.** Для каждой пары (`origin`, `destination`) посчитайте долю рейсов по дням недели. Покажите первые 5 строк.

<details>
<summary>Решение</summary>

```sql
WITH per_day AS (
    SELECT origin, destination, day_of_week, count(*) AS n_day
    FROM flights WHERE cancelled = 0
    GROUP BY ALL
), per_route AS (
    SELECT origin, destination, count(*) AS n_total
    FROM flights WHERE cancelled = 0
    GROUP BY ALL
)
SELECT d.origin, d.destination, d.day_of_week,
       round(100.0 * d.n_day / r.n_total, 1) AS pct
FROM per_day d
JOIN per_route r USING (origin, destination)
ORDER BY d.origin, d.destination, d.day_of_week
LIMIT 5;
```

Два `CTE` дают числитель и знаменатель. Так же считает автор книги.
</details>
