**Главная мысль:** AWS Glue запускает задания интеграции данных с поддержкой Iceberg и может использовать Glue Data Catalog для регистрации таблиц. Для работы нужны настройки задания, каталога и прав доступа к данным.

## О чём глава

После [Dremio](/book-summaries/engineering/apache-iceberg-the-definitive-guide/07-dremio/) рассмотрим создание, чтение и запись Iceberg в Glue. Книга описывает Glue 3.0 и 4.0; совместимость библиотек и доступные операции зависят от выбранной версии среды.

![Задание AWS Glue, каталог и файлы Iceberg](/assets/apache-iceberg-the-definitive-guide/ch08-overview.png)

Схема показывает, как задание Glue использует каталог и работает с файлами таблицы.

## Настройка

В Glue Data Catalog создают базу — пространство имён для таблиц. Затем создают задание Visual ETL, выбирают источник S3, формат входных данных, версию Glue, число работников и IAM-роль. Роль должна иметь необходимые права на исходные данные, каталог и расположение таблицы.

Параметр задания `--datalake-formats` со значением `iceberg` подключает поддержку формата в описанной книге конфигурации. Через `--conf` задают расширения Spark, именованный `SparkCatalog`, `GlueCatalog`, warehouse и `S3FileIO`. Ошибки переноса строк или несовместимые версии библиотек могут привести к тому, что параметры не применятся. Версии, упомянутые книгой, отражают её время и не заменяют проверку текущей среды.

## Создание таблицы

Visual ETL может прочитать CSV из S3 как Glue `DynamicFrame`. В примере книги его преобразуют через `toDF()` в Spark DataFrame и создают временное представление `temp_df`. После этого Spark SQL выполняет `CREATE TABLE ... USING iceberg AS SELECT` и регистрирует таблицу в Glue catalog. Для выполнения нужны задание AWS Glue с настроенным Iceberg, представление `temp_df`, каталог `glue_catalog` и база `test`; выполнение ещё не проверено.

```sql
-- не запускается: нужны AWS Glue Spark, настроенный Iceberg и представление temp_df
CREATE TABLE glue_catalog.test.employee
USING iceberg
AS SELECT * FROM temp_df;
```

CTAS одновременно создаёт таблицу и записывает результат запроса. Проверьте схему входных данных и разрешения на создание до запуска: операция изменяет каталог и хранилище.

## Чтение и запись

Книга показывает чтение через `GlueContext.create_data_frame.from_catalog` с именами базы и таблицы. Для записи DataFrame она приводит `GlueContext.write_data_frame.from_catalog` и параметр `--enable-glue-datacatalog`. Поддержку конкретной комбинации API, версии Glue и Iceberg следует проверять в выбранной среде; наличие записи в каталоге само по себе не подтверждает доступ к файлам.

В Glue также можно выполнять Spark SQL через настроенную сессию. Отличайте Glue Data Catalog как сервис метаданных от самого задания Glue, которое выполняет вычисления. После обработки задание фиксирует свой жизненный цикл через `job.commit()`; это отдельное понятие от фиксации состояния таблицы Iceberg.

## Итоги главы

- Glue объединяет настройку источников и запуск заданий обработки данных.
- Iceberg требует совместимой конфигурации задания, каталога и доступа к S3.
- `DynamicFrame` можно преобразовать в DataFrame и использовать в Spark SQL.
- Создание и запись таблицы изменяют внешнее состояние и требуют проверки схемы и прав.

## Ключевые термины

| Термин | Значение |
|---|---|
| Glue Data Catalog | Сервис метаданных и пространств имён AWS Glue. |
| `DynamicFrame` | Представление данных AWS Glue для заданий интеграции. |
| CTAS | Создание таблицы из результата запроса. |

## Что это значит на практике

- Проверяйте версии Glue и Iceberg и права IAM до запуска задания.
- Контролируйте схему CSV перед CTAS и отдельно проверяйте результат фиксации таблицы.
