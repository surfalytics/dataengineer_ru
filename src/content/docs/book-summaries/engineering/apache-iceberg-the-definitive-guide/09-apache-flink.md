**Главная мысль:** Flink читает и записывает таблицы Iceberg в пакетных и потоковых заданиях. Режим выполнения, поддержка операций и настройки контрольных точек определяют фактическое поведение.

## О чём глава

После [AWS Glue](/book-summaries/engineering/apache-iceberg-the-definitive-guide/08-aws-glue/) рассмотрим настройку Flink SQL, DDL, чтение, запись и Java Table API. Книга использует Flink 1.16 и соответствующий runtime Iceberg; совместимость необходимо проверять для выбранных версий.

![Flink, каталог и таблица Iceberg](/assets/apache-iceberg-the-definitive-guide/ch09-overview.png)

Схема показывает работу Flink с каталогом и запись данных в таблицу Iceberg.

## Подготовка среды

Flink нужен совместимый Iceberg runtime JAR, а в зависимости от каталога и хранилища — дополнительные библиотеки для Hive, Hadoop или облачного ввода-вывода. Книга показывает локальный кластер и Flink SQL Client. JobManager координирует выполнение и контрольные точки, а TaskManager выполняет задачи в доступных слотах.

Для доступа к S3 нужны соответствующие зависимости и настройки. Сочетание версий Flink, Java, Iceberg и файловых библиотек важно: простое наличие JAR не гарантирует совместимость. Роль каталогов и особенности конкурентной записи рассмотрены в [главе 5](/book-summaries/engineering/apache-iceberg-the-definitive-guide/05-catalogs/).

## DDL во Flink SQL

`CREATE CATALOG` подключает реализацию Iceberg. Для встроенного Hadoop catalog задают тип и warehouse; для Hive нужны адрес Metastore и совместимые зависимости. Пользовательскую реализацию указывают через `catalog-impl`. Затем выбирают каталог, создают пространство имён и таблицу.

Пример написан на Flink SQL. Создание Hadoop catalog проверено на Flink 1.20.5 и Iceberg 1.8.1 с локальным warehouse.

```sql
-- Flink SQL: нужны Iceberg runtime и зависимости Hadoop client
CREATE CATALOG lake WITH (
  'type' = 'iceberg',
  'catalog-type' = 'hadoop',
  'warehouse' = 'file:///tmp/flink-warehouse'
);
```

Проверенный [пакетный пример Flink SQL](https://github.com/argon4ik902/dataengineer_ru/blob/8b3d5b5fc02220ff2b5a44d87991d68ad3b3eccc/scripts/iceberg-tdg-code/flink_batch.sql) выполнен на Flink 1.20.5 и Iceberg 1.8.1: создание каталога и таблицы, вставка и `SELECT` вернули строку `1, Software Engineer, Engineering, 25000.0, NA`. Скрипт использует `file:///tmp/iceberg-warehouse`; перед повторным запуском выберите пустой изолированный путь.

В этой проверке внутри Iceberg-каталога `CREATE TABLE` без свойства `WITH ('connector'='iceberg')` сработал, а вариант с этим свойством из книги был отклонён. Поэтому не переносите указанное свойство в DDL без проверки используемой конфигурации.

Путь используется только как пример: создание каталога и таблиц меняет состояние файловой системы. `CREATE TABLE` задаёт схему, `PARTITIONED BY` — поля разбиения, а `CREATE TABLE ... LIKE` может скопировать определение существующей таблицы с учётом правил версии Flink. Книга отмечает ограничение Flink DDL на преобразования скрытого разбиения для рассматриваемой версии; не переносите это утверждение на все будущие версии.

`ALTER TABLE` позволяет, например, переименовать таблицу или изменить свойства записи. `DROP TABLE` удаляет регистрацию с последствиями, зависящими от каталога и реализации. Проверяйте эти последствия и наличие ссылок на общие файлы заранее.

## Чтение

### Пакетное чтение

В режиме `batch` запрос читает конечный набор данных выбранного состояния таблицы и завершается. Движок использует каталог и метаданные для построения плана, как описано в [главе 3](/book-summaries/engineering/apache-iceberg-the-definitive-guide/03-write-and-read-queries/). Фильтры могут сократить число файлов, если поддерживаются планировщиком и статистикой.

### Потоковое чтение

В режиме `streaming` подключение может начать с выбранной точки и периодически обнаруживать новые состояния таблицы. Книга показывает hint `OPTIONS` с `streaming=true` и интервалом опроса. Интервал отвечает за частоту проверки, а не обещает мгновенную доставку после фиксации. Начальное состояние, поддерживаемые типы изменений и поведение при удалениях зависят от версии коннектора и выбранной стратегии чтения.

Не приравнивайте инкрементальное чтение новых файлов к полноценному CDC всех изменений строк. Для таблиц с обновлениями и удалениями нужно отдельно проверить возможности источника, настройку стартовой позиции и правила восстановления.

### Таблицы метаданных

Через таблицы метаданных можно исследовать историю, `snapshot`, манифесты и журнал файлов метаданных. Книга показывает обращение к ним с суффиксом `$`, например `$snapshots`. Синтаксис идентификаторов и поддержка конкретных таблиц зависят от версии Flink и коннектора. Такие представления описывают метаданные, но сами по себе не доказывают отсутствие файлов без ссылок в хранилище.

## Запись

`INSERT INTO` добавляет данные в пакетном и потоковом режиме. `INSERT OVERWRITE` заменяет выбранные данные и в описанной книге интеграции поддерживается в пакетном режиме. Перед заменой необходимо проверить область действия: запрос без ограничения может заменить всю таблицу.

### UPSERT

Книга показывает режим upsert для таблицы формата v2: он включается свойством таблицы или настройкой конкретной записи. Для сопоставления изменений нужен определённый ключ; если таблица разбита, учитывайте требования коннектора к включению исходных полей разбиения в поля равенства. `PRIMARY KEY ... NOT ENFORCED` в Flink описывает ключ для планирования, но сам Flink не проверяет его уникальность в источнике.

Потоковые записи Iceberg связаны с контрольными точками Flink. Надёжность полного pipeline зависит от настроек checkpoint, источника, восстановления состояния и корректной работы при сбоях. Нельзя вывести гарантию end-to-end только из того, что целевой формат поддерживает атомарную фиксацию.

## DataStream и Table API

В Java-примере книги создаются `StreamExecutionEnvironment` и `StreamTableEnvironment`, затем через Table API настраивается каталог, создаются база и таблица и выполняется `INSERT INTO ... SELECT`. Для сборки Maven-проекта нужны согласованные зависимости Flink и Iceberg. Собранный JAR отправляют в кластер; статус, ошибки и checkpoint отслеживают через интерфейс Flink.

Table API связывает табличные операции с потоковым вычислением, а DataStream API задаёт сам поток и его преобразования. Конфигурация endpoint и доступа к объектному хранилищу должна быть доступна выполняющим задачи узлам, а не только машине отправителя.

## Итоги главы

- Flink подключает каталог Iceberg с совместимым runtime и зависимостями хранилища.
- Пакетное чтение завершается, а потоковое отслеживает новые состояния согласно настройкам.
- Инкрементальное чтение не следует автоматически считать полным CDC.
- Поддержка overwrite и upsert зависит от режима, версии и схемы таблицы.
- Гарантии восстановления зависят от всего pipeline и контрольных точек.

## Ключевые термины

| Термин | Значение |
|---|---|
| JobManager | Компонент Flink, координирующий задания и контрольные точки. |
| TaskManager | Компонент Flink, выполняющий назначенные задачи. |
| `UPSERT` | Режим записи изменений по заданному ключу. |
| `Checkpoint` | Контрольная точка состояния для восстановления задания. |

## Что это значит на практике

- Проверяйте поддерживаемые типы изменений при потоковом чтении таблицы.
- Настраивайте и проверяйте восстановление checkpoint вместе с целевым каталогом.
- Проверяйте область замены перед пакетным overwrite.
