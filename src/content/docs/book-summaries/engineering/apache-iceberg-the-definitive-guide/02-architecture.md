**Главная мысль:** Таблица Iceberg состоит из файлов данных и дерева метаданных. Каталог указывает на текущий файл метаданных, а тот помогает найти нужное состояние таблицы и его файлы.

## О чём глава

В [главе 1](/book-summaries/engineering/apache-iceberg-the-definitive-guide/01-introduction/) мы рассмотрели роль открытого формата таблиц. Теперь разберём слои данных, метаданных и каталога и то, как они обеспечивают чтение и изменение таблицы.

![Слои таблицы Iceberg: каталог, метаданные и данные](/assets/apache-iceberg-the-definitive-guide/ch02-overview.png)

Схема показывает путь от каталога к файлу метаданных таблицы, списку манифестов, файлам манифестов и файлам данных и удалений. Метаданные связывают логическое состояние таблицы с физическими файлами.

## Слой данных

Здесь хранятся строки и сведения об удалениях. Файлы обычно размещают в HDFS или объектном хранилище. Большинство запросов в итоге читает данные, хотя иногда ответ можно получить из метаданных, если движок поддерживает такую оптимизацию.

### Файлы данных

Iceberg отделяет формат таблиц от формата файла. В книге рассматриваются Parquet, ORC и Avro. Разные форматы подходят разным нагрузкам, но возможность использовать новый формат зависит от поддержки спецификацией и конкретным движком; произвольный формат нельзя подключить автоматически.

Parquet часто выбирают для аналитики благодаря столбцовому хранению. Файл состоит из групп строк, внутри которых значения каждого столбца размещены вместе и разбиты на страницы. Движок может читать нужные столбцы и использовать параллелизм. Статистика групп строк, например границы значений, помогает пропустить части файла, которые не подходят под условие. Эффект зависит от расположения данных и возможностей читателя.

### Файлы удалений

Файлы данных обычно рассматривают как неизменяемые. При `copy-on-write` (COW) изменение создаёт новый файл с обновлёнными строками. При `merge-on-read` (MOR) сведения об удалениях записываются отдельно и применяются при чтении; обновлённые значения также требуют записи данных. Книга относит файлы удалений к версии формата Iceberg v2 и предупреждает, что поддержку следует проверять у движка.

Удаление по позиции задаёт путь к файлу данных и позицию строки внутри него, начиная с нуля. Оно точно указывает на запись, но зависит от конкретного физического файла. Удаление по значениям полей задаёт значения одного или нескольких полей; оно может удалить несколько подходящих строк, если значения не уникальны. Ключ в таком условии не создаёт автоматически ограничение уникальности.

Порядковые номера предотвращают применение старого удаления по значениям к более поздней вставке. Например, файл данных получил номер 1, файл удалений — 2, а новая запись с тем же ключом попала в файл с номером 3. Удаление относится к подходящим старым данным, но не к последующей вставке. На применимость также влияют правила спецификации и разбиения.

## Слой метаданных

Дерево метаданных описывает состав и историю таблицы. Движок начинает с файла метаданных таблицы и постепенно переходит к более подробным сведениям. Метаданные не требуют открывать каждый файл данных только ради его статистики.

### Файлы манифестов

Файл манифеста перечисляет часть файлов данных или файлов удалений. Он содержит пути, принадлежность к разделам, число записей и доступные границы значений столбцов. Файлы данных и файлы удалений перечисляются в отдельных файлах манифестов. Их формат — Avro, хотя для просмотра содержимое можно представить как JSON.

Поскольку записывающий движок уже обрабатывает строки, он может собрать статистику при записи. При чтении сведения по нескольким файлам доступны из одного манифеста: движок исключает заведомо неподходящие файлы до обращения к ним. Это особенно полезно, когда файлов много, но наличие статистики и точность отсечения зависят от записи и типа данных.

### Список манифестов

Для каждого `snapshot` — зафиксированного состояния данных — список манифестов перечисляет файлы манифестов этого состояния. Запись содержит путь, размер, идентификатор спецификации разбиения, тип содержимого и порядковые номера. В ней также могут быть счётчики добавленных, существующих и удалённых файлов и строк, а также сводки значений полей разбиения.

Сводка может содержать границы и признаки наличия `null` или `NaN`. Она помогает не открывать целый файл манифеста, когда известно, что содержащиеся в нём разделы не подходят запросу. Список манифестов тоже хранится в Avro; состояние таблицы при этом определяется не одним только списком, а связанным с ним `snapshot` в метаданных.

### Файл метаданных таблицы

Файл метаданных хранит идентификатор и расположение таблицы, версию формата, схемы, спецификации разбиения, порядки сортировки, свойства и сведения о `snapshot`. Идентификаторы схем и полей позволяют различать их при изменениях. Также могут храниться история метаданных и именованные ссылки на состояния.

При фиксации изменения создаётся новая версия метаданных, а каталог атомарно переключает текущую ссылку. Старый файл при этом не изменяется на месте. Две одновременно подготовленные записи должны согласовать фиксацию: подготовить файл ещё не значит опубликовать его как текущее состояние. Файл данных, нужный сохранённому `snapshot`, нельзя удалять лишь потому, что он не входит в текущую версию.

### Файлы Puffin

Puffin предназначен для дополнительной статистики и индексов. Он хранит блоки данных и сведения об их интерпретации. В книге в качестве поддерживаемой на момент написания структуры указан Theta sketch из Apache DataSketches: он позволяет приблизительно оценить число различных значений, не выполняя каждый раз точный подсчёт всех строк.

Приблизительный результат подходит не каждой задаче, а использование такой статистики зависит от поддержки движка. Границы в манифестах, статистика Parquet и дополнительные статистические структуры решают разные задачи и не гарантируют одинаковой оптимизации.

## Каталог

Каталог Iceberg связывает имя таблицы с текущими метаданными и участвует в атомарной фиксации изменений. Реализации различаются: например, Hive Metastore и Nessie хранят ссылки в своих записях, а файловый Hadoop catalog использует собственные правила обнаружения метаданных. Не следует считать вспомогательный файл `version-hint.text` универсальным механизмом атомарной фиксации или полагаться на него как на единственный источник истины.

Каталог решает задачу обнаружения и согласования текущей версии; файлы данных и метаданных при этом обычно лежат отдельно в хранилище. Каталог, движок и само хранилище должны поддерживать выбранный способ конкурентной работы.

## Практика: отсечение по границам

Это самостоятельная модель планирования на Python 3, а не запуск Iceberg. Она проверяет, пересекается ли диапазон значений файла с диапазоном фильтра. Если статистики нет или она недостаточно точна, реальный движок не может безопасно исключить файл только на её основе.

```python
files = [("a.parquet", 1, 9), ("b.parquet", 10, 19), ("c.parquet", 20, 29)]
low, high = 12, 22
for name, minimum, maximum in files:
    if minimum <= high and maximum >= low:
        print(name)
```

Результат запуска:

```text
b.parquet
c.parquet
```

Второй и третий файлы лишь *могут* содержать подходящие строки: точный фильтр всё равно применяется при чтении. Полный [пример](https://github.com/argon4ik902/dataengineer_ru/blob/8b3d5b5fc02220ff2b5a44d87991d68ad3b3eccc/scripts/iceberg-tdg-code/ch02_pruning.py) запускается через `python3 -I`.

## Итоги главы

- Файлы данных хранят строки, а файлы удалений задают исключения при чтении.
- Манифесты перечисляют файлы и статистику, а список манифестов связывает их с состоянием таблицы.
- Файл метаданных описывает схемы, разбиение и историю состояний.
- Каталог хранит текущую ссылку и обеспечивает её согласованное обновление.
- Статистика помогает отсекать данные, но её использование зависит от движка.

## Ключевые термины

| Термин | Значение |
|---|---|
| Файл данных | Файл со строками таблицы. |
| Файл удалений | Сведения о строках, исключаемых при чтении. |
| Файл манифеста | Метаданные о наборе файлов данных или удалений. |
| Список манифестов | Список манифестов одного `snapshot`. |
| Каталог Iceberg | Компонент, связывающий имя таблицы с текущими метаданными. |

## Что это значит на практике

- Проверяйте поддержку типа файлов удалений всеми читателями таблицы.
- Сохраняйте файлы, пока на них ссылаются нужные исторические состояния.
- Оценивайте эффективность отсечения по плану и метрикам конкретного движка.
