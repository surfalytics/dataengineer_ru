**Главная мысль:** для первой отладки достаточно запустить точку входа приложения в IDE. Flink может разместить координатор и исполнителей в той же JVM, где работает отладчик.

## О чём глава

В главе «[Архитектура Apache Flink](/book-summaries/engineering/stream-processing-with-apache-flink/03-flink-architecture/)» задачи распределялись по процессам кластера. При разработке важнее быстро увидеть, какая запись пришла в функцию и почему она выдала неожиданный результат. Авторы показывают этот путь на знакомом приложении с датчиками, а затем собирают самостоятельный проект.

## Необходимое ПО

Для примеров нужны JDK, Maven 3.x и IDE с поддержкой выбранного языка. В книге используется Java 8. Одной среды исполнения JRE мало, поскольку она не содержит компилятора. Авторы приводят основной код на Scala и предлагают отдельный репозиторий с примерами на Java. Для Scala в IntelliJ IDEA понадобится соответствующий плагин.

## Запуск и отладка в IDE

### Импорт и запуск проекта

Загрузите проект примеров и откройте его в IDE как Maven-проект через файл `pom.xml`. Тогда IDE сама восстановит структуру модулей и зависимости. Проверьте выбранный JDK и дайте Maven завершить загрузку библиотек. После импорта найдите метод `main` в `AverageSensorReadings` из первой главы.

При запуске `main` сначала описывает граф потока. Вызов `execute()` передаёт его среде исполнения. В локальном режиме необходимые компоненты Flink запускаются внутри JVM программы, а результаты печати появляются в консоли IDE. Генератор продолжает выдавать новые показания, поэтому процесс останавливают вручную.

### Точка останова

Установите точку останова внутри функции преобразования записи и запустите приложение в режиме отладки. Когда придёт очередное измерение, можно изучить идентификатор датчика, время и температуру. Точка останова в строке, которая добавляет преобразование к графу, покажет другой момент работы. В этой строке клиент только собирает граф, поэтому конкретного входного измерения ещё нет.

## Новый проект Maven

Архетип задаёт структуру проекта, версии и настройки упаковки. Для примера издания укажите версию архетипа явно. После генерации перейдите в созданный каталог и соберите JAR.

```bash
mvn -B org.apache.maven.plugins:maven-archetype-plugin:3.3.1:generate \
  -DarchetypeGroupId=org.apache.flink -DarchetypeArtifactId=flink-quickstart-scala \
  -DarchetypeVersion=1.7.1 -DgroupId=ru.dataengineer -DartifactId=flink-scala-project \
  -Dversion=0.1 -Dpackage=ru.dataengineer -DinteractiveMode=false
cd flink-scala-project
mvn clean package -Dscala.binary.version=2.12 -Dscala.version=2.12.8
ls target/flink-scala-project-0.1.jar
```

Результат команды после успешной сборки на Java 8:

```text
target/flink-scala-project-0.1.jar
```

> **Пояснение:** в проверенном архетипе 1.7.1 по умолчанию заданы Scala 2.11.12 и бинарная версия 2.11, а в дистрибутиве первой главы используется ветка 2.12. Поэтому при сборке выше обе версии указаны явно. Профиль `build-jar` из печатной команды отсутствует в сгенерированном POM. Упаковка привязана к фазе `package`.

## Итоги главы

- Совместимость проекта определяют версии JDK, Scala и Flink.

- Локальная среда позволяет отлаживать код обработки обычным отладчиком JVM.
- При непрерывном входе программа не завершится сама.

## Что это значит на практике

Сначала воспроизведите ошибку на небольшом известном входе и поставьте точку останова в пользовательской функции. Когда функция вернёт ожидаемый результат, соберите тот же код в JAR для запуска в кластере.
