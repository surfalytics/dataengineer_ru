## О чём книга простыми словами

Датчик прислал три измерения. Чтобы показать среднюю температуру за пять секунд, приложению нужно знать, какому прибору принадлежит запись и в какое окно входит её время. Пока результат считается, ещё одно измерение может задержаться в сети. А когда значение уже ушло в базу, исполнитель может упасть и перечитать те же записи. Каждая из этих ситуаций меняет требования к программе.

Авторы разбирают их последовательно. Журнал позволяет перечитать вход, Flink хранит промежуточные результаты по ключам, а согласованные снимки связывают накопленное состояние с позицией чтения. Последняя часть книги показывает, как сохранить эти свойства при обновлении кода, изменении параллелизма и отказе машины.

## Что нужно знать заранее

- Представлять, как запись попадает из приложения в очередь или таблицу.
- Уметь прочитать небольшую Java- или Scala-функцию. Для концептуальных глав достаточно понимать вход функции и её результат.
- Для практики с командной строкой пригодится знакомство с JVM, Maven и запуском процессов Linux.

## Зачем читать

- Разобраться, какое время определяет результат, когда события приходят с опозданием.
- Выбрать между окном, нарастающим агрегатом и обработчиком с таймером.
- Проверить, что после сбоя повторное чтение не задвоит результат во внешней системе.
- Спланировать перенос задания на другой кластер с сохранением истории ключей.
- По метрикам отличить медленный приёмник от задержки записи снимка.

## Как читать

Если вы впервые работаете с потоками, начните с первых трёх глав и только затем запускайте пример. Аналитику, который определяет метрику по времени события, особенно пригодятся главы 2 и 6. Для разработки DataStream-приложения прочтите главы 4–8, а при подготовке к дежурству свяжите главы 3, 9 и 10. Руководителю проекта главы 1 и 8 помогут обсудить допустимую задержку и смысл обещания об однократной обработке.

## Как работать с практикой

Издание описывает DataStream API 1.7. Для примеров использованы Flink 1.7.1, Java 8 и дистрибутив для Scala 2.12. Пример авторов собран с Scala 2.12.8. У страниц с кодом указан фактический вывод. Восьмая глава включает отдельный опыт с повторной записью в DuckDB и проверку Flink-приёмника в Derby. Десятая глава восстанавливает задание из планового снимка и проверяет результат через REST.
