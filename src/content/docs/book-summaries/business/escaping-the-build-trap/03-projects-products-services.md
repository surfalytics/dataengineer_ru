**Главная мысль:** продукт нужно растить долго, а проект заканчивается в срок. Если думать только проектами, компания теряет стратегию и попадает в build trap.

![Сравнение проекта и продукта: проект имеет срок и заканчивается, продукт растёт через серию проектов к нужному результату](/assets/escaping-the-build-trap/ch03-project-vs-product.png)

## Проектное мышление

Многие компании работают так:

1. Определяют объём работ.
2. Ставят дедлайны и вехи.
3. Команда делает работу.
4. Проект закрыт. Переходят к следующему.

У проектов бывают свои метрики результата. Но над ними нет общей стратегии.

Есть фреймворки и сертификаты по управлению проектами: PRINCE2, Project Management Institute, PMBOK. Компании в build trap часто путают их с product management.

## Продукт

Продукт — это носитель ценности. Он даёт ценность клиенту снова и снова. Компании не нужно каждый раз делать что-то новое.

- Это может быть железо, софт, товар в упаковке.
- Человек не нужен, чтобы пользователь получил ценность.
- Примеры из книги: Microsoft Excel, детское питание, Tinder, iPhone.

## Сервис

Сервис даёт ценность в основном через труд людей.

- Примеры: агентство, которое рисует логотипы; бухгалтер, который делает налоговую декларацию.
- Сервис можно «упаковать как продукт»: одна услуга по одной цене для всех. Но выполнять её всё равно должны люди.
- Сервис можно автоматизировать. Для этого делают софт, который выполняет услугу.

Часто продукты и сервисы работают вместе. Пример: on-premises софт. Компания ставит софт на компьютеры клиента. Команда сервиса делает установку и настройку. Такие продукты и сервисы надо улучшать вместе, как одну систему.

## Проект

Проект — это отдельный объём работ с конкретной целью.

| | Проект | Продукт |
|---|---|---|
| Срок | Есть дедлайн и вехи | Живёт долго |
| Результат | Конкретный `output` | `Outcome` для клиента и бизнеса |
| Когда закончен | Цель достигнута | Когда растёт до зрелости, работа продолжается |
| Роль | Часть развития продукта | Цель, ради которой делают проекты |

- Проекты нужны. Это важная часть разработки продукта.
- Вредно думать **только** проектами.
- Новая фича — это проект. Но после её выпуска работа может быть не закончена.
- Нужно запускать новые проекты, пока продукт не достигнет нужного результата.

## Зачем нужен product management

- Компании нужна дисциплина: организовать работу вокруг продуктов, а не проектов.
- Компании, которые улучшают продукты ради ценности, называются **product-led**.
- Они растут через продукты, масштабируются через софт и улучшают продукт, пока не получат нужный `outcome`.

## Ключевые термины

| Термин | Значение |
|---|---|
| Project | Отдельный объём работ с целью, сроком и `output` |
| Product | Носитель ценности, который даёт её снова и снова без участия людей |
| Service | Ценность через труд людей |
| Productized service | Одинаковая услуга по одной цене для всех клиентов |
| Product-led organization | Компания, которая растёт через успех продуктов |

## Что это значит на практике

- Витрина данных или dbt-проект — это продукт, а не проект. После запуска его нужно поддерживать, улучшать и измерять.
- «Миграция в новый warehouse» — это проект. Спросите, какой продуктовый результат он должен дать: быстрее отчёты, дешевле запросы, новые данные для аналитиков.
- Если команда данных работает как сервис (ручные выгрузки по запросу), ищите повторяющиеся запросы. Их можно превратить в продукт: self-service витрину или дашборд.
- Не закрывайте работу словом «готово» после релиза пайплайна. Запланируйте следующую итерацию по обратной связи пользователей.
