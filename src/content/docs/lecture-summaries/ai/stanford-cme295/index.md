## О чём курс простыми словами

`LLM` пишут код, отвечают на вопросы и работают как агенты (`agent`). Но снаружи они выглядят как чёрный ящик. Курс открывает этот ящик. У него две цели: понять, как работает трансформер и как он связан с `LLM`, и узнать, как `LLM` обучают и применяют в разных задачах.

Главная модель в голове такая. Текст режут на токены, токены превращают в векторы, а трансформер с помощью внимания (`attention`) уточняет каждый вектор по всем остальным токенам. То есть `LLM` — это большая модель такого вида, обученная на огромном объёме текста. Дальше модель дообучают, в том числе с помощью `RL` (обучения с подкреплением), запускают на многих GPU и встраивают в агентов. В конце нужно понять, насколько хорошо она работает.

Лекторы говорят, что аудитория курса широкая. Например, он полезен будущим исследователям, тем, кто делает свой проект с coding agents, и всем, кому нужна базовая AI-грамотность: понимать, в чём модели сильны и где ошибаются.

## Что нужно знать заранее

- Линейная алгебра на базовом уровне: что такое матрица и как её умножать.
- Основы машинного обучения: функция потерь (`loss`), нейросеть, `embedding` (векторное представление). Эти идеи объясняют и на лекциях, но лучше знать их заранее.
- Python для задач из раздела «Практика»: [Базовый минимум Python](/practice/python/).
- Для мягкого входа в тему: конспект книги [Machines that Think](/book-summaries/ai/machines-that-think/).

## Зачем проходить

- Понять, что происходит внутри `LLM`, вместо того чтобы верить ей на слово.
- Читать статьи и документацию моделей: за год в этой области появляются десятки сокращений, и курс связывает их с понятиями.
- Понимать, откуда берутся цена и скорость ответа модели: они зависят от числа токенов и устройства внимания.
- Знать этапы обучения `LLM`, от предобучения (`pre-training`) до `RL`.
- Строить свои системы на `LLM`: агентов, поиск документов (`retrieval`), оценку качества.
- Говорить на одном языке с ML-инженерами в своей команде.

## Главные идеи

| Идея | Лекция |
|---|---|
| Модель работает с числами: текст режут на токены, а токены превращают в векторы | [1. Токены, внимание и трансформер](/lecture-summaries/ai/stanford-cme295/01-transformers/) |
| Самовнимание (`self-attention`) строит представление токена из всех токенов текста через `query` (запрос), `key` (ключ) и `value` (значение) | [1. Токены, внимание и трансформер](/lecture-summaries/ai/stanford-cme295/01-transformers/) |
| Трансформер победил `RNN` (рекуррентные нейросети), потому что хорошо масштабируется: больше данных и вычислений дают лучшее качество | [1. Токены, внимание и трансформер](/lecture-summaries/ai/stanford-cme295/01-transformers/) |
| Современная `LLM` — это трансформер только с декодером (`decoder`). Качество предсказуемо растёт с размером модели, данными и вычислениями | [2. Большие языковые модели](/lecture-summaries/ai/stanford-cme295/02-large-language-models/) |
| `MoE` (смесь экспертов) увеличивает модель, но для каждого токена работает только часть экспертов (`expert`), поэтому проход почти не дорожает | [2. Большие языковые модели](/lecture-summaries/ai/stanford-cme295/02-large-language-models/) |
| Ответ модели выбирают токен за токеном. Температура (`temperature`), `top-k` и `top-p` задают, насколько этот выбор случаен | [2. Большие языковые модели](/lecture-summaries/ai/stanford-cme295/02-large-language-models/) |
| Модель учится по этапам: предобучение (`pre-training`) даёт знания, `SFT` (дообучение на парах «запрос — ответ») учит отвечать, обучение по предпочтениям задаёт тон | [3. Обучение LLM](/lecture-summaries/ai/stanford-cme295/03-llm-training/) |
| `LoRA` дообучает две малые матрицы вместо всех весов модели | [3. Обучение LLM](/lecture-summaries/ai/stanford-cme295/03-llm-training/) |
| `RL` (обучение с подкреплением) сдвигает модель к ответам с высоким вознаграждением (`reward`). `PPO` и `GRPO` по-разному делают этот сдвиг устойчивым | [4. Обучение с подкреплением для LLM](/lecture-summaries/ai/stanford-cme295/04-reinforcement-learning/) |
| `KL`-штраф держит модель рядом с исходной, чтобы обучение не испортило то, что уже работает | [4. Обучение с подкреплением для LLM](/lecture-summaries/ai/stanford-cme295/04-reinforcement-learning/) |
| Скорость часто упирается не в вычисления, а в память `GPU`. FlashAttention и KV-кэш (`KV cache`) уменьшают число обращений к медленной памяти | [5. Системы LLM: обучение и запуск моделей](/lecture-summaries/ai/stanford-cme295/05-llm-systems/) |
| Большую модель делят между многими `GPU`: по данным, по слоям, по токенам и по экспертам | [5. Системы LLM: обучение и запуск моделей](/lecture-summaries/ai/stanford-cme295/05-llm-systems/) |
| `RAG` (генерация ответа с поиском документов) добавляет модели свежие знания, и главное в нём — качество поиска | [6. AI-агенты](/lecture-summaries/ai/stanford-cme295/06-ai-agents/) |
| Агент — это модель плюс обвязка: вызов инструментов (`tool calling`), цикл ReAct, память и сжатие контекста (`context compaction`) | [6. AI-агенты](/lecture-summaries/ai/stanford-cme295/06-ai-agents/) |
| У качества `LLM` нет одной меры: его делят на критерии и проверяют людьми, тестами, LLM-судьёй (`LLM-as-a-judge`) и наборами задач | [7. Оценка LLM](/lecture-summaries/ai/stanford-cme295/07-llm-evaluation/) |
| Если долго улучшать одну метрику, она перестаёт отражать качество (закон Гудхарта). Поэтому модель выбирают по границе Парето (Pareto frontier): качество против цены | [7. Оценка LLM](/lecture-summaries/ai/stanford-cme295/07-llm-evaluation/) |
