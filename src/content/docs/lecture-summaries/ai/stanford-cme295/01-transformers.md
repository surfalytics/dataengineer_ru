**Главная мысль:** модель не читает текст, она работает с числами. Поэтому текст режут на токены, каждому токену дают `embedding` (векторное представление), а трансформер (`transformer`) с помощью внимания (`attention`) делает этот вектор зависимым от всех остальных токенов. Эта архитектура хорошо масштабируется, и на ней построены все современные `LLM` (большие языковые модели).

## Токенизация

▶ [16:56](https://youtu.be/114i2Kz-LZA?t=1016)

Токенизация — это разбиение текста на неделимые части, токены. Модель понимает только числа, поэтому каждому токену потом сопоставят вектор. Чтобы разбивать текст, нужен словарь (`vocabulary`): список всех токенов, которые разрешено использовать. Число токенов в тексте называют длиной последовательности (`sequence length`). Её определяет выбранный словарь: чем длиннее куски текста в нём, тем короче последовательность.

### Три способа разбить текст

Возьмём фразу «A cute teddy bear is reading».

| Способ | Что такое токен | Плюсы | Минусы |
|---|---|---|---|
| По словам | Слово, граница — пробел | Просто, понятно, что означает токен | Словарь огромный из-за форм слов. `bear` и `bears` получают несвязанные векторы. Незнакомое слово — это слово вне словаря (`out-of-vocabulary`) |
| По символам | Одна буква | Малый словарь, нет незнакомых слов, устойчиво к опечаткам и регистру | Последовательность очень длинная, а сложность модели растёт с её длиной. Вектор одной буквы почти ничего не значит |
| По подсловам (`subword tokenization`) | Частый кусок слова: `read` и `ing` | Общий корень у `bear` и `bears`, токены выучены по данным | Токенизатор (`tokenizer`) надо сначала обучить на корпусе. Результат зависит от корпуса, на котором учили токенизатор |

Подслова — компромисс, поэтому сегодня их используют почти все модели.

### BPE

`BPE` (Byte Pair Encoding) — это способ построить словарь подслов из самых частых пар. Алгоритм простой:

1. Берём начальный словарь, например все буквы.
2. Считаем, какая пара соседних токенов чаще всего встречается в корпусе.
3. Добавляем в словарь новый токен: слияние этой пары.
4. Повторяем, пока словарь не достигнет нужного размера.

> **Пояснение:** это похоже на `GROUP BY` по соседним парам с `ORDER BY count DESC LIMIT 1`, который запускают снова и снова, пока таблица токенов не вырастет до нужного размера.

Частые куски становятся одним токеном, поэтому текст получается короче. Пример на корпусе из четырёх слов с частотами: незнакомое слово `lowest` разбивается на известные куски и не становится словом вне словаря.

<details>
<summary>Код: lec01_bpe.py</summary>

```python
"""BPE на маленьком корпусе: словарь растёт слиянием самой частой пары."""
from collections import Counter

# Слова корпуса и сколько раз каждое встречается
corpus = {"low": 5, "lower": 2, "newest": 6, "widest": 3}

# Начинаем с отдельных букв
words = {w: list(w) for w in corpus}
vocab = sorted({ch for w in corpus for ch in w})
print("Начальный словарь:", vocab)


def count_pairs():
    pairs = Counter()
    for w, freq in corpus.items():
        parts = words[w]
        for a, b in zip(parts, parts[1:]):
            pairs[(a, b)] += freq
    return pairs


def merge(pair):
    new = pair[0] + pair[1]
    for w, parts in words.items():
        out, i = [], 0
        while i < len(parts):
            if i + 1 < len(parts) and (parts[i], parts[i + 1]) == pair:
                out.append(new)
                i += 2
            else:
                out.append(parts[i])
                i += 1
        words[w] = out
    return new


merges = []
for step in range(1, 9):
    pairs = count_pairs()
    # при равенстве берём пару, которая раньше по алфавиту
    best = min(pairs, key=lambda p: (-pairs[p], p))
    new = merge(best)
    merges.append(best)
    vocab.append(new)
    print(f"Шаг {step}: пара {best} встречается {pairs[best]} раз -> токен '{new}'")

print("Слова после слияний:", words)


def tokenize(word):
    """Применяем выученные слияния по порядку к новому слову."""
    parts = list(word)
    for pair in merges:
        i = 0
        while i + 1 < len(parts):
            if (parts[i], parts[i + 1]) == pair:
                parts[i:i + 2] = [pair[0] + pair[1]]
            else:
                i += 1
    return parts


print("Новое слово 'lowest':", tokenize("lowest"))
print("Размер словаря:", len(vocab))
```

Типичная ошибка — считать токен словом: редкое слово занимает несколько токенов. Для работы на нескольких языках токенизатор учат на корпусе всех этих языков.

**Вопрос из зала:** какой словарь у современных `LLM`? Ответ лектора: порядка сотен тысяч токенов, например 200 000, на нескольких языках.

### Служебные токены

Кроме кусков текста, в словаре есть служебные токены (`special tokens`):

| Токен | Зачем нужен |
|---|---|
| `UNK` (unknown) | Заменяет кусок, которого нет в словаре. Если слово «teddy» написали с опечаткой, получится `UNK` и `bear` |
| `BOS` (beginning of sequence) | Начало последовательности. С него модель начинает генерацию |
| `EOS` (end of sequence) | Модель выдаёт его, когда закончила |
| `PAD` (padding) | Дополняет короткие последовательности до одной длины: железо быстрее считает матрицы одного размера |

Список неполный, а обозначения в разных моделях различаются, например `<|end_of_text|>`. Для чатов есть и токены ролей user и assistant.

## Как получить вектор токена: Word2vec

▶ [37:27](https://youtu.be/114i2Kz-LZA?t=2247)

Самый простой вектор — `one-hot` (вектор с одной единицей). Его длина равна размеру словаря: единица стоит на месте токена, а остальное нули.

> **Пояснение:** `one-hot` — это как dummy-колонки для категориального признака в таблице.

Проблема в том, что любые два таких вектора ортогональны. Скалярное произведение у всех пар нулевое, и вектор не говорит, что `teddy bear` ближе к `soft`, чем к `book`. Нам нужен `embedding`: плотный вектор, в котором близкие по смыслу токены лежат рядом.

`Word2vec` (около 2013 года) получает такие векторы через прокси-задачу (`proxy task`). Это задача, которую решают не ради неё самой, а ради побочного результата. Есть два варианта:

- `CBOW` (continuous bag of words): угадать слово по словам вокруг;
- `skip-gram`: угадать соседей по слову.

Пример: «A cute teddy bear is reading», прокси-задача — угадать следующее слово, словарь из шести токенов (`V = 6`).

1. `A` — первый токен, его `one-hot` вектор `[1,0,0,0,0,0]`.
2. Умножение на матрицу даёт скрытый вектор размера `d`. У лектора `d = 2`, например `[0.2, 0.9]`. `d` выбираем сами, и он намного меньше `V`.
3. Вторая матрица возвращает вектор размера `V`, и `softmax` (функция, которая превращает числа в веса с суммой, равной единице) делает из него вероятности.
4. Верный ответ — `cute`, то есть `[0,1,0,0,0,0]`. Функция потерь (`loss`) здесь — кросс-энтропия (`cross-entropy loss`). Она штрафует низкую вероятность этого токена, и веса обновляются.

Так проходят по всему корпусу. Скрытый вектор в середине сети получается осмысленным: похожие токены близки, а соотношения сохраняются (Paris относится к France так же, как Berlin к Germany).

Слабые места метода:

- у слова один вектор в любом предложении, а у «bank» (берег или банк) смыслов несколько;
- порядок слов не учитывается: «ребёнок обнимает мишку» и «мишка обнимает ребёнка» дают одни и те же векторы;
- размер векторов и матриц растёт вместе со словарём. Но это ограничение любого метода: размер словаря задаёт токенизатор.

## RNN и LSTM

▶ [48:26](https://youtu.be/114i2Kz-LZA?t=2906)

`RNN` решает проблему порядка. Она читает токены по одному и несёт скрытое состояние (`hidden state`) — вектор, в котором сжат смысл прочитанного. Для каждого нового токена используются и его `embedding`, и скрытое состояние, поэтому модель видит порядок слов. `RNN` применяли для классификации (тональность) и разметки токенов (существительное или глагол).

Слабые места:

- одного вектора мало для длинного текста: информация о далёком прошлом теряется, а с ней и дальние зависимости (`long-range dependency`). В «My teddy bear is so cute. It is 3 feet tall» слово «It» относится к началу;
- причина глубже: затухающие градиенты (`vanishing gradient`) при обратном распространении ошибки (`backpropagation`);
- токены надо читать строго по одному, поэтому обучение очень медленное.

`LSTM` (long short-term memory) добавляет второй вектор, который хранит информацию дольше: состояние ячейки (`cell state`). Это помогло, но не решило проблему. Решением оказалось внимание.

## Внимание и самовнимание

▶ [55:18](https://youtu.be/114i2Kz-LZA?t=3318)

Идея внимания (`attention`): не полагаться только на скрытое состояние, а дать модели прямые связи с прошлыми токенами. Она сама учится, какие токены важны. Пример: при переводе на французский следующее слово зависит от конкретного английского слова. С `RNN` к нему можно добраться лишь через скрытое состояние, а с вниманием — напрямую.

▶ [57:16](https://youtu.be/114i2Kz-LZA?t=3436)

Самовнимание (`self-attention`) — это внимание, где токены смотрят на токены того же текста. Представление токена выражают как функцию от всех остальных токенов последовательности. Это основа статьи 2017 года.

Есть и цена. Если токен связан со всеми, модель теряет порядок слов. Как это исправить, видно ниже, в разделе про вход.

## Query, key, value

▶ [59:54](https://youtu.be/114i2Kz-LZA?t=3594)

У каждого токена есть три вектора:

| Вектор | Роль |
|---|---|
| `query` | Что этот токен ищет. Ему нужны токены, полезные для его представления |
| `key` | Чем помечен каждый токен. С ним сравнивают `query` |
| `value` | Что токен отдаёт, когда его выбрали |

> **Пояснение:** это похоже на `JOIN`. `query` — то, что ищем, `key` — ключ соединения, `value` — данные в строке. Но совпадение «мягкое»: вместо точного равенства каждая строка получает вес.

Как это работает. Для `teddy bear` берём его `query`. Считаем скалярное произведение с `key` каждого токена: чем больше, тем больше токен подходит. `Cute` хорошо описывает мишку, поэтому его вес будет большим. Веса нормируем так, чтобы сумма была равна 1. Новое представление мишки — сумма `value` всех токенов с этими весами.

`Q`, `K`, `V` получают умножением входного вектора на три обучаемые матрицы проекции: `Wq`, `Wk`, `Wv`.

![Самовнимание для одного токена: проекции Wq, Wk, Wv дают query, key и value, softmax даёт веса, сумма value с весами даёт новое представление](/assets/stanford-cme295/lec01-qkv.png)

Диаграмма читается слева направо: из `embedding` получаем три вектора, `query` и `key` дают веса, а веса применяются к `value`.

Для всех токенов сразу это одна формула. Лектор говорит, что она будет встречаться часто и может пригодиться на экзамене:

```text
Attention(Q, K, V) = softmax(Q · Kᵀ / √d_k) · V
```

Разберём символы:

- `Q`, `K`, `V` — матрицы, в которых по одной строке на токен;
- `Q · Kᵀ` — матрица `n × n` скалярных произведений: сходство каждого `query` с каждым `key`;
- `√d_k` — масштаб, о нём ниже, в сквозном примере;
- `softmax` — превращает каждую строку в веса с суммой 1;
- умножение на `V` — взвешенная сумма `value` для каждого токена.

То же на четырёх токенах. Веса матриц случайные, поэтому смысла в таблице нет. Важно другое: строки дают в сумме 1, а каузальная маска (`causal mask`) обнуляет веса на будущие токены. Эта маска не даёт токену смотреть на следующие токены, подробнее о ней в разделе про декодер.

<details>
<summary>Код: lec01_attention.py</summary>

```python
"""Self-attention на 4 токенах: scaled dot-product и causal mask. Веса не обучены, поэтому смысла в картинке нет."""
import numpy as np

rng = np.random.default_rng(0)
tokens = ["A", "cute", "teddy", "bear"]
n, d_model, d_k = len(tokens), 8, 4

X = rng.normal(size=(n, d_model))        # embedding токенов (позиции здесь опущены)
Wq = rng.normal(size=(d_model, d_k))     # проекции в query, key, value
Wk = rng.normal(size=(d_model, d_k))
Wv = rng.normal(size=(d_model, d_k))
Q, K, V = X @ Wq, X @ Wk, X @ Wv


def softmax(s):
    e = np.exp(s - s.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)


def attention(Q, K, V, causal=False):
    scores = Q @ K.T / np.sqrt(d_k)                 # n x n: сходство query и key
    if causal:
        scores = np.where(np.triu(np.ones_like(scores), k=1) == 1, -np.inf, scores)
    weights = softmax(scores)                       # каждая строка даёт в сумме 1
    return weights, weights @ V                     # взвешенная сумма value


np.set_printoptions(precision=2, suppress=True)
w, out = attention(Q, K, V)
print("Веса self-attention (строка = токен-query):")
print(w)
print("Сумма по строкам:", w.sum(axis=1))
print("Форма выхода:", out.shape, "(по строке на токен, размер d_k)")

wc, _ = attention(Q, K, V, causal=True)
print("\nВеса с causal mask (токен не видит будущее):")
print(wc)
```

## Архитектура трансформера

▶ [1:09:35](https://youtu.be/114i2Kz-LZA?t=4175)

Название статьи «Attention Is All You Need» объясняет идею: кроме внимания, связь между токенами не нужна. Раньше модели были рекуррентными: шли по токенам и несли скрытое состояние. Здесь рекуррентность убрали, токены общаются напрямую через самовнимание.

Статья вышла для машинного перевода, поэтому у архитектуры две части:

- энкодер (`encoder`) читает исходный текст и строит осмысленное представление каждого токена;
- декодер (`decoder`) берёт эти представления и пишет перевод.

Современные `LLM` стоят на этой основе, но чаще используют только одну из частей: `encoder-only` (только энкодер) или `decoder-only` (только декодер). Об этом речь пойдёт в следующих лекциях.

![Энкодер и декодер: энкодер строит представления токенов, декодер создаёт перевод по одному токену и возвращает его на свой вход](/assets/stanford-cme295/lec01-transformer.png)

Слева энкодер, справа декодер. Стрелка между ними передаёт `key` и `value`, а стрелки справа образуют цикл генерации.

### Вход: embedding и позиция

▶ [1:12:19](https://youtu.be/114i2Kz-LZA?t=4339)

Текст превращается в токены, и каждому токену соответствует `embedding`, который учится вместе с моделью. Этот вектор описывает только сам токен: он не знает ни соседей, ни места токена в тексте. Чтобы вернуть порядок, к нему прибавляют `positional embedding` (вектор позиции). Авторы статьи попробовали два способа:

- выучить вектор для каждой позиции. Это просто, но если на входе 1000 токенов, а модель видела позиции только до 500, остальные ей неизвестны;
- задать вектор формулой из синусов и косинусов разной частоты. Похоже на часы: часовая, минутная и секундная стрелки вращаются с разной скоростью, и вместе они однозначно показывают время. У близких позиций такие векторы похожи, у далёких — нет.

### Энкодер

▶ [1:16:27](https://youtu.be/114i2Kz-LZA?t=4587)

В блоке энкодера два слоя. Сначала слой самовнимания: проекции `Wq`, `Wk`, `Wv` дают `query`, `key` и `value`, и токен выражается через остальные. Затем полносвязная сеть (`feedforward`): она переводит представление в пространство большей размерности, а функция активации (`activation function`) добавляет нелинейность. На выходе у каждого токена получается осмысленное представление, зависящее от всех токенов.

### Декодер

▶ [1:18:19](https://youtu.be/114i2Kz-LZA?t=4699)

Декодер генерирует перевод по одному токену. Он начинается с `BOS` и устроен так:

1. Токен получает `positional embedding`.
2. Слой маскированного самовнимания (`masked self-attention`): токен смотрит на себя и на всё, что уже создано.
3. Слой перекрёстного внимания (`cross-attention`): `query` берётся из декодера, а `key` и `value` — из энкодера. Так модель спрашивает: какие токены исходного текста важны для этого токена.
4. Полносвязная сеть.
5. Линейный слой (`linear layer`) и `softmax` превращают результат в вероятности по словарю. Выбираем следующий токен.

Выбранный токен возвращается на вход декодера, и цикл повторяется. Такое чтение по своим же выходам называют авторегрессионным (`autoregressive`). Генерация заканчивается на `EOS`.

## Приёмы, которые помогают учиться

▶ [1:22:16](https://youtu.be/114i2Kz-LZA?t=4936)

Кроме главных слоёв, в статье есть несколько приёмов.

- Остаточная связь (`residual connection`): выход слоя — это `f(x) + x`, а не `f(x)`. Слой чуть правит `x`, а не переписывает его заново, и признаки проходят напрямую. Так легче обучать глубокие сети.
- Нормализация слоя (`LayerNorm`): нормирует значения внутри слоя и помогает сходимости.
- Маскированное самовнимание: токен декодера видит только уже созданные токены.
- Многоголовое внимание (`multi-head attention`): `Q`, `K`, `V` считают `h` раз с разными проекциями. Это как несколько фильтров в свёрточной сети: каждая голова учится смотреть по-своему.
- `Dropout` (случайное отключение значений): при обучении часть значений случайно отключают, и модель меньше зависит от отдельных признаков.
- Сглаживание меток (`label smoothing`): для «what a nice ...» правильный ответ не только «day», но и «class» или «evening». Поэтому вместо 100% для одного слова ставят, например, 90%, а остальные 10% делят между другими словами. Это улучшало метрики перевода, например BLEU.

## Сквозной пример: перевод фразы

▶ [1:27:35](https://youtu.be/114i2Kz-LZA?t=5255)

Дальше Shervine Amidi собирает всё в один пример: перевод «A cute teddy bear is reading» на французский.

**Вход.** Фразу разбивают на токены (для примера лектор берёт произвольное разбиение), добавляют `BOS` и `EOS`. Для каждого токена из таблицы берут `embedding` размера `d_model` и прибавляют `positional embedding` такого же размера. Результат — матрица `n × d_model`.

**Размеры.** Для `Q`, `K`, `V` нужны три матрицы проекции: `d_model × d_q`, `d_model × d_k`, `d_model × d_v`. Условие `d_q = d_k` нужно, чтобы перемножить `Q` и `Kᵀ`. В итоге у `Q`, `K`, `V` по `n` строк, а столбцов `d_q`, `d_k`, `d_v`.

**Механизм внимания.** Матрица `Q · Kᵀ` — это `n × n`: в каждой ячейке сходство одного `query` с одним `key`. Формула на самом деле не просто `QKᵀV`: сначала применяют `softmax` построчно, чтобы получить распределение с суммой 1. Перед ним делят на `√d_k`, потому что от `d_k` зависит разброс скалярных произведений. Без деления при большом `d_k` `softmax` становится почти `one-hot` и градиенты ухудшаются. Это показывает задача 3.

**Многоголовое внимание.** Всё это повторяют `h` раз параллельно. Результаты склеивают и умножают на матрицу `Wo`, которая возвращает размер к `d_model`. Размер вектора на входе и выходе слоя не меняется, поэтому блоки удобно складывать в стопку.

**Полносвязная сеть.** У неё один скрытый слой: она переводит `d_model` в `d_ff`, обычно больший, чем `d_model`, и обратно. Весь блок повторяют `N` раз. В оригинальной статье `N = 6`.

**Декодер.** Начинаем с `BOS`, берём его `embedding`, добавляем позицию. Маскированное самовнимание работает с каузальной маской: токен видит себя и предыдущие. Затем перекрёстное внимание: `query` из декодера, `key` и `value` из последнего выхода энкодера. Каждый блок декодера получает один и тот же выход энкодера. Дальше полносвязная сеть, линейный слой и `softmax` по словарю. В примере берут самый вероятный токен, а другие способы выбора обсудят позже. Из `BOS` получаем «un», затем следующий токен и так до `EOS`.

**Вопрос из зала:** что в этой схеме главное? Ответ лектора: внимание (название статьи подсказывает это) и полносвязная сеть, где лежит большая часть параметров и идёт обучение. Остальное — приёмы, которые помогают учиться. Ещё важно качество данных. В следующих лекциях многие детали выбросят, а оставят повторяющийся набор этих двух блоков.

**Про маску.** Маскированное самовнимание реализуют треугольной матрицей: на запрещённые места подставляют минус бесконечность, и после `softmax` вес нулевой.

**Про `softmax`.** Он встречается дважды с разной задачей: внутри механизма внимания распределяет веса между токенами, а в конце сети выбирает следующий токен из словаря.

Это ещё базовая версия: мы пока в 2017 году. Как обучают такие модели, будет в следующих лекциях, а во второй части курса речь пойдёт об агентах и системах.

## Итоги лекции

- Модель работает с числами, поэтому текст делят на токены, а токены превращают в векторы.
- Токены бывают из слов, символов и подслов. Подслова (`BPE`) дают компромисс между размером словаря и длиной последовательности.
- `One-hot` вектор не отражает сходство токенов. `Embedding` из `Word2vec` отражает, но даёт один вектор на слово и не учитывает порядок.
- `RNN` и `LSTM` учитывают порядок через скрытое состояние, но забывают далёкое прошлое и учатся медленно.
- Внимание даёт токену прямые связи с другими токенами, а самовнимание строит представление токена из всех токенов текста.
- В самовнимании у каждого токена есть `query`, `key` и `value`. Веса считает `softmax(QKᵀ / √d_k)`, а результат — сумма `value` с этими весами.
- Без позиции самовнимание не знает порядка, поэтому к `embedding` прибавляют `positional embedding`.
- Энкодер строит представления токенов, а декодер по одному токену пишет перевод. Он использует маскированное самовнимание и перекрёстное внимание.
- Основные слои — внимание и полносвязная сеть. Остаточная связь, нормализация слоя, `dropout` и сглаживание меток помогают учиться.
- Главная причина успеха трансформера — масштабируемость: больше данных и вычислений дают лучшее качество.

## Что это значит на практике

- Цену и время работы `LLM` определяет число токенов, а не слов. Считайте токены.
- Токенизатор надо подбирать под язык данных: русский текст на английском токенизаторе занимает больше токенов.
- Если собираете `prompt` (запрос к модели) вручную, служебные токены (`BOS`, `EOS`, роли в чате) должны совпадать с форматом модели.
- Сложность внимания растёт с длиной последовательности: матрица `n × n`. Длинные документы дорогие, и это стоит помнить при выборе размера контекста.

## Практика

Три небольшие задачи на Python. Нужен `numpy==2.5.1` (файл `scripts/cme295-code/requirements.txt`). Платные API не нужны.

### Задача 1. Токенизатор по слияниям BPE

Дан выученный список слияний: `("l","o")`, `("lo","w")`, `("e","s")`, `("es","t")`, `("n","e")`, `("ne","w")`. Напишите `tokenize(word)`: разбейте слово на буквы и примените слияния строго по порядку. Ожидаемый результат: `lowest` даёт `['low', 'est']`, `newest` даёт `['new', 'est']`, `slow` даёт `['s', 'low']`, `wow` даёт `['w', 'o', 'w']`.

<details>
<summary>Решение</summary>

```python
"""Задача 1: токенизируем слово по готовому списку слияний BPE."""
merges = [("l", "o"), ("lo", "w"), ("e", "s"), ("es", "t"), ("n", "e"), ("ne", "w")]


def tokenize(word):
    parts = list(word)
    for a, b in merges:                      # слияния применяем строго по порядку
        i = 0
        while i + 1 < len(parts):
            if parts[i] == a and parts[i + 1] == b:
                parts[i:i + 2] = [a + b]
            else:
                i += 1
    return parts


for w in ["lowest", "newest", "slow", "wow"]:
    print(w, "->", tokenize(w))
```

Вывод:

```text
lowest -> ['low', 'est']
newest -> ['new', 'est']
slow -> ['s', 'low']
wow -> ['w', 'o', 'w']
```

</details>

### Задача 2. Positional embedding из синусов и косинусов

Для `d_model = 16` постройте вектор позиции: первые 8 значений — синусы `pos · freq`, вторые 8 — косинусы, где `freq = 1 / 10000^(2i/d_model)` для `i = 0..7`. Посчитайте косинусное сходство позиции 10 с позициями 11, 12, 20 и 100. Ожидаемый результат: 0,936, 0,796, 0,456 и 0,035. Чем дальше позиция, тем меньше сходство.

<details>
<summary>Решение</summary>

```python
"""Задача 2: синусоидальные position embedding. Близкие позиции похожи, далёкие нет."""
import numpy as np

d_model = 16


def pos_embedding(pos):
    i = np.arange(d_model // 2)
    freq = 1.0 / (10000 ** (2 * i / d_model))      # частоты от высокой к низкой, как стрелки часов
    return np.concatenate([np.sin(pos * freq), np.cos(pos * freq)])


def cos_sim(a, b):
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)))


p10 = pos_embedding(10)
for other in [11, 12, 20, 100]:
    print(f"позиция 10 и {other}: cosine = {cos_sim(p10, pos_embedding(other)):.3f}")
```

Вывод:

```text
позиция 10 и 11: cosine = 0.936
позиция 10 и 12: cosine = 0.796
позиция 10 и 20: cosine = 0.456
позиция 10 и 100: cosine = 0.035
```

</details>

### Задача 3. Зачем делить на √d_k

Возьмите `numpy.random.default_rng(1)`, `n = 6` и для `d_k` из `[4, 256]` создайте случайный `q` размера `d_k` и матрицу `K` размера `6 × d_k`. Посчитайте `K @ q` и максимальный вес `softmax` с делением на `√d_k` и без него. Ожидаемый результат при `d_k = 256`: без деления 0,96, с делением 0,26. Для `d_k = 4` разница небольшая.

<details>
<summary>Решение</summary>

```python
"""Задача 3: зачем делить на sqrt(d_k). Без деления softmax становится почти one-hot."""
import numpy as np

rng = np.random.default_rng(1)
n = 6                                    # токенов в тексте


def softmax(s):
    e = np.exp(s - s.max())
    return e / e.sum()


for d_k in [4, 256]:
    q = rng.normal(size=d_k)
    K = rng.normal(size=(n, d_k))
    raw = K @ q
    print(f"d_k={d_k}")
    print("  разброс (std) скалярных произведений:", round(float(np.std(raw)), 2))
    print("  максимальный вес без деления:        ", round(float(softmax(raw).max()), 2))
    print("  максимальный вес с делением:         ", round(float(softmax(raw / np.sqrt(d_k)).max()), 2))
```

Вывод:

```text
d_k=4
  разброс (std) скалярных произведений: 0.67
  максимальный вес без деления:         0.28
  максимальный вес с делением:          0.23
d_k=256
  разброс (std) скалярных произведений: 8.42
  максимальный вес без деления:         0.96
  максимальный вес с делением:          0.26
```

</details>

## Вопросы для самопроверки

1. Почему современные модели используют токены-подслова, а не токены-слова или токены-символы?

<details>
<summary>Ответ</summary>

Слова дают огромный словарь и проблему слов вне словаря. Символы дают слишком длинные последовательности, а модель дорожает с их длиной. Подслова — компромисс: частые куски становятся токенами, редкие слова собираются из частей.

</details>

2. Какой недостаток `Word2vec` исправила `RNN` и какие проблемы у неё остались?

<details>
<summary>Ответ</summary>

`RNN` читает токены по порядку и несёт скрытое состояние, поэтому учитывает порядок слов. Остались две проблемы. Информация о далёком прошлом теряется, а с ней и дальние зависимости. Причина — затухающие градиенты. Кроме того, токены читают строго по одному, и обучение идёт медленно.

</details>

3. Что делают `query`, `key` и `value` в самовнимании?

<details>
<summary>Ответ</summary>

`Query` токена сравнивают с `key` всех токенов, получают сходство, а `softmax` превращает его в веса. Новое представление токена — сумма `value` с этими весами.

</details>

4. Почему в самовнимании нужен `positional embedding`?

<details>
<summary>Ответ</summary>

Каждый токен связан со всеми остальными напрямую, поэтому порядок слов сам по себе теряется. `Positional embedding` прибавляют ко входу, и токен «знает», где он стоит.

</details>

5. Чем перекрёстное внимание в декодере отличается от самовнимания?

<details>
<summary>Ответ</summary>

В самовнимании все три вектора берутся из одного текста. В перекрёстном внимании `query` приходит из декодера, а `key` и `value` — из энкодера. Так токен перевода сверяется с исходным текстом.

</details>

6. Зачем в декодере нужна маска и что будет без неё при обучении?

<details>
<summary>Ответ</summary>

Маска не даёт токену видеть следующие токены: при генерации их ещё нет. Без маски модель при обучении подсмотрела бы ответ в будущих токенах и не научилась бы генерировать.

</details>
