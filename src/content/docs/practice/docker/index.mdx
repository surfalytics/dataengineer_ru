**Docker** — инструмент для запуска программ в контейнерах.
**Контейнер** — это программа вместе со всем, что ей нужно: библиотеки, настройки, версия языка. Она работает одинаково на ноутбуке, у коллеги и на сервере.

## Зачем знать Docker

- **Любой инструмент данных запускается одной командой.** Postgres, Airflow, Metabase, Kafka, ClickHouse, Jupyter. Не нужно ставить и настраивать их вручную.
- **Одинаковая среда у всех.** Новый коллега делает `git clone` и `docker compose up`. Не нужно неделю собирать окружение.
- **Изолированные задачи.** Airflow, dbt и BI-инструмент не мешают друг другу и вашему ноутбуку. У каждого своя версия Python, и они не конфликтуют. Ненужное удаляется одной командой.
- **Продакшен.** Пайплайны в продакшене почти всегда работают как контейнеры: AWS ECS, Google Cloud Run, Azure Container Apps, Kubernetes. Образ, который вы проверили локально, запускается в облаке без изменений.
- **Открытые проекты.** У каждого популярного open source проекта есть готовый образ. Попробовать новый инструмент можно за пять минут.

## Как Docker используют в работе

| Кто | Задачи |
|---|---|
| Инженер данных | Пишет `Dockerfile` для пайплайна, запускает Postgres, Airflow, Kafka локально, собирает образы в CI, деплоит контейнеры в облако |
| Аналитик данных | Поднимает локальную базу или Metabase, запускает `dbt` без установки Python, воспроизводит чужой проект |
| Инженер ML | Упаковывает модель и её зависимости, запускает MLflow и Jupyter |

## Как устроен курс

Вы работаете на своём компьютере с настоящим Docker. Мы дадим небольшой набор файлов: заказы магазина в CSV и два Python-скрипта. На них вы пройдёте весь путь:

1. Запустите готовые контейнеры.
2. Соберёте свой образ.
3. Подключите контейнеры друг к другу.
4. Опишете всё в одном файле Docker Compose: база, загрузка данных, BI-инструмент.

## Что нужно знать заранее

- Базовые команды терминала. Если их нет, пройдите [курс CLI](/practice/cli/).
- Немного Python и SQL. Мы не пишем сложный код. Скрипты уже готовы.

<Aside type="note" title="Kubernetes в этом курсе">
Мы объясним, что такое Kubernetes. Но главная мысль курса другая: **во многих командах данных Kubernetes не нужен**. Контейнеры, Docker Compose и управляемый сервис в облаке закрывают большинство задач. Подробности — в уроке [Нужен ли Kubernetes](/practice/docker/kubernetes/).
</Aside>

## Как заниматься

Идите по урокам по порядку. Каждый урок: короткая теория, команды, потом задания.

Главное правило: **решайте сами, без AI**. Напишите команду, посмотрите на результат, и только потом открывайте решение.

<Aside type="tip" title="Не бойтесь ошибок">
Контейнеры одноразовые. Всё, что вы сломали, можно удалить и создать заново. Все команды очистки есть в [шпаргалке](/practice/docker/cheatsheet/).
</Aside>
