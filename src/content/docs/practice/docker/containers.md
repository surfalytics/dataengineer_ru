Это урок-теория. Здесь мало команд. Но он нужен: дальше вся работа с Docker строится на трёх словах — образ, контейнер, реестр.

## Какую проблему решает Docker

Вы написали Python-скрипт. На вашем ноутбуке он работает. Коллега запускает его и получает ошибку. Причины бывают такие:

- У коллеги Python 3.9, а у вас 3.12.
- У него другая версия библиотеки `pandas`.
- Не хватает системной библиотеки.
- Другая операционная система.

Это называют «у меня работает». Docker решает проблему так: вы упаковываете **скрипт вместе со всем окружением** в образ. Образ запускается одинаково везде.

## Что такое контейнер

**Контейнер** — это изолированный процесс на вашем компьютере. У него есть:

- своя файловая система;
- свои процессы (он не видит процессы хоста);
- своя сеть;
- лимиты памяти и процессора, если их задать.

Внутри контейнера программа думает, что она одна в системе. Но на деле это обычный процесс Linux. Контейнеры используют **общее ядро** операционной системы. Поэтому они лёгкие и запускаются за секунды.

Изоляцию делает само ядро Linux. Две главные функции:

- **namespaces** — ограничивают, что процесс видит (файлы, сеть, другие процессы);
- **cgroups** — ограничивают, сколько процесс использует (память, процессор).

Docker не придумал эти функции. Он сделал их простыми в использовании.

## Контейнер и виртуальная машина

Виртуальная машина (VM) — это целый компьютер внутри компьютера. У неё своя операционная система. Контейнер делит ядро с хостом и несёт только программу и её библиотеки.

![Сравнение виртуальных машин и контейнеров: у каждой VM своя гостевая ОС, а контейнеры делят одно ядро хоста](/assets/practice/docker/vm-vs-container.svg)

| | Виртуальная машина | Контейнер |
|---|---|---|
| Что внутри | Своя ОС целиком | Программа и библиотеки |
| Размер | Гигабайты | Мегабайты (десятки или сотни) |
| Запуск | Минуты | Секунды |
| Изоляция | Сильная | Хорошая, но слабее: общее ядро |
| Сколько на одном сервере | Единицы | Десятки и сотни |

Контейнеры не заменяют виртуальные машины. Часто контейнеры работают внутри VM. Облако так и устроено.

<details>
<summary>Почему на macOS и Windows контейнеры видят Linux?</summary>

Контейнеры Linux нуждаются в ядре Linux. На macOS и Windows его нет. Поэтому Docker Desktop запускает одну маленькую виртуальную машину с Linux. Все ваши контейнеры работают внутри неё. Это видно по команде `docker run --rm alpine:3.22 uname -sr`. Она покажет `Linux` даже на Mac.

</details>

## Образ, контейнер, реестр

Три главных слова:

| Слово | Что это | Как связано |
|---|---|---|
| **Образ** (image) | Файл с программой и всем, что ей нужно. Только для чтения. Неизменяемый | Шаблон для контейнеров |
| **Контейнер** (container) | Запущенная копия образа | Из одного образа можно запустить много контейнеров |
| **Реестр** (registry) | Хранилище образов. Например, Docker Hub | Откуда образы скачивают и куда загружают |

Ещё одно слово: **Dockerfile** — текстовый файл с рецептом. В нём написано, как собрать образ. Мы напишем его в уроке [Свой образ](/practice/docker/dockerfile/).

![Путь от Dockerfile к образу и контейнерам: build собирает образ, push и pull работают с реестром, run запускает контейнеры](/assets/practice/docker/image-to-container.svg)

Образ и контейнер — разные вещи. Это важно:

- Образ — это **файл** на диске. Он не «работает».
- Контейнер — это **процесс**. Он работает, останавливается, удаляется.
- Из образа `postgres:17` можно запустить три контейнера Postgres. Образ при этом один.

Если вы знаете Python: образ похож на класс, а контейнер — на объект этого класса.

## Слои образа

Образ состоит из **слоёв**. Команды `RUN`, `COPY` и `ADD` в `Dockerfile` создают слои с файлами: базовая система, Python, ваши библиотеки, ваш код.

- Слои только для чтения.
- Слои общие. Если у двух образов одинаковая база, она хранится на диске один раз.
- Docker скачивает только те слои, которых у вас ещё нет.

Когда вы запускаете контейнер, Docker добавляет сверху один тонкий слой **для записи**. Все файлы, которые программа создаёт, попадают туда.

Из этого следует важное правило: **когда контейнер удаляют, слой записи удаляется вместе с ним**. Данные пропадают. Как сохранить данные, мы разберём в уроке [Тома](/practice/docker/volumes/).

## Из чего состоит Docker

Когда вы пишете `docker run`, работают две части:

- **CLI** (`docker`) — программа, которую вы запускаете. Она только отправляет запросы.
- **Engine** (демон `dockerd`) — программа в фоне. Она скачивает образы и запускает контейнеры.

Если Engine не запущен, CLI пишет `Cannot connect to the Docker daemon`. Мы видели это в уроке [Установка](/practice/docker/setup/).

Docker — не единственный инструмент. Формат образов и контейнеров стандартный (OCI). Образ, который вы собрали в Docker, запустят Podman, containerd и Kubernetes.

## Почему контейнеры подходят для данных

Работа с данными — это много разных инструментов. У каждого свои зависимости и своя версия Python или Java. Контейнеры дают каждому инструменту отдельную изолированную среду.

| Инструмент | Как работает в контейнерах |
|---|---|
| **Airflow** | Несколько контейнеров: планировщик, веб-сервер, воркеры, база метаданных |
| **dbt** | Образ с нужной версией dbt. Запуск моделей как одноразовая команда |
| **BI** (Metabase, Superset) | Один контейнер для BI и один для базы. Запуск за минуту |
| **Postgres, MySQL, ClickHouse** | Локальная база для разработки. Удаляется и создаётся заново за секунды |
| **Kafka** | Локальный брокер для проверки стриминга без кластера |
| **Spark** | Образ с Spark и нужными JAR-файлами. Одинаковая среда для разработки и кластера |
| **Jupyter** | Ноутбук с нужными библиотеками. Не засоряет систему |
| **ML** (MLflow, модели) | Модель и её зависимости в одном образе. Запуск сервиса предсказаний |
| **Проверки качества данных** (Great Expectations, Soda) | Запуск проверок как одноразовая задача после загрузки |
| **ETL-скрипт на Python** | Образ со скриптом. Запуск по расписанию в облаке (ECS, Cloud Run, Airflow) |
| **Тесты и CI** | Тестовая база создаётся на время теста и удаляется |
| **Стек команды** | `git clone` и `docker compose up`. Новый коллега работает в первый же день |

Общая идея: контейнер — **одноразовая и повторяемая** среда. Сломали — удалили и создали заново.

Подробные примеры с командами — в уроке [Open source за минуты](/practice/docker/use-cases/).

## Когда контейнеры не нужны

- **Одноразовый запрос в DuckDB** на вашем компьютере. Достаточно `duckdb`.
- **Продакшен-база с важными данными.** Postgres в контейнере хорош для разработки. В продакшене чаще берут управляемую базу (Amazon RDS, Cloud SQL), чтобы не отвечать за бэкапы самому.
- **Программы с окном и мышью.** Контейнеры лучше всего работают с серверными программами.

## Практика

Для заданий нужен запущенный Docker. Первые команды `docker run` мы разберём подробно в следующем уроке. Сейчас просто выполните их.

### Задание 1

Запустите Python 3.12 в контейнере и узнайте его версию. Затем узнайте версию Python на своём компьютере (`python3 --version`). Совпадают ли они?

**Проверка:** контейнер печатает `Python 3.12.<число>`. Версия на вашем компьютере может быть другой, или Python может не быть совсем. Контейнеру это всё равно.

<details>
<summary>Решение</summary>

```bash
docker run --rm python:3.12-slim python --version
python3 --version
```

</details>

### Задание 2

Узнайте, какая операционная система и какое ядро внутри контейнера Alpine. Затем сравните с вашей системой (`uname -sr`).

**Проверка:** контейнер отвечает `Linux <версия>`. Первое слово — всегда `Linux`, даже если у вас Mac.

<details>
<summary>Решение</summary>

```bash
docker run --rm alpine:3.22 uname -sr
uname -sr
```

На macOS второй ответ начнётся с `Darwin`. Ядро контейнера — Linux из виртуальной машины Docker Desktop.

</details>

### Задание 3

Файл в контейнере исчезает вместе с ним. Проверьте это. Создайте файл `/tmp/f` внутри контейнера и покажите содержимое `/tmp`. Затем запустите **новый** контейнер из того же образа и снова покажите `/tmp`.

**Проверка:** первый контейнер показывает `f`. Второй не показывает ничего, папка пустая.

<details>
<summary>Решение</summary>

```bash
docker run --rm alpine:3.22 sh -c 'echo test > /tmp/f && ls /tmp'
docker run --rm alpine:3.22 ls /tmp
```

Каждый контейнер — новая копия образа со своим слоем записи. Файл из первого контейнера пропал вместе с ним.

</details>

### Задание 4

Ответьте без команд. Это образ или контейнер?

1. `postgres:17` на Docker Hub.
2. Процесс Postgres, который сейчас слушает порт 5432.
3. Файл на диске, который Docker скачал командой `pull`.
4. То, что показывает `docker ps`.

**Проверка:** образ, контейнер, образ, контейнер.

<details>
<summary>Объяснение</summary>

Образ — это шаблон, он лежит на диске и не работает. Контейнер — запущенный процесс. `docker ps` показывает только контейнеры. Образы показывает `docker images`.

</details>
