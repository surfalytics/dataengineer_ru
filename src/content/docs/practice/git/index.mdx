**Git** — система контроля версий. Она хранит историю всех изменений в коде.
**GitHub** и **GitLab** — сайты, где живут Git-репозитории и где команда работает вместе.

В этом курсе мы возьмём SQL-проект и пройдём весь путь: от первого коммита до Pull Request и проверок в CI.

## Зачем знать Git

- **Не нужны файлы `report_v2.sql`, `report_v2_final.sql`, `report_final_FINAL.sql`.** Git хранит все версии в одном файле.
- **Видно, кто, когда и зачем изменил код.** Любую ошибку можно откатить.
- **Коллеги смотрят код до продакшена.** Изменения проходят через Pull Request (Merge Request). Замечания пишут прямо в коде.
- **CI проверяет код автоматически.** Тесты и линтер ловят ошибки до того, как они сломают продакшен.
- **Git — обязательный минимум для работы с AI-агентами.** Агент меняет много файлов. Git показывает, что именно он изменил, и позволяет всё отменить.

## Как Git используют в работе

| Кто | Задачи |
|---|---|
| Инженер данных | Хранит в Git пайплайны, DAG для Airflow, модели dbt, Terraform. Каждое изменение идёт через Pull Request и CI |
| Аналитик данных | Хранит SQL-запросы и модели dbt в Git. Делает ревью запросов коллег |

## Как заниматься

Идите по урокам по порядку. Каждый урок: короткое объяснение, примеры, задания.

Главное правило: **решайте сами, без AI**. Напишите команду, посмотрите результат, и только потом открывайте решение.
