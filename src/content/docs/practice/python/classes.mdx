Класс объединяет данные и функции, которые с ними работают. Это шаблон, а объект — конкретный экземпляр по этому шаблону.

Для data engineer нужен минимум. Вы будете **читать** классы в библиотеках и **писать** простые `dataclass`. ООП, наследование и паттерны сейчас не нужны.

Правило курса: решайте сами, без AI.

## class и __init__

```python
class Order:
    def __init__(self, order_id, user, amount, channel="web"):
        self.order_id = order_id
        self.user = user
        self.amount = amount
        self.channel = channel

    def with_vat(self, rate=0.2):
        return round(self.amount * (1 + rate), 2)

    def is_big(self):
        return self.amount > 100


o = Order(1001, "anna", 49.9)
print(o.user, o.amount, o.channel)
print(o.with_vat())
print(o.is_big())
o.amount = 150
print(o.is_big())
```

Ответ:

```
anna 49.9 web
59.88
False
True
```

| Часть | Что значит |
|---|---|
| `class Order` | Объявление класса. Имя пишут с заглавной буквы |
| `__init__` | Вызывается при создании объекта. Задаёт начальные данные |
| `self` | Сам объект. Первый параметр каждого метода |
| `self.amount` | Атрибут: данные объекта |
| `with_vat`, `is_big` | Методы: функции внутри класса |

- Создать объект: `Order(1001, "anna", 49.9)`. Python сам вызовет `__init__`.
- Читать и менять атрибут: `o.amount`.
- Вызвать метод: `o.is_big()`. Аргумент `self` передавать не нужно.

Если вывести объект, вы увидите мало пользы:

```python
print(o)
```

Ответ (адрес у вас будет другой):

```
<__main__.Order object at 0x1052da120>
```

Писать `__init__` и `self.x = x` для каждого поля скучно. Для этого есть `dataclass`.

## dataclass

```python
from dataclasses import dataclass


@dataclass
class Order:
    order_id: int
    user: str
    amount: float
    channel: str = "web"

    def is_big(self) -> bool:
        return self.amount > 100


d = Order(1002, "boris", 120.0, "app")
print(d)
print(d.is_big())
print(d == Order(1002, "boris", 120.0, "app"))
```

Ответ:

```
Order(order_id=1002, user='boris', amount=120.0, channel='app')
True
True
```

`@dataclass` сам создаёт:

- `__init__` из списка полей;
- читаемый вывод (`repr`);
- сравнение объектов по значениям полей.

Поля описывают типом: `amount: float`. Поле со значением по умолчанию ставьте после обязательных.

<Aside type="note" title="Типы не проверяются">
`dataclass` не проверяет типы. `Order(1, "a", "oops")` создастся без ошибки. Приводите типы сами: `float(row["amount"])`.
</Aside>

### Из словаря в dataclass

Данные из CSV приходят как строки. Преобразуйте их при создании объекта.

```python
rows = [
    {"order_id": "1001", "user": "anna", "amount": "49.9", "channel": "web"},
    {"order_id": "1002", "user": "boris", "amount": "120.0", "channel": "app"},
    {"order_id": "1004", "user": "dina", "amount": "300.0", "channel": "app"},
]

orders = [
    Order(int(r["order_id"]), r["user"], float(r["amount"]), r["channel"])
    for r in rows
]
print(round(sum(o.amount for o in orders), 2))
print([o.order_id for o in orders if o.is_big()])
```

Ответ:

```
469.9
[1002, 1004]
```

Разница с `dict`: вместо `o["amount"]` пишем `o.amount`. Опечатка в имени поля даст ошибку сразу, а не `None` позже.

### frozen: объект нельзя менять

```python
@dataclass(frozen=True)
class Config:
    path: str
    limit: int = 10


c = Config("orders.csv")
print(c)
c.limit = 99
```

Ответ:

```
Config(path='orders.csv', limit=10)
...
dataclasses.FrozenInstanceError: cannot assign to field 'limit'
```

Для настроек и записей, которые не должны меняться, ставьте `frozen=True`.

## Класс с состоянием

Иногда объект копит данные между вызовами.

```python
class OrderStats:
    def __init__(self):
        self.count = 0
        self.total = 0.0

    def add(self, order):
        self.count += 1
        self.total += order.amount

    def report(self):
        return f"{self.count} orders, total {self.total}"


st = OrderStats()
for o in orders:
    st.add(o)
print(st.report())
```

Ответ:

```
3 orders, total 469.9
```

`self.count` и `self.total` живут между вызовами `add`. В обычной функции для этого пришлось бы передавать их туда и обратно.

## Где это в работе

| Задача | Как помогают классы |
|---|---|
| Запись данных с известными полями | `dataclass`: `Order`, `Event`, `User` |
| Настройки pipeline | `dataclass(frozen=True)`: путь, лимит, дата |
| Чужие библиотеки | `client = Client(...)`, `client.get(...)`: это объекты и методы |
| Коннекторы к БД, S3, API | Класс держит соединение между вызовами |
| Pydantic, SQLAlchemy | Те же идеи: класс описывает поля |

Простое правило: если хватает функций и `dict`, класс не нужен. Класс нужен, когда данные и поведение связаны, или когда нужна понятная структура записи.

<summary>Решение</summary>

```python

    def __init__(self, name, city):

        self.city = city

    def greet(self):
        return f"Hi, {self.name} from {self.city}"


print(User("anna", "Moscow").greet())
```

## Что запомнить

- Класс — шаблон. Объект — экземпляр. `__init__` задаёт начальные данные, `self` — сам объект.
- Метод — функция внутри класса: `obj.method()`.
- `@dataclass` убирает шаблонный код и даёт читаемый вывод и сравнение.
- `frozen=True` защищает объект от случайных изменений.
- Классы вы чаще читаете в библиотеках, чем пишете. Хватит `dataclass`.
