**WAL (Write-Ahead Log)** — журнал предзаписи PostgreSQL. В нём хранятся записи об изменениях, достаточные для их повторного применения при восстановлении. Прежде чем сохранить изменённую страницу таблицы или индекса на диске, сервер должен сохранить относящиеся к ней записи WAL.

## Что происходит при UPDATE и COMMIT?

Допустим, транзакция уменьшает остаток товара с **5 до 1**.

| Момент | Что делает PostgreSQL |
| --- | --- |
| `UPDATE` | Создаёт новую версию строки, меняет страницу в общих буферах и формирует записи WAL. Изменённую страницу в памяти называют «грязной». |
| `COMMIT` | Добавляет запись о фиксации. При обычной локальной синхронной фиксации подтверждает успех клиенту, когда WAL до этой записи надёжно сохранён. Страница таблицы в этот момент ещё может быть только в памяти в обновлённом виде. |
| Запись страницы | PostgreSQL записывает грязную страницу в файл таблицы. Это может произойти отдельно от `COMMIT`, в том числе во время контрольной точки. Для страницы соблюдается правило предзаписи. |

Так серверу достаточно последовательно записывать журнал, чтобы подтверждать транзакции. Запись множества изменённых страниц таблиц и индексов можно распределить во времени. [Как работает WAL](https://www.postgresql.org/docs/18/wal-intro.html)

## Как после сбоя восстановится остаток?

Пусть клиент уже получил подтверждение `COMMIT`, а файл таблицы на диске всё ещё содержит **5**. После перезапуска PostgreSQL берёт точку начала восстановления из последней завершённой контрольной точки и читает WAL вперёд. Записи журнала позволяют восстановить недостающие изменения. После восстановления клиент увидит **1**.

Если запись о фиксации транзакции не успела сохраниться до сбоя, её изменения останутся невидимыми для других транзакций. Поэтому наличие в WAL записи об изменении строки само по себе ещё не означает успешный `COMMIT`. [Контрольные точки и восстановление](https://www.postgresql.org/docs/18/wal-configuration.html)

## Что такое LSN и где ещё используется WAL?

**LSN (Log Sequence Number)** — позиция в потоке WAL. По двум позициям можно определить расстояние в байтах, например между отправленной и воспроизведённой частью журнала. На основном сервере текущую позицию записи можно посмотреть так.

```sql
SELECT pg_current_wal_lsn();
```

- **Физическая репликация.** Резервный сервер получает и воспроизводит WAL, постепенно догоняя основной. При асинхронной репликации недавний подтверждённый заказ некоторое время может быть виден только на основном сервере.
- **Восстановление на момент времени (PITR).** Берут базовую резервную копию и непрерывную цепочку архивных сегментов WAL. Их можно воспроизвести до момента перед ошибочным удалением, если нужный период покрыт архивом.
