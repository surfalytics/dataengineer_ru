Вид соединения в SQL определяет, **какие строки попадут в результат**. Например, `INNER JOIN` возвращает совпавшие пары. `LEFT JOIN` также сохраняет строки слева, для которых совпадения нет, и заполняет столбцы справа значениями `NULL`. У `RIGHT JOIN` сохраняется правая сторона, у `FULL JOIN` — обе.

Физический алгоритм определяет, **как СУБД найдёт совпадения**. Например, для одного и того же `LEFT JOIN` по равенству ключей PostgreSQL может выбрать Hash Join, Merge Join или Nested Loop. Выбор зависит от условия соединения, числа строк, порядка данных и доступных индексов. В трёх схемах ниже для сравнения взят один пример: `INNER JOIN` с условием `A.key = B.key`.

## Декартово произведение

`CROSS JOIN` соединяет каждую строку слева с каждой строкой справа. Если слева `N` строк, а справа `M`, получится ровно `N × M` пар. Это правило SQL описывает результат. Конкретный способ его построения выбирает СУБД.

### Когда нужны все комбинации

Допустим, в отчёте нужна строка **для каждого магазина за каждый день**, в том числе за дни без продаж. Возьмём два магазина и три даты:

```sql
WITH shops(shop_id) AS (
    VALUES (1), (2)
),
days(sale_date) AS (
    VALUES (DATE '2026-11-01'), (DATE '2026-11-02'), (DATE '2026-11-03')
)
SELECT s.shop_id, d.sale_date
FROM shops AS s
CROSS JOIN days AS d
ORDER BY s.shop_id, d.sale_date;
```

Получится шесть строк: три даты для магазина 1 и те же три даты для магазина 2. Теперь к этим парам можно присоединить дневные продажи через `LEFT JOIN` по **магазину и дате**, а пропуски заменить нулём через `COALESCE`.

### Когда размножение строк опасно

- **Результат слишком велик.** При 100 тысячах строк с каждой стороны полное произведение даст 10 миллиардов пар. Даже вывод такого результата дорог, а последующая сортировка или агрегация добавит работы. Для отчёта ограничьте список магазинов и период теми, которые действительно нужны.
- **Потеряна связь между таблицами.** Запись `FROM orders, customers` без условия связи сопоставит каждый заказ со всеми клиентами. Если после этого сложить суммы заказов, выручка окажется завышена.
- **Условие связи неполное.** Если в примере с магазинами присоединить дневные продажи только по дате, каждый магазин получит продажи всех магазинов за этот день. При выручке 100 и 150 рублей сумма за день удвоится с 250 до 500. Здесь лишние комбинации возникают внутри одной даты.
