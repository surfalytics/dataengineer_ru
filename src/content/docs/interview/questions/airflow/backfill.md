**Backfill** — управляемый запуск DAG за исторический период. Допустим, 8 марта исправили расчёт выручки и нужно пересчитать только 1–3 марта. Для суточного расписания Airflow рассмотрит три логические даты. Каждый созданный DagRun получит свой интервал. Если расчёт берёт границы из контекста запуска, первый обработает 1 марта, второй — 2 марта, третий — 3 марта.

**Когда какой механизм нужен?** `catchup` автоматически подхватывает пропущенные интервалы расписания. Backfill позволяет выбрать период вручную, в том числе при `catchup=False`. Если в существующем запуске нужно повторить лишь упавшую загрузку одной таблицы, можно очистить состояние этой задачи через `Clear`.

## Как запускать в Airflow 2 и 3?

| Версия | Пример для DAG `sales_daily` |
| --- | --- |
| Airflow 2.11 | `airflow dags backfill -s 2026-03-01 -e 2026-03-03 sales_daily`. Флаг `--rerun-failed-tasks` разрешает повтор упавших задач. `--reset-dagruns` сбрасывает прежние запуски в диапазоне для полного пересчёта. |
| Airflow 3.4 | В UI откройте меню запуска DAG и выберите **Backfill**. Через CLI — `airflow backfill create --dag-id sales_daily --from-date 2026-03-01 --to-date 2026-03-03 --reprocess-behavior failed --max-active-runs 2`. Доступен и REST API. |

## Что будет, если за дату уже есть запуск?

В Airflow 3.4 учитывается состояние последнего запуска за каждую логическую дату.

| `--reprocess-behavior` | Какие даты получат новый запуск |
| --- | --- |
| `none` | Только даты, за которые ещё не было запуска. |
| `failed` | Пропущенные даты и даты с последним запуском в состоянии `failed`. |
| `completed` | Пропущенные даты и даты, где последний запуск завершился успешно или с ошибкой. |

Если последний запуск ещё в очереди или выполняется, новый для той же даты не создаётся. `--dry-run` покажет даты-кандидаты. Отдельный `--max-active-runs` ограничивает параллелизм backfill независимо от одноимённого лимита DAG. `--run-backwards` начинает с новых дат, если бизнес-логика допускает такой порядок.

**Как сохранить результат корректным?** Для пересчёта 1–3 марта используйте интервал соответствующего запуска и заменяйте только его партицию. Если каждый запуск читает общий watermark «до сегодняшнего дня», он может пропустить историю.
