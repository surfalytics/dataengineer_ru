**Генератор DAG** — Python-фабрика, которая при разборе файла создаёт несколько определений DAG по конфигурации. Например, у 40 источников одинаковые шаги «извлечь → проверить → загрузить», но отдельные расписания, владельцы и правила повторного запуска. Фабрика задаёт общий процесс, а описание источника — то, что различается.

| Откуда берётся конфигурация | Как устроить | Когда выбирать |
| --- | --- | --- |
| YAML или JSON в Git рядом с DAG | Одна запись описывает источник, расписание и назначение. CI проверяет схему и уникальность идентификаторов. Фабрика перебирает записи и строит DAG. | Небольшой каталог, изменения проходят code review. |
| Сгенерированный Python-модуль | CI заранее преобразует метаданные в модуль с константами. При парсинге фабрика импортирует готовые структуры. | Каталог больше, формат стабилен, желательно сократить работу парсера. |
| Внешняя БД или API каталога | Владельцы ведут каталог в БД, сервис отдаёт его по API. Отдельный процесс забирает, проверяет и публикует **версионированный снимок** рядом с DAG. Фабрика читает этот снимок. | Каталог меняется независимо от репозитория, за источники отвечают несколько команд. |

**Где выполнять запрос к API?** DAG Processor регулярно исполняет верхнеуровневый Python-код DAG-файлов. Если там обращаться к БД или API, даже обычный парсинг будет ждать сеть, а недоступный каталог может сорвать импорт всех его DAG. При публикации снимка сохраняйте предыдущую исправную версию до готовности новой, стройте стабильный `dag_id` из идентификатора источника и сортируйте определения для предсказуемого порядка задач. Секреты передавайте через Connections или secrets backend.

**Когда генератор избыточен?** Если граф один и меняется только дата или клиент, достаточно одного DAG с Params. Если лишь после начала запуска выясняется, какие файлы появились, первая задача читает каталог, а **Dynamic Task Mapping** через `expand()` создаёт экземпляры следующей задачи в том же DagRun. Генератор нужен, когда самостоятельной единицей планирования, истории и перезапуска должен стать сам DAG.
