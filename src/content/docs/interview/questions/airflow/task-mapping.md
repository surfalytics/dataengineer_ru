**Dynamic Task Mapping** создаёт несколько экземпляров одной задачи во время запуска DAG. Например, `plan_ranges` возвращает список дат, а `load_day.expand(day=plan_ranges())` назначает каждому экземпляру `load_day` свой день. В графе видна одна mapped task. Если открыть её в UI, внутри выбранного DagRun виден список экземпляров. У каждого свой `map_index`, статус, лог и попытки выполнения.

## Как это выглядит для трёх дней?

<details open>
<summary><strong>load_day</strong> — 3 экземпляра в одном DagRun</summary>

| Экземпляр в списке | Какие события читает | Пример состояния |
| --- | --- | --- |
| `load_day[0]` | С 1 марта включительно до 2 марта | Выполняется |
| `load_day[1]` | Со 2 марта включительно до 3 марта | Выполняется |
| `load_day[2]` | С 3 марта включительно до 4 марта | В очереди |

</details>

В примере пул источника даёт два слота, и каждая загрузка берёт один. Пока два дня читаются параллельно, третий ждёт. Если упадёт только 2 марта, можно повторить конкретный экземпляр и перезаписать его партицию. Для удобства в UI экземплярам можно дать подписи с датами через `map_index_template`.

Для нескольких месяцев схема та же. Планирующая задача отдаёт пары границ `start` и `end`, а `load_range.expand_kwargs(ranges)` сохраняет каждую пару вместе. Два отдельных списка в `expand(start=..., end=...)` дали бы декартово произведение. В XCom достаточно передать границы, сами данные считывает каждый экземпляр задачи.

**Откуда ускорение?** Независимые диапазоны можно читать и писать одновременно. Airflow планирует каждый экземпляр отдельно. В нашем примере каждая загрузка открывает своё соединение с источником. Выигрыш есть, пока у источника, сети и приёмника остаётся запас. Ограничить общий доступ к БД можно через Pool, а число одновременно работающих экземпляров конкретной задачи по всем активным DagRun — через `max_active_tis_per_dag`. При необходимости выставляют и лимит размера списка `max_map_length`.

**Mapping и backfill решают разные задачи.** Для истории суточного DAG backfill создаёт запуски по датам. Mapping, например, позволяет внутри одного месячного запуска загрузить дни параллельно. Если в DAG используются оба механизма, учитывайте произведение числа активных запусков и числа одновременно работающих загрузок.
