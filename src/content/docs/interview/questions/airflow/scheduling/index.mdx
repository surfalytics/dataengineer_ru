**Catchup** определяет, создаст ли scheduler запуски за пропущенные интервалы расписания. Допустим, у суточного DAG с интервальным расписанием завершились периоды 1, 2 и 3 марта, за которые ещё нет запусков.

| Настройка | Что сделает scheduler при включении DAG |
| --- | --- |
| `catchup=True` | Создаст недостающие запуски за все три завершённых интервала с учётом лимитов. |
| `catchup=False` | Запланирует последний актуальный завершённый интервал. Предыдущие два автоматически навёрстывать не будет. |

В конфигурации по умолчанию у **2.11** catchup включён, у **3.x** выключен. Явное значение на DAG делает поведение понятным при переносе. Для управляемой обработки конкретного исторического диапазона используют **backfill**, а `retries` повторяет упавший экземпляр задачи.

Нагонять историю имеет смысл, если каждый запуск читает свой период. DAG, который всегда берёт «вчера относительно текущего времени», при трёх запусках может трижды обработать один день.
