Почему ключом словаря может быть только неизменяемый тип?

## Ответ

Точнее: ключ словаря должен быть **хешируемым**, а не просто неизменяемым.

`dict` реализован как хеш-таблица. При добавлении ключа Python вычисляет его хеш и использует это значение для поиска позиции в таблице. Пока ключ находится в словаре, его хеш должен оставаться стабильным. Если хеш изменится, словарь будет искать ключ уже в другой позиции и нарушится целостность структуры данных.

Поэтому изменяемые встроенные контейнеры `list`, `dict` и `set` не хешируются и не могут быть ключами.

```python
# TypeError: unhashable type: 'list'
data = {[1, 2]: "value"}
```

`tuple` может быть ключом только тогда, когда все его элементы тоже хешируемы.

```python
valid = {(1, 2): "value"}

# TypeError: unhashable type: 'list'
invalid = {([1, 2], 3): "value"}
```

## Функции, классы и экземпляры как ключи

Функции и классы являются объектами и обычно хешируются по идентичности. Экземпляры пользовательских классов также хешируемы по умолчанию, пока класс не переопределил правила равенства и хеширования несовместимым образом.

```python
def my_func(a):
    return a


class MyClass:
    def __init__(self, a):
        self.a = a


myclass = MyClass(1)

values = {
    my_func(1): 1,
    my_func: 2,
    MyClass: 3,
    myclass: 4,
}

print(
    values[my_func(1)],
    values[my_func],
    values[MyClass],
    values[myclass],
)  # 1 2 3 4
```

Важный контракт: если `a == b`, то `hash(a)` и `hash(b)` должны быть одинаковыми. Объект, чей хеш зависит от изменяемого состояния, опасно использовать как ключ.
