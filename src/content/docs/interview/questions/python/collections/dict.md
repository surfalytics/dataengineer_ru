Что такое словарь в Python? Как устроены его операции, какова их сложность и что такое коллизии?

## Ответ

`dict` — хеш-таблица, которая хранит пары «ключ — значение».

Python вычисляет хеш ключа и по нему находит нужную позицию в таблице, поэтому ему не требуется перебирать все элементы.

| Операция | Средняя сложность | Худший случай |
| --- | --- | --- |
| Чтение по ключу | `O(1)` | `O(n)` |
| Добавление или обновление | `O(1)` | `O(n)` |
| Удаление | `O(1)` | `O(n)` |
| Проверка наличия ключа | `O(1)` | `O(n)` |

Худший случай возникает при большом количестве коллизий, но при нормальном распределении хешей основные операции работают в среднем за `O(1)`.

## Как из ключа получается номер ячейки?

1. Вычисляется `h = hash(key)`. Результат — целое число. Способ вычисления зависит от типа ключа. Для небольших положительных `int` хеш равен самому числу, а у `str` он зависит от содержимого и по умолчанию от случайного секрета процесса. Пользовательский класс может задать `__hash__`. У равных ключей должны быть равные хеши.
2. Из хеша получается **стартовая позиция**. Для таблицы на `capacity` ячеек удобно записать `h % capacity`. В CPython ёмкость — степень двойки, поэтому используется эквивалентная маска `h & (capacity - 1)`. Ёмкость — число ячеек внутренней таблицы. `len(d)` показывает число пар в словаре.
3. По индексу ячейки словарь находит запись и проверяет ключ. Если это тот же объект или ключи с одинаковым хешем равны, словарь возвращает значение. Если ячейку занял другой ключ, проверяется следующая позиция в последовательности проб. Нетронутая пустая ячейка завершает безуспешный поиск.

```python
capacity = 8
for key in (10, 18):
    h = hash(key)
    print(key, h, h % capacity, h & (capacity - 1))
# ключ  хеш  остаток  маска
#   10   10        2      2
#   18   18        2      2

d = {10: "десять", 18: "восемнадцать"}
assert d[18] == "восемнадцать"
```

**Почему в среднем O(1)?** Вычислив стартовую позицию, словарь сразу обращается к конкретной ячейке. При хорошем распределении хешей и свободном месте среднее число проверок остаётся небольшим даже при росте словаря. При множестве коллизий поиск может дойти до **O(n)**. Оценка относится к числу записей при ограниченной стоимости хеширования и сравнения ключа. Например, первое вычисление хеша длинной строки зависит и от её длины. [Реализация dict в CPython](https://github.com/python/cpython/blob/3.14/Objects/dictobject.c) · [Контракт хеширования](https://docs.python.org/3/reference/datamodel.html#object.__hash__)

## Требования к ключам

Ключ должен быть **хешируемым**: его хеш не должен изменяться во время жизни объекта, а сам объект должен поддерживать сравнение на равенство.

- `int`, `str` и `frozenset` подходят как ключи.
- `list`, `dict` и `set` не подходят, потому что они изменяемые.
- `tuple` подходит только тогда, когда все его элементы тоже хешируемы.

```python
valid = {
    "name": "Анна",
    (10, 20): "координаты",
}

# TypeError: unhashable type: 'list'
invalid = {[1, 2]: "значение"}
```

## Коллизии

**Коллизия** возникает, когда разные ключи претендуют на одну позицию в хеш-таблице.

Python разрешает коллизии с помощью пробирования: проверяет другие позиции и сравнивает сами ключи. Поэтому разные ключи с одинаковым хешем не смешивают свои значения.
