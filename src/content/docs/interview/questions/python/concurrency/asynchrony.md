**Асинхронность** позволяет одной задаче уступить управление, пока она ждёт данные, а другой — продолжить работу. Например, приложение может отправить запрос в каталог товаров, а во время ожидания ответа отправить второй запрос на склад.

В Python `async def` объявляет корутину. Вызов такой функции создаёт объект корутины. `asyncio.create_task()` ставит её на выполнение, а `await` позволяет дождаться результата. Когда задача доходит до ожидания ещё не готового результата, цикл событий может выполнить другую готовую задачу.

## Как два ожидания перекрываются?

```python
import asyncio

async def request(source):
    await asyncio.sleep(0.1)  # Имитируем ожидание ответа сервиса
    return source

async def main():
    catalog = asyncio.create_task(request("Каталог"))
    stock = asyncio.create_task(request("Склад"))
    print(await catalog, await stock)

asyncio.run(main())  # Каталог Склад
```

Обе задачи запланированы до первого `await` в `main`. Пока каталог ждёт, склад тоже успевает начать своё ожидание. Две задержки по 0,1 секунды в таком примере занимают в сумме около 0,1 секунды. При двух последовательных вызовах `await request(...)` второй начнётся только после первого, и ожидание займёт около 0,2 секунды.

## Чем это отличается от мультипроцессинга?

Один цикл событий выполняет Python-код задач по очереди в своём потоке. Это удобно для сетевых запросов и других операций с ожиданием. Долгий вычислительный цикл без передачи управления займёт поток и задержит остальные задачи. Для вычислений, которые нужно выполнять одновременно на нескольких ядрах, работу можно распределить между процессами.
