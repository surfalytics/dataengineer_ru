За какую асимптотику работает базовая сортировка в Python?

## Ответ

`list.sort()` и `sorted()` используют алгоритм **Timsort**.

| Случай | Временная сложность |
| --- | --- |
| Лучший | `O(n)` |
| Средний | `O(n log n)` |
| Худший | `O(n log n)` |

Timsort находит в данных уже упорядоченные участки — `runs` — и эффективно объединяет их. Поэтому отсортированные или почти отсортированные последовательности могут обрабатываться за `O(n)`. Это лучший случай, а не средний.

Алгоритм особенно эффективен, когда порядок данных частично сохранился, например после предыдущей сортировки с небольшими изменениями.

## `sort()` и `sorted()`

- `list.sort()` изменяет исходный список на месте и возвращает `None`.
- `sorted()` принимает любой итерируемый объект и возвращает новый список.

```python
numbers = [3, 1, 2]

result = sorted(numbers)
print(numbers)  # [3, 1, 2]
print(result)   # [1, 2, 3]

numbers.sort()
print(numbers)  # [1, 2, 3]
```

## Стабильность

Сортировка Python стабильна: элементы с одинаковым ключом сохраняют исходный взаимный порядок.

```python
users = [
    {"name": "Анна", "age": 30},
    {"name": "Олег", "age": 20},
    {"name": "Мария", "age": 30},
]

users.sort(key=lambda user: user["age"])
# Анна останется раньше Марии среди пользователей с age=30
```

В худшем случае Timsort использует `O(n)` дополнительной памяти.
