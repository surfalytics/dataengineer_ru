Producer может указать partition явно либо передать key. Обычно partitioner вычисляет partition по key, поэтому события с одинаковым key попадают в одну partition. Например, все изменения заказа с одним `order_id` я отправляю с этим ID как key.

Kafka сохраняет порядок записей внутри конкретной partition: consumer увидит их в той последовательности, в которой они были успешно добавлены в этот log. Между разными partitions общего порядка нет, потому что они обрабатываются параллельно.

Если нужен порядок по отдельной сущности, достаточно стабильно направлять её события в одну partition. Если нужен абсолютный порядок всех событий topic, придётся оставить одну partition, но тогда теряется горизонтальный параллелизм.

Также учитываю, что изменение количества partitions может изменить распределение keys. Поэтому для данных, где порядок критичен, это изменение нужно планировать отдельно.
