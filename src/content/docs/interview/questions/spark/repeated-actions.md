**Переменная DataFrame хранит план получения строк.** Присваивание `paid = orders.where("status = 'paid'")` само по себе не сохраняет отфильтрованные заказы. Два действия могут запустить два отдельных вычисления этого плана.

```python
paid = orders.where("status = 'paid'")
paid.count()
paid.groupBy("shop_id").sum("amount").show()
```

Первый вызов вернул одно число. Из него невозможно восстановить суммы по магазинам. Второе действие снова запрашивает нужные ему строки. При чтении Parquet первый запрос может ограничиться колонкой статуса, а второму понадобятся также магазин и сумма. Поэтому фразу «каждый раз пересчитывается вся цепочка» стоит понимать как **повторное выполнение нужной части плана**: отдельные промежуточные блоки, например сохранившийся shuffle, иногда доступны для переиспользования.

Если одна дорогая выборка нужна обоим расчётам, пометь её `paid.cache()` до первого действия. Полный проход `paid.count()` в этом примере заполнит кеш. Второй запрос сможет читать сохранённые партиции через `InMemoryTableScan`. После последнего использования вызови `paid.unpersist()`.
