Spark UI показывает выполнение одного приложения. Пока оно работает, интерфейс доступен на стороне driver, обычно на порту `4040`. После завершения его можно посмотреть через Spark History Server, если для запуска сохранились журналы событий. [Мониторинг Spark](https://spark.apache.org/docs/4.1.1/monitoring.html#web-interfaces)

| Вкладка | Что в ней смотреть |
| --- | --- |
| **Jobs** | Какие jobs запущены, завершились или упали. Открой нужную job, чтобы увидеть её длительность, граф стадий и стадию, на которой остановилось выполнение. |
| **Stages** | Что происходило с отдельными задачами внутри стадии. Здесь видны длительность каждой попытки, причина ошибки, объём shuffle read/write и сброс данных на диск (spill). |
| **Storage** | Какие RDD и DataFrame попали в кэш после `cache()` или `persist()`, сколько партиций уже сохранено и сколько места они заняли в памяти и на диске. |
| **Environment** | С какими настройками и зависимостями запустилось приложение. Здесь можно проверить версию JVM, заданные Spark properties и JAR-файлы в classpath. |
| **Executors** | Сколько executors активно, сколько у них ядер, сколько задач завершилось с ошибкой и сколько времени ушло на сборку мусора (GC). Отсюда можно открыть логи executor, если они доступны. |

### Вкладки, которые зависят от приложения

| Вкладка | Когда и зачем открывать |
| --- | --- |
| **SQL / DataFrame** | При выполнении SQL-запросов и операций с DataFrame. Показывает физический план, связанные jobs и метрики операторов. Например, по плану видно, какой join выбрал Spark и сколько строк вышло из фильтра. |
| **Structured Streaming** | Для потоковых запросов в режиме микробатчей. Здесь сравнивают скорость поступления и обработки строк, смотрят длительность батчей и размер состояния у операций, которые его хранят. |
| **Streaming** | Для приложений на DStreams API. Показывает, сколько батч ждал запуска и сколько времени обрабатывался. |
| **JDBC/ODBC Server** | При работе через Spark Thrift Server. Здесь видны клиентские сессии, отправленные SQL-запросы и их статусы. |
| **Connect** | На сервере Spark Connect. Здесь можно найти клиентскую сессию и посмотреть отправленные через неё запросы. |

Например, если загрузка упала, открой **Jobs**, выбери упавшую job и перейди в проблемную **stage**. В таблице **Tasks** найди неудачную попытку и прочитай её ошибку. Если загрузка просто долго идёт, сравни **Median** и **Max** по длительности задач и по **Shuffle Read Size**. Когда одна задача и работает дольше, и читает намного больше данных, стоит проверить перекос партиций.
