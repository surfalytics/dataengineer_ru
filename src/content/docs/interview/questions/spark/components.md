У Spark-приложения в кластере есть один **driver** и набор **executors**. Driver планирует вычисления, executors выполняют их на рабочих узлах. Ресурсы для приложения выделяет **cluster manager**.

| Компонент | За что отвечает |
| --- | --- |
| **Driver** | Выполняет основной код приложения. Через `SparkSession` мы описываем, что хотим посчитать. Когда требуется результат, driver планирует стадии, отправляет задачи на executors и отслеживает их выполнение. |
| **Executor** | Рабочий процесс конкретного приложения. Читает и обрабатывает партиции, хранит закэшированные данные в памяти или на диске. При наличии свободных ядер один executor может выполнять несколько задач одновременно. |
| **Cluster manager** | Выделяет приложениям CPU и память на узлах кластера. Эту роль может выполнять Kubernetes, YARN или встроенный менеджер Spark Standalone. |

**Worker node** — машина, на которой запускаются executors. На одном узле могут одновременно работать несколько executor-процессов.

### Как это выглядит при запуске

Допустим, нужно прочитать заказы из Parquet, посчитать выручку по магазинам и записать результат. При запуске приложения cluster manager выделяет ресурсы для executors. Когда код доходит до записи результата, driver планирует задачи. Executors параллельно читают свои партиции и считают промежуточные суммы. При shuffle данные одного магазина попадают в одну партицию, где задача складывает суммы. Итоговые строки executors записывают в хранилище.
