**Lazy evaluation** означает, что Spark откладывает обработку данных, пока приложению не понадобится результат. В API для работы с RDD и DataFrame есть два основных вида операций:

- **Transformation** описывает новый набор данных. Например, `filter()` оставляет подходящие строки, а `select()` выбирает колонки. Spark запоминает эти операции и их зависимости.
- **Action** запускает вычисление. Ты вызываешь метод, которому уже нужны данные, и Spark выполняет ту часть плана, которая нужна для ответа. Например, `orders.count()` запускает подсчёт заказов и возвращает одно число.

```python
paid = orders.filter("status = 'paid'").select("shop_id", "amount")
totals = paid.groupBy("shop_id").sum("amount")
totals.write.parquet(output_path)
```

Первые две строки описывают расчёт выручки по магазинам. **Вычисление запускает вызов `parquet(output_path)` в третьей строке.** Чтобы записать результат, Spark отбирает оплаченные заказы, суммирует выручку по магазинам и записывает итоги в файлы.

### Какие вызовы запускают вычисление?

Вместо записи в Parquet к тому же DataFrame `totals` можно применить любое из этих действий.

| Вызов | Что произойдёт |
| --- | --- |
| `totals.show(5)` | Spark получит строки для просмотра и напечатает в консоли до пяти строк с выручкой магазинов. |
| `totals.count()` | Посчитает строки и вернёт на driver одно число. В этом примере оно равно количеству магазинов, у которых были оплаченные заказы. |
| `totals.collect()` | Соберёт итоги по всем магазинам на driver и вернёт их как Python-список объектов `Row`. |
| `totals.toPandas()` | Соберёт все строки на driver в pandas DataFrame. Как и для `collect()`, весь результат должен поместиться в память драйвера. |
| `totals.write.saveAsTable("sales_by_shop")` | Запишет выручку в таблицу `sales_by_shop`. Затем к ней можно обратиться по имени из SQL. |
| `totals.foreachPartition(send_rows)` | Вызовет твою функцию `send_rows` на executors для каждой партиции. Например, функция может отправить строки в базу данных пачками. |

**Почему один `count()` запускает вычисление, а другой ждёт?** Вызов `paid.count()` сразу возвращает число оплаченных заказов. Вызов `paid.groupBy("shop_id").count()` создаёт DataFrame с планом подсчёта заказов по магазинам. Если вызвать у этого DataFrame `show()`, Spark выполнит подсчёт и покажет результат. [GroupedData.count в документации PySpark](https://spark.apache.org/docs/4.1.1/api/python/reference/pyspark.sql/api/pyspark.sql.GroupedData.count.html)

### Узкие и широкие зависимости

| Зависимость | Как движутся данные | Пример |
| --- | --- | --- |
| **Узкая (narrow)** | Записи одной входной партиции нужны максимум одной дочерней партиции. Цепочку таких операций Spark может выполнить в одной task за один проход. | `filter` и `select` из примера выполняются в одной стадии. |
| **Широкая (wide)** | Записи одной входной партиции могут понадобиться нескольким выходным. Spark перераспределяет их через shuffle, и дальнейшая обработка идёт в следующей стадии. | Если покупки магазина находятся в разных партициях, `groupBy("shop_id")` с агрегацией собирает его частичные суммы вместе. |

Граница определяется фактическим планом. Например, если данные уже распределены по нужному ключу и Spark знает об этом, дополнительный shuffle для группировки может не понадобиться. В Spark UI на вкладке **SQL / DataFrame** ищи оператор `Exchange` с типом распределения, например `hashpartitioning(shop_id, …)`. [Операции над RDD](https://spark.apache.org/docs/4.1.1/rdd-programming-guide.html#rdd-operations)
