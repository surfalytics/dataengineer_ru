В MapReduce сначала преобразуют отдельные записи, затем собирают данные по ключу и вычисляют результат для каждого ключа. На схеме ключом служит слово. В первой партиции лежат «кот, пёс, кот», во второй — «пёс, кот».

<SparkDataFlow mode="map-reduce" />

1. **Map — применить одну и ту же функцию к каждому элементу.** Каждая задача проходит по своей партиции и преобразует записи по отдельности. На схеме каждое слово превращается в пару `(слово, 1)`. Для «кот» первая задача получает две пары `("кот", 1)`, вторая — одну. Дальше `reduceByKey` уже внутри каждой партиции складывает единицы. К отправке готовы частичные счётчики **2** и **1**.
2. **Shuffle — перераспределить данные по ключу.** Во время такого «перемешивания» Spark направляет значения с одинаковым ключом в одну выходную партицию. На схеме оба счётчика для «кот» попадают в P0, а для «пёс» — в P1. Задача для P0 читает двойку локально, а единицу получает по сети.
3. **Reduce — объединить значения одного ключа по заданному правилу.** Для подсчёта слов правило — сложение. Задача для «кот» получает 2 и 1 и вычисляет `2 + 1 = 3`. Для «пёс» получается `1 + 1 = 2`.

### А если нужно найти самый дорогой заказ в каждом магазине?

**Map** берёт из каждого заказа два поля и возвращает пару `(магазин, сумма заказа)`. **Shuffle** направляет данные одного магазина в одну партицию. **Reduce** теперь выбирает большее из двух значений. Если в одной партиции заказы магазина стоили 350 и 900 ₽, а в другой — 650 ₽, локальные максимумы будут 900 и 650 ₽. Итог для магазина — `max(900, 650) = 900 ₽`. Для расчёта выручки по тем же заказам сложили бы все три суммы и получили `350 + 900 + 650 = 1 900 ₽`.

В RDD API `reduceByKey` — ленивая трансформация. Она возвращает распределённый набор пар с одним результатом на ключ. Метод `reduce` — action, которая объединяет элементы всего RDD в одно значение и возвращает его на driver.
