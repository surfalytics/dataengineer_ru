Представь два набора Parquet одинакового объёма. В одном сотня файлов, в другом сто тысяч. Во втором случае Spark и хранилище тратят больше времени на поиск файлов, открытие, чтение футеров и планирование. В HDFS растёт нагрузка на NameNode, в объектном хранилище растёт число запросов. Spark умеет читать несколько маленьких файлов одной задачей, но открыть каждый файл всё равно придётся.

**Откуда они берутся.** Каждый микробатч или дневная загрузка дописывает свою порцию. Если ещё и записывать через `partitionBy("user_id")` при миллионах пользователей, небольшие порции разойдутся по огромному числу каталогов. Даже одна пишущая задача может создать несколько файлов в разных табличных партициях.

**Что проверить.** Посмотри количество и распределение размеров файлов за один день, число пишущих задач и колонки физического партиционирования. Для небольшого результата сократи число выходных партиций. Для накопившихся файлов выполни compaction средствами используемого табличного формата. `maxRecordsPerFile` только ограничивает число строк сверху и не склеивает уже записанные мелкие файлы. [Настройки файловых источников Spark SQL](https://spark.apache.org/docs/4.1.1/sql-performance-tuning.html#tuning-partitions)
