**Action запускает вычисление. Spark делит Job на стадии по границам shuffle, а внутри каждой стадии запускает по одной Task на каждую партицию, которую нужно обработать.**

## Что такое Job и когда она запускается?

**Job (задание)** — параллельное вычисление, которое Spark запускает в ответ на действие пользователя. Например, `count()` требует посчитать строки, `collect()` — вернуть результат на driver, а `save()` — записать его в хранилище. Такой вызов в коде называется **Action**. В простом случае ему соответствует одна Job. Для одного действия над DataFrame Spark может запустить несколько Jobs.

## Как Job делится на Stages?

**Stage (стадия)** объединяет операции, которые можно выполнить последовательно над одной партицией. Например, `filter` отбрасывает отменённые заказы, а `map` сразу же превращает каждый оставшийся заказ в пару «магазин, сумма». Обе операции выполняются в одной стадии.

**Граница между стадиями — shuffle.** Если покупки одного магазина лежат в разных партициях, для подсчёта выручки их нужно собрать по ключу. Задачи первой стадии записывают промежуточные суммы в shuffle-блоки. Задачи следующей стадии читают нужные блоки и считают итог по каждому магазину.

## Что такое Task и сколько их будет?

**Task (задача)** — наименьшая единица работы в Spark. Driver отправляет её на executor. В пределах стадии задачи выполняют один и тот же код, но каждая обрабатывает свою партицию. Число обрабатываемых партиций определяет количество задач, а число свободных слотов — сколько из них могут работать одновременно.

Продолжим пример с магазинами. Пусть у исходного RDD **16 партиций**, у `reduceByKey` запрошены **2 выходные партиции**, а `collect()` должен вернуть выручку на driver.

| Что видно в Spark UI | Что делают задачи |
| --- | --- |
| **Stage 0 · 16 задач** | Каждая читает одну входную партицию, выполняет `filter` и `map`, считает локальные суммы по магазинам и записывает shuffle-блоки. |
| **Stage 1 · 2 задачи** | Каждая читает блоки для одной из двух выходных партиций, складывает суммы по своим магазинам и возвращает результат на driver. |

Итого для этого примера — **одна Job, две стадии, 18 задач**. Если у executor свободны 16 ядер и на задачу выделено одно ядро, он может выполнить все 16 задач первой стадии параллельно. С четырьмя свободными ядрами одновременно пойдут максимум четыре задачи. [Термины в документации Spark](https://spark.apache.org/docs/4.1.1/cluster-overview.html#glossary)
