**Action** — команда в коде, которой нужен результат, например `count()` или запись в Parquet. **Job** — вычисление, которое Spark запускает для получения этого результата. Одна action может запустить несколько jobs. Например, для SQL-запроса Spark может отдельно подготовить данные для broadcast join.

**Stage** — часть job, в которой задачи могут обработать свои партиции без нового перераспределения данных. Если следующей операции нужны записи из других партиций, возникает граница стадий. Задачи одной стадии записывают блоки для shuffle, задачи следующей читают нужные блоки.

**Task** — минимальная единица работы, которую планировщик Spark отправляет на executor. Одна task обрабатывает одну партицию своей стадии. При четырёх партициях будут четыре задачи, даже если у приложения всего два свободных слота. Тогда остальные задачи начнут работу по мере освобождения слотов.

### Один action, две стадии

Допустим, заказы лежат в четырёх входных партициях. Нужно убрать отменённые заказы, сложить суммы по магазинам через `reduceByKey` с двумя выходными партициями и сохранить результат. Для такого RDD без готового разбиения по магазину запись запускает job:

1. **Stage 0, четыре tasks.** Каждая задача читает свою партицию, отбрасывает отменённые заказы и локально суммирует покупки по магазинам. Промежуточные суммы записывает в shuffle-блоки.
2. **Stage 1, две tasks.** Каждая задача читает блоки для своей выходной партиции, объединяет суммы каждого магазина и записывает результат.

В Spark UI открой **Jobs**, выбери job и посмотри граф стадий. Внутри каждой стадии в таблице **Tasks** видны отдельные попытки выполнения и executor, на котором они запускались. [Термины Spark](https://spark.apache.org/docs/4.1.1/cluster-overview.html#glossary)
