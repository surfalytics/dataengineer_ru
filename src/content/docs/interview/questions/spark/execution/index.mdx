**В этом примере одна Action запускает одну Job, а shuffle делит её на две стадии.** Параллелизм внутри каждой стадии обеспечивают задачи (Tasks). Каждая задача обрабатывает свою партицию.

## Что запускает Job?

Допустим, заказы лежат в четырёх партициях RDD `orders`. Нужно отобрать оплаченные заказы и посчитать выручку по каждому магазину.

```python
totals = (orders
    .filter(lambda order: order["status"] == "paid")
    .map(lambda order: (order["shop_id"], order["amount"]))
    .reduceByKey(lambda a, b: a + b, numPartitions=2))
result = totals.collect()
```

Первые три операции — **трансформации**. Они описывают, как получить результат. Вызов `collect()` — это **Action**. Он запрашивает готовые суммы на driver. Для этого Spark запускает **Job** — задание на выполнение расчёта.

## Где проходит граница между стадиями?

**Первая стадия — четыре задачи.** На каждую входную партицию Spark запускает одну Task. Она выполняет целую цепочку операций. `filter` оставляет оплаченные заказы, `map` превращает каждый заказ в пару «магазин, сумма», а `reduceByKey` локально складывает суммы одного магазина. Четыре задачи выполняют один и тот же код на четырёх разных частях данных.

**Shuffle.** Заказы одного магазина могли попасть в разные входные партиции. Поэтому задачи первой стадии записывают частичные суммы в блоки, распределяя их по ключу магазина. Теперь все суммы одного магазина может прочитать одна задача следующей стадии.

**Вторая стадия — две задачи.** В `reduceByKey` мы указали `numPartitions=2`. Каждая Task читает блоки для своей выходной партиции, складывает частичные суммы по своим магазинам и возвращает результат на driver.

Итого — **одна Action, одна Job, две стадии и шесть задач** (четыре до shuffle и две после). [Как Spark выделяет стадии](https://github.com/apache/spark/blob/v4.1.1/core/src/main/scala/org/apache/spark/scheduler/DAGScheduler.scala)

## Сколько задач выполняется одновременно?

**По умолчанию на одну Task планировщик выделяет одно ядро CPU** (`spark.task.cpus=1`). Если у приложения четыре свободных ядра, все четыре задачи первой стадии могут работать одновременно. Если ядро одно, они выполнятся по очереди. Во второй стадии одновременно могут работать максимум две задачи, даже если свободны все четыре ядра, поскольку выходных партиций всего две.

Число ядер на задачу можно изменить. При `spark.task.cpus=2` четырёх свободных ядер одного executor хватит на две одновременные задачи. [Настройка spark.task.cpus](https://spark.apache.org/docs/4.1.1/configuration.html#scheduling)
