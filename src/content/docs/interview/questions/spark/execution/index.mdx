**Action запускает вычисление. Spark делит Job на стадии по границам shuffle, а внутри каждой стадии запускает по одной Task на каждую партицию, которую нужно обработать.**

## Что такое Job и когда она запускается?

**Job** — задание, которое Spark запускает в ответ на **Action**. Например, `count()` запрашивает число строк, `collect()` возвращает результат на driver, а `save()` записывает его в хранилище. Одно действие может запустить одну или несколько Jobs.

**Параллелизм внутри Job обеспечивают задачи (Tasks).** Driver назначает готовые задачи на свободные слоты executors. Если у приложения всего один слот, задачи этой Job будут выполняться по очереди.

## Как Job делится на Stages?

**Stage (стадия)** объединяет операции, которые можно выполнить последовательно над одной партицией. Например, `filter` отбрасывает отменённые заказы, а `map` сразу же превращает каждый оставшийся заказ в пару «магазин, сумма». Обе операции выполняются в одной стадии.

**Граница между стадиями — shuffle.** Если покупки одного магазина лежат в разных партициях, для подсчёта выручки их нужно собрать по ключу. Задачи первой стадии записывают промежуточные суммы в shuffle-блоки. Задачи следующей стадии читают нужные блоки и считают итог по каждому магазину.

## Что такое Task и сколько их будет?

**Task (задача)** — наименьшая единица работы в Spark. В пределах стадии задачи выполняют один и тот же код, каждая над своей партицией. Сколько партиций предстоит обработать, столько задач потребуется.

**По умолчанию на одну Task планировщик выделяет одно ядро CPU** (`spark.task.cpus=1`). Например, executor с четырьмя свободными ядрами может взять до четырёх готовых задач одновременно. Если задать `spark.task.cpus=2`, на тех же четырёх ядрах одновременно поместятся только две задачи. [Настройка spark.task.cpus](https://spark.apache.org/docs/4.1.1/configuration.html#scheduling)

Продолжим пример с магазинами. Пусть у исходного RDD **16 партиций**, у `reduceByKey` запрошены **2 выходные партиции**, а `collect()` должен вернуть выручку на driver.

| Что видно в Spark UI | Что делают задачи |
| --- | --- |
| **Stage 0 · 16 задач** | Каждая читает одну входную партицию, выполняет `filter` и `map`, считает локальные суммы по магазинам и записывает shuffle-блоки. |
| **Stage 1 · 2 задачи** | Каждая читает блоки для одной из двух выходных партиций, складывает суммы по своим магазинам и возвращает результат на driver. |

Итого — **одна Job, две стадии, 18 задач**. При 16 свободных ядрах и `spark.task.cpus=1` все 16 задач первой стадии могут работать параллельно. Во второй стадии одновременно будут работать максимум две задачи, потому что после shuffle осталось две партиции. [Термины в документации Spark](https://spark.apache.org/docs/4.1.1/cluster-overview.html#glossary)
