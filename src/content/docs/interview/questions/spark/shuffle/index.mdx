**Shuffle** — перераспределение записей между партициями. Например, покупки одного магазина приходят из разных файлов. Чтобы собрать их вместе, Spark назначает каждой записи выходную партицию по ключу магазина. Задачи следующей стадии сами читают предназначенные им блоки. Через driver эти данные не проходят.

<SparkDataFlow mode="shuffle" />

На схеме ключ — номер магазина, буква — покупка. Есть две выходные партиции. Для примера номер партиции равен `shop_id % 2`: магазин **10** попадает в P0, магазин **11** — в P1.

1. **Shuffle write.** Первая задача читает покупки `10:a` и `11:b`, вторая — `11:c` и `10:d`. Каждая раскладывает записи по выходным партициям и записывает блоки на своей стороне.
2. **Shuffle read.** В показанном размещении задача P0 работает на первом executor. Блок с `a` уже рядом, а блок с `d` она запрашивает по сети у второго узла. Задача P1 получает `c` локально и забирает `b` с первого узла.
3. **После обмена.** В P0 собраны покупки `{a, d}`, в P1 — `{b, c}`. Порядок записей внутри групп здесь не задан. Теперь каждая задача может, например, посчитать покупки своего магазина. Сам shuffle только переместил записи.

P0 и P1 — номера партиций. На схеме executors работают на разных узлах. При другом размещении задач доля локального и сетевого чтения изменится.

### Где увидеть стоимость shuffle

В **Spark UI → Stages** у предыдущей стадии смотри **Shuffle Write**, у следующей — **Shuffle Read**. Пересылка блоков расходует сеть, запись и чтение — дисковый ввод-вывод. Если одна задача читает заметно больше остальных и заканчивает последней, сравни распределение ключей: большой объём данных по одному магазину мог попасть в одну партицию. [Как Spark выполняет shuffle](https://spark.apache.org/docs/4.1.1/rdd-programming-guide.html#shuffle-operations)
