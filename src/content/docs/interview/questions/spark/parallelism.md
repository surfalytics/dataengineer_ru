**Число партиций определяет, сколько отдельных задач можно запустить на стадии.** Число одновременно работающих задач ограничивают свободные ресурсы executors. При обычной настройке `spark.task.cpus=1` сорок доступных ядер дают до сорока одновременных задач.

| Что видишь в Spark UI | Какое изменение проверить |
| --- | --- |
| На 40 ядрах всего 10 больших задач, каждая долго работает | Если работа делится, увеличь число входных или shuffle-партиций на нужном этапе. Если источник даёт только 10 независимых частей и обмен слишком дорог, попробуй кластер поменьше. |
| 120 сопоставимых задач на 40 ядрах | Примерно три волны работы. Пока освобождается ядро, следующая задача получает слот. Очередь сама по себе ещё не проблема. |
| Тысячи очень коротких задач, много времени уходит на запуск | Уменьши число партиций или позволь AQE объединить маленькие партиции после shuffle. Если узкое место в БД-приёмнике, дополнительно ограничь число одновременных записей. |
| Одна задача работает несколько минут, остальные уже завершились | Сначала проверь перекос. Дополнительные executors не разделят одну горячую партицию автоматически. |

`spark.sql.shuffle.partitions` задаёт начальное число партиций для многих SQL-обменов. Количество файлов на чтении, партиций после JOIN и записывающих задач может различаться. После изменения сравни **время всей стадии при том же входе**, длительность задач и spill.
