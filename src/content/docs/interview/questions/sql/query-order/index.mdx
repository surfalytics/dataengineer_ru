Порядок записи SQL и логический порядок обработки различаются. **Агрегация происходит после `WHERE` и до `HAVING`.** Оптимизатор может переставить физические операции, сохранив результат.

| Шаг | Что происходит |
| --- | --- |
| 1. `FROM`, `JOIN … ON` | Определяются источники и пары строк. Внешний JOIN добавляет сохраняемые строки без пары. |
| 2. `WHERE` | Отбрасываются отдельные строки до группировки. |
| 3. `GROUP BY` и агрегаты | Строки собираются в группы, для каждой вычисляются `SUM`, `COUNT` и другие итоги. При агрегате без `GROUP BY` образуется одна общая группа. |
| 4. `HAVING` | Отбрасываются группы по их итогам. |
| 5. Оконные функции | Окна получают строки, оставшиеся после предыдущих этапов. При группировке это уже строки групп. |
| 6. `SELECT` | Формируются выходные столбцы и их имена. |
| 7. `DISTINCT` | Убираются повторяющиеся строки результата, если это запрошено. |
| 8. `ORDER BY` | Результат сортируется для выдачи. |
| 9. `OFFSET`, `LIMIT` / `FETCH` | Пропускается заданное число строк и выбирается нужная часть результата. |

## Когда именно считается сумма?

```sql
SELECT region, SUM(amount) AS revenue,
       DENSE_RANK() OVER (ORDER BY SUM(amount) DESC) AS place
FROM sales
WHERE status = 'paid'
GROUP BY region
HAVING SUM(amount) >= 1000
ORDER BY revenue DESC, region
LIMIT 3;
```

Сначала остаются оплаченные продажи. Затем `SUM(amount)` считается по каждому региону. `HAVING` исключает регионы с итогом меньше 1000, и только после этого `DENSE_RANK` присваивает места оставшимся регионам. `LIMIT 3` ограничивает количество строк итогового отчёта.

В PostgreSQL псевдоним `revenue` уже доступен в `ORDER BY`. В `HAVING` этого же уровня пишем `SUM(amount)`. Для фильтра по оконному `place` можно вынести расчёт в CTE и применить `WHERE` во внешнем запросе. [Обработка SELECT в PostgreSQL](https://www.postgresql.org/docs/18/sql-select.html)
