**Некоррелированный подзапрос** можно выполнить отдельно. **Коррелированный подзапрос** ссылается на строку внешнего запроса. Найдите во внутреннем запросе имя, объявленное снаружи, и проверьте, зависит ли от него ответ.

## Некоррелированный. Кто зарабатывает больше среднего по компании?

```sql
SELECT e.name, e.salary
FROM employees AS e
WHERE e.salary > (SELECT AVG(salary) FROM employees);
```

Внутренний `SELECT` возвращает одно среднее для всей компании. Ему ничего не нужно знать о текущем сотруднике `e`.

## Коррелированный. Кто зарабатывает больше среднего в своём отделе?

```sql
SELECT e.name, e.salary
FROM employees AS e
WHERE e.salary > (
    SELECT AVG(d.salary)
    FROM employees AS d
    WHERE d.department_id = e.department_id
);
```

`e.department_id` приходит из внешнего запроса. Для сотрудника отдела продаж берётся среднее отдела продаж, для инженера — среднее инженерного отдела. При зарплатах 80 и 120 в продажах и 200 у единственного инженера первый запрос вернёт инженера, второй — продавца с зарплатой 120.

## Что добавить на собеседовании?

Отдельный вопрос о термине может и не прозвучать. Если обсуждаете подзапросы или `EXISTS`, покажите ссылку на внешний столбец и объясните, как она меняет смысл выборки. Зависимость задаёт логику SQL. Реальное число запусков подузла и возможное преобразование в соединение проверяют по плану. [Подзапросы в PostgreSQL](https://www.postgresql.org/docs/18/functions-subquery.html)
