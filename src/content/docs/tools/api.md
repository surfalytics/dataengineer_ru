## Что такое API?  

**API (Application Programming Interface)** — это интерфейс, через который одна система работает с другой. Через него приложения обмениваются данными и вызывают функции друг друга.  

API часто выступают как посредник между источником данных (например, базой данных) и пользователем (программистом или приложением).  

## Типы API  

1. **REST API**  
   - Основан на HTTP-протоколе.  
   - Использует методы HTTP: GET, POST, PUT, DELETE.  
   - Данные обычно передаются в формате JSON или XML.  

2. **SOAP API**  
   - Протокол обмена сообщениями.  
   - Более строгий и формализованный, чем REST.  
   - Использует XML.  

3. **GraphQL**  
   - Клиент сам выбирает, какие поля получить, и получает только их.  
   - Одна точка входа (endpoint) для всех запросов.  

4. **gRPC**  
   - Быстрый двоичный протокол, поддерживает двустороннюю потоковую передачу.  
   - Его выбирают, когда важна скорость обмена данными.  

## API как источник данных 

API часто предоставляют доступ к данным, например:  
- Социальные сети (Twitter API, Facebook Graph API).  
- Финансовые системы (Stripe, PayPal).  
- Геолокационные данные (Google Maps API).  
- Внутренние системы компаний.  

Для инженеров данных API — это основной способ извлечения данных из внешних и внутренних систем.  

## Интеграция с API  

### 1. Авторизация (Auth)  

   - **API Key** — простой ключ для идентификации. Передаётся в заголовке или параметрах запроса.  
   - **OAuth 2.0** — стандарт безопасного доступа: пользователь даёт приложению доступ к своим данным и не передаёт ему пароль.  
   - **Basic Auth** — передача имени пользователя и пароля в заголовках запроса в формате Base64.  
   - **Bearer Token** — токен, который даёт доступ к защищённым ресурсам. Передаётся в заголовке запроса:  
     ```http
     Authorization: Bearer <your_token>
     ```  

### 2. Пагинация (Pagination)  

   - API отдаёт данные частями (страницами), а не все сразу. Чтобы получить всё, нужно сделать несколько запросов.  
   - Типы пагинации:  
     - **Offset-Based** — номер страницы и её размер: `?page=2&limit=100`.  
     - **Cursor-Based** — метка места, где закончилась прошлая страница: `?cursor=eyJhb...`.  

### 3. Rate Limiting  

   - Ограничение числа запросов за определённое время.  
   - Если лимит превышен, подождите и повторите запрос (retry).  

### 4. Форматы данных  

   - **JSON** — популярный и читаемый формат.  
   - **XML** — используется реже, но встречается в SOAP.  

### 5. Error Handling  

   Обработка кодов ошибок HTTP:  
     - `200` — успех.  
     - `400` — ошибка клиента (например, неправильный запрос).  
     - `500` — ошибка сервера.

### 6. Инструменты интеграции  

   - CLI: `curl` для выполнения запросов.  Подробнее: [How to send curl](https://dataimpulse.com/blog/how-to-send-http-headers-with-curl/)
   - Библиотеки: `requests` для Python, `axios` для JavaScript.  
   - ETL-инструменты: Apache Airflow, AWS Lambda.  

### 7. Инструменты для работы с API  

#### Postman  

Postman — это популярный инструмент для тестирования API. В нём удобно выполнять запросы, смотреть ответы и работать с коллекциями запросов. Ещё Postman поддерживает авторизацию, пагинацию, переменные и тесты.  

#### Thunder Client  

Thunder Client — это легковесный плагин для VS Code, который позволяет тестировать API прямо в редакторе. Он быстрый, простой и подходит для базовой работы с REST API. Основные преимущества:  
- Удобная интеграция с VS Code.  
- Поддержка авторизации (включая OAuth).  
- Простая работа с коллекциями запросов.  

#### Выбор инструмента  

- Если нужно много функций (коллекции, переменные, тесты) — выбирайте Postman.  
- Если вы работаете в VS Code и нужен простой инструмент — берите Thunder Client.
