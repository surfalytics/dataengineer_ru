## Git и версионность

[Git](https://git-scm.com/) — это распределённая система контроля версий, которая стала стандартом в разработке, в том числе в Data Engineering. В работе с данными Git нужен для трёх задач:

1. **Версионирование кода и конфигураций**  
   Git позволяет отслеживать изменения в коде ETL-процессов, SQL-запросах и конфигурационных файлах. Можно 
откатиться к прошлой версии и узнать, кто и когда изменил data pipeline.

2. **Командная работа и code review**  
   Через pull/merge requests команда проверяет изменения в ETL-процессах (code review), 
следит за качеством кода и делится знаниями. Это особенно важно для data pipelines, от которых зависит бизнес.

3. **Интеграция с CI/CD**  
   В Git-платформы встроены инструменты для CI/CD (например, GitHub Actions, GitLab CI/CD). 
Они автоматически запускают тесты, развёртывание и проверку данных при каждом изменении в репозитории.

Основные платформы для хостинга Git-репозиториев:

- [GitHub](https://github.com/) — крупнейшая платформа для хостинга открытого кода с широкими возможностями для CI/CD и командной работы
- [GitLab](https://gitlab.com/) — самая популярная платформа, которую ставят на свой сервер (self-hosted), с полным набором инструментов DevOps
- [Bitbucket](https://bitbucket.org/) — платформа от Atlassian, тесно интегрированная с другими продуктами компании
- [Gitea](https://gitea.io/) — легковесная self-hosted платформа, простая в установке и администрировании

## Что нужно уметь

- `clone`, `status`, `add`, `commit`, `push`, `pull`.
- Работать в ветках: `switch -c`, `merge`, `rebase`.
- Решать конфликты при merge.
- Открывать pull request и делать code review.
- Писать понятные commit-сообщения.
- Использовать `.gitignore`. Не коммитить пароли и ключи.
